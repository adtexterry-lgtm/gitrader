# 模拟场所 kernel-sim · 撮合假设

> 专业用户要看的一页：纸面成交和真场所到底差在哪。本文是 `src/declaration.ts` 里对外声明（契约 §1.5.3）的逐条解释，`test/declaration.test.ts` 会检查两者一致。
> 结论先行：**纸面成绩偏乐观**——没有排队、没有延迟、强平不模拟清算金库，结果页必须和回测、实盘分开标注，不得混用。

## 一、数据来源

- 吃**真实 L2 盘口**：行情源是被模拟场所的连接器（`HyperliquidConnector`）或回放夹具（`ReplayMarket`），模拟场所不自己造价格。
- 标的、精度、杠杆上限、费率都取自行情源的 `Instrument`，纸面账户的 `venue` 写被模拟的场所（契约 §1.2）。
- 行情陈旧（`quote.stale`）或没有报价时下单直接拒（`2007 STALE_PRICE`），不拿旧价成交。
- **盘口读本地快照，不逐单打 REST**：行情源（HL 连接器）用 WS `l2Book` 订阅维护本地 L2 快照（带 `asOf` / `stale`），模拟场所对每个交易过的标的订阅一次、之后只读缓存。快照缺失或 stale（默认 15 s 没更新）才走有界（≤1 s）、限频（同一标的 ≥2 s 一次）的 REST 兜底；兜底也拿不到就**拒单**（`2007`，消息写明「no fresh L2 snapshot … (last update N ms ago / none received yet) … order not matched」），挂单与触发单则这一轮不撮合、下个 tick 再试——不阻塞、不拿旧盘口成交。行情源没有快照接口（回放夹具）时直接读它的 `book()`。
- 因此下面的 `noBook`（mid ± 5 bp）只适用于**盘口存在、但需要的那一侧没有挂单**的情况；取不到盘口本身是拒单，不是 mid ± 5 bp。

## 二、成交模型（`fillModel`）

| 键 | 值 | 含义 |
|---|---|---|
| `market` | `walk-l2-book` | 市价单逐档吃盘口（买吃卖盘、卖吃买盘），成交价为加权均价；一笔订单记一条成交（均价），不按档拆分。 |
| `bookShortfall` | `last-level-plus-0.1pct` | 盘口吃空后，剩余数量按**末档价 ±0.1%**补足（买加、卖减）。只有市价单有这条；限价单不会凭空造流动性。 |
| `noBook` | `mid-plus-5bps` | 取不到盘口时，市价单按**中间价 ±5 bp**整笔成交。 |
| `limit` | `touch-fill-at-limit` | 挂单：对手最优价**碰到**限价（买单 bestAsk ≤ 限价）的下一次 `tick`，按**限价整笔**成交，记 maker。 |
| `queuePosition` | `false` | 不模拟排队：碰到就全成，真实场所里排在后面的单可能根本成交不了。**偏乐观。** |
| `latencyMs` | `0` | 没有延迟：下单瞬间按当时盘口成交，真实往返约几十到几百毫秒。 |
| `funding` | `hourly-accrual` | 资金费按持仓名义额 × 当前小时费率 × 经过时间连续计提，跨整点出一条汇总记录。 |
| `liquidation` | `approx-at-mark` | 账户权益 < 维持保证金时按**标记价**平仓（见第五节），不模拟清算金库与 ADL。 |
| `positionMode` | `oneWay` | 同一标的只有一个净持仓。 |
| `marginMode` | `cross-only` | 全部按全仓算；逐仓专用 / HIP-3 仅逐仓的市场也按全仓模拟（见 `knownGaps`）。 |

补充（声明里一个词放不下的细节）：

- **穿价限价单**（买价 ≥ 卖一）：下单当场当 taker 吃盘口，**不越过限价**；吃不完的部分，GTC 挂单、IOC 作废。这比声明里的 `touch-fill-at-limit` 更严（真实场所也是这样）。
- **ALO（只做 maker）**：下单时会立刻成交就拒绝（`kernel-sim: post only order would have immediately matched`），不会悄悄改成挂单。
- **IOC / 市价一笔都没吃到**：当作拒绝，不是静默作废。
- **市价单滑点上限**：`maxSlippageBps` 换成价格上限（买单向下、卖单向上贴到合法刻度），吃盘口和「末档补足」都不越过它；越过的部分不成交，残量作废（回执仍是 `filled`，数量小于下单量）。
- **触发单**（止损 / 止盈，`stop_*` / `take_*`）：以**标记价**判断，每次 `tick` 检查一次；触发后市价类吃盘口（无价格上限，与场所一致），限价类变限价单。
- **父子单（TP/SL）**：`grouping: order` 的子单在父单**全部成交**后才生效；父单被撤或 IOC 残量作废 → 子单全撤（场所语义 `cancel_children`）。`grouping: position` 的子单立即生效。子单都是只减仓，持仓没了会被撤掉（所以止盈和止损天然互斥）。
- **reduceOnly**：下单时没有反向持仓直接拒；成交时按当前持仓裁剪数量；持仓没了的遗留只减仓单被撤。

## 三、费用

- 取 `Instrument.fees`；没有则用兜底（`PaperVenueOptions.fees`，默认 HL 基础档 taker 0.045% / maker 0.015%）。
- 穿价 / 市价 / 触发 / 强平 记 taker；挂单碰价成交记 maker。**不模拟**质押折扣、成交量分档、builder 费、返佣。
- 强平成交同样收 taker 费（沿用 Demo；真实场所对清算的收费口径未核）。

## 四、保证金与杠杆

- 杠杆：下单带 `leverage` > 该标的已设杠杆（`setLeverage`）> `defaultLeverage`（默认 **1**，沿用 Demo）。不得超过标的 `maxLeverage`。
- 初始保证金 = 名义额 / 杠杆；**下单时**只检查会加仓的部分是否放得下（可用 = 权益 − 已占用），放不下拒 `3004`；挂单碰价成交时再检查一次，不够就撤单。
- 维持保证金 = 名义额 × 1 / (2 × 最大杠杆)（HL 文档口径：约为最大杠杆下初始保证金的一半，不含分档）。
- **不模拟**挂单占用保证金（`openOrderMarginReserve`）：可以用同一笔钱挂很多单，成交时才检查。

## 五、强平

- 触发：账户权益（现金 + 全部未实现盈亏）< 全部持仓维持保证金之和。
- 动作：名义额最大的持仓先平，按**标记价**整笔平（taker 费），平完重算，直到权益 ≥ 维持保证金或没有持仓。成交带 `liquidation: true`，并发 `liquidation` 事件。
- 与 Demo 的差别：Demo 是「每个持仓各自一条强平价」，对全仓账户不对；这里改成账户级。
- **持仓的 `liquidationPrice` 是估算值（`estimated: true`）**：只让该标的价格移动、其它持仓不动，解 `权益(p) = 维持保证金(p)`。
- **不模拟**：清算金库接管（权益跌破维持保证金 2/3）、部分清算、ADL。账户可能被击穿到负权益（坏账不分摊，直接体现在余额里）。

## 六、价格口径

- 标记价 = 行情源报价的 `last`（HL 连接器里是买卖中间价 / 活跃资产上下文，不是 HL 官方融合了外部 CEX 价的标记价）。强平和触发单都用它，所以会和真场所有出入。
- 资金费率取行情源的 `context.fundingRate`（每小时），取不到就这一轮不计提，下一轮按经过的总时间补算。

## 七、已知缺口（`knownGaps`）

1. `no-queue-position`：没有排队位置（偏乐观）。
2. `no-latency-model`：没有延迟（偏乐观）。
3. `isolated-only-markets-simulated-as-cross`：逐仓专用 / HIP-3 仅逐仓市场按全仓模拟。

声明之外还有（不影响声明的字段，但专业用户该知道）：无挂单保证金占用；无清算金库 / ADL；无费率分档；标记价是中间价近似；一笔订单一条成交；只支持线性合约、单向持仓。

## 八、回放模式

`ReplayMarket` 按时间戳重放夹具（`fixtures/hl/replay/*.json`）：时钟由回放驱动，同一份夹具、同一串指令，结果逐位一致（有测试：两次回放的 `exportState()` 完全相同）。回放用的盘口是**把真实盘口形状平移到每根 K 线收盘价**合成的，不是逐笔真实盘口，用来验证撮合逻辑与账务，不用来评估策略盈利。
