# 实盘与风控

这一篇讲**碰真钱**之前要知道的事。默认安装是测试网 + 纸面账户；实盘是一串需要你本人到场的动作，不是改一个开关。

## 1. 支持边界

| 项 | 现状 |
|---|---|
| 交易场所 | 随包的交易连接器只有 Hyperliquid（`venues[].id = "hyperliquid"`）；其他场所是只读行情 |
| 网络 | 默认 `testnet`。主网默认关着，切过去之前必须有主网 API 钱包 |
| 资金 | **不托管**。密钥只在本机，交易用「只交易、不能提现」的 API 钱包 |
| 风控覆盖范围 | 经工作台 / Agent / 引擎模式 A 发的单都过闸门；**外部引擎自己连场所下的单不过闸**，账本标成 `engine-reported`，界面会写明 |
| 状态 | 产品本体 M1 施工中。没有经过真网验证的连接器，不得接实盘 |

一句话：**Gitrader 不替你赚钱，也不承诺任何结果；它保证的是「钱动之前有一道你设的闸」。**

## 2. 三道门槛

实盘不是「一个」开关，而是三层，每层都要有人：

### 第一层：钱包（只交易，不能提现）

```text
gitrader keys new wallet main-key --network mainnet --days 180
gitrader keys import my-api-wallet --network mainnet
gitrader keys list
```

- `new wallet` 在本机生成，只打印地址；私钥不出钥匙库。之后你要在**自己的浏览器钱包**里用主钱包对这个地址做一次 `approveAgent` 授权。
- `import` 读的是终端隐藏输入（私钥绝不走命令行参数，因为 argv 会进 shell 历史与进程列表）。
- 钱包有效期到了要轮换：`keys.walletExpiryWarnDays`（默认 14 天）会提前提醒。

### 第二层：授权书（Agent 能做什么）

每个接进来的 Agent 一把钥匙，四档：

| 档 | 能做什么 |
|---|---|
| `read_only` | 只读 + 研究（不能交易）：能看行情和账户，能写笔记、建实验、提回测；不能下单、不能启停策略（只能停自己启动的） |
| `paper` | 纸面下单 / 启停纸面策略（只能停自己启动的，停别人的要「需确认」以上） |
| `confirm` | 提案，等你批 |
| `auto_limited` | 在授权书额度内自动执行；**不能当默认档** |

```text
gitrader keys new agent "my-agent" --host claude-code --tier confirm \
  --accounts main-live --max-order 500 --max-daily 2000 --max-daily-loss 200
```

签发 L3 / L4 授权书时，协议强制写清账户 / 场所 / 标的白名单、额度、日亏、心跳、有效期；缺项不是「宽松」，是**闸门会把它判成不完整并转成提案**（`MANDATE_INCOMPLETE`）。令牌只在创建时显示一次。

### 第三层：风控闸（每一单都过）

闸门在**内核里**，是唯一的检查点。它按固定顺序全量评估 13 个阶段，不短路：

```text
SYS 系统健康（策略验签、账户视图陈旧、标记价缺失）
KILL 断电器   STATE 作用域状态（REDUCING / HALTED）
MANDATE 授权书   LLM 大模型来源   ALLOWLIST 白名单
CONST 杠杆 / 单笔名义 / 滑点    EXPOSURE 单标的与总敞口、持仓数、日名义
BUYING_POWER 购买力    LOSS 当日亏损    RATE 频率与重复意图
PROTECTOR 保护器    APPROVAL 需人批准
```

判决只有三档：

| 判决 | 含义 | 后果 |
|---|---|---|
| `ALLOW` | 全部通过 | 原样发出 |
| `LIMIT` | 有 `limit` 类命中（如单笔名义超了） | 按调整后的数量发出，票据绑定调整后的内容 |
| `BLOCK` | 有 `deny`，或有 `review`（需人批） | **什么都不发**；`review` 转成提案等你批（纸面账户批准不用 PIN；实盘账户、或单笔名义超过这把钥匙的 PIN 门槛 `presenceAboveNotional` 时才输 PIN） |

几条硬规矩：

- **降风险动作永远能走**：`reduce`（仅减仓）与 `cancel`（撤单）在 `SYS` / `KILL` / `STATE` 异常下一律放行并记 `warn`，也不受日笔数、权重预算限制。停机不能让人平不掉仓。
- **行情陈旧 = 拒单**：超过 `risk.failClosed.stalePriceMs`（默认 5000 ms）或拿不到价格，一律拒。
- **大模型不得实盘开仓**：`denyLlmLiveEntries` 默认 `true`。这条能在配置文件里写，但写 `false` 会被忽略——只能在 工作台里输 PIN 关。
- **可预演**：`dryRun` 的判定不入账、不出票、不占预留、不计入熔断计数。想先看「会不会被拦」，用预演。
- **票据**：每次向场所提交恰好对应一次判定；没有票据或票据过期，内核不签、不发（`GATE_TICKET_INVALID` / `GATE_TICKET_EXPIRED`）。

## 3. 上线前检查

逐项打勾，缺一项就别开：

- [ ] `gitrader keys list` 里有主网 API 钱包，状态 `active`，到期日够远；
- [ ] 该地址已在主钱包里 `approveAgent`，且**没有**提现权限；
- [ ] `accounts[]` 里实盘账户有 `mode: "live"`、`environment: "mainnet"`、`signerRef` 指向那只钱包、`accounts[].owner.address` 是主账户公开地址；
- [ ] `venues[]` 里 `hyperliquid` 的 `environment` 是 `mainnet`（工作台切网络会改写这一行并提示重启）；
- [ ] `risk.preset` 是你想要的档（默认 `p-lev3-o2000-d3`：≤3× / 单笔 ≤2,000 / 3% 日亏）；
- [ ] `risk.denyLlmLiveEntries` 是 `true`；
- [ ] `risk.failClosed` 的 `stalePriceMs` 符合你的行情频率；
- [ ] `plugins.developerMode` 是 `false`，没有未签名插件在跑；
- [ ] `embed.allowedOrigins` 为空（除非你明确要把工作台嵌进别的页面）；
- [ ] `gitrader ledger verify` 通过；
- [ ] `gitrader risk policy export` 的结果里，限额与你以为的一致；
- [ ] 这条策略已经过纸面（`paper`）与影子（`shadow`）阶段，实验里记着 `holdoutWindow` 与 `assumptions`。

## 4. 启动与升级路径

推荐顺序，别跳级：

1. **纸面**（`mode: "paper"`）：吃真实行情的模拟撮合，先看行为是否符合预期；
2. **影子**（`mode: "shadow"`）：当前与纸面走同一条模拟撮合路径，用来固定「如果按实盘参数跑会怎样」的记录；
3. **实盘小额**（实验阶段 `live_small`，试运行语义 30 天）：授权书额度压到最小，`--tier confirm` 起步；
4. **实盘**（`live`）：在 3 稳定之后才谈。

实验阶段每升一级要有证据包；推到 `live_small` / `live` 要你本人在工作台里审、输 PIN（`lab.stage`），Agent 的这类请求一律被拒。

## 5. 运行中

- `gitrader status` 一行看全：交易状态、风控策略版本与完整性、账本序号、账户与场所连接、引擎与插件数量、PIN 与钥匙库状态。要机器读加 `--json`。
- 交易状态三态：

  | 状态 | 含义 | 还能做什么 |
  |---|---|---|
  | `ACTIVE` | 正常 | 全部 |
  | `REDUCING` | 只减仓 | 平仓、撤单；不许加敞口 |
  | `HALTED` | 停机（锁存） | 平仓、撤单；一切加敞口动作被拒 |

- 进入 `REDUCING` / `HALTED` 的常见原因：你按了接管、保护器触发、Agent 心跳超时（死人开关）、启动对账失败、风控策略验签失败。
- **不要把 `gitrader serve` 的终端一直最小化**：它会打印重启、拒绝、连接变化等警告。警告也进 `status` 的 `warnings` 段。

## 6. 接管与保护器

**接管**（自救动作，人和 Agent 都能触发，不需要 PIN——快比仪式重要）：

- 停止新开仓；
- 撤销挂单（默认保留只减仓的止损 / 止盈保护单，回包里 `cancelled` 是撤掉的挂单数、`keptProtective` 是保留下来的保护单数；Agent 汇报以回包字段为准）；
- 全部平仓。

接管发出的撤单 / 平仓以 `system` 身份走闸门，豁免撤单速率限制，不会被自己刚触发的规则拦住。

**保护器**（在闸门的 `PROTECTOR` 阶段生效，只会拒绝或收紧）：

| 种类 | 作用 |
|---|---|
| `cooldown` | 开仓后若干秒内不许再开 |
| `stoploss_guard` | 窗口内止损次数超限 → 暂停若干分钟 |
| `drawdown_pause` | 窗口内回撤超限 → 暂停 |
| `low_profit_lock` | 窗口内收益过低 → 锁定 |
| `max_consecutive_failures` | 连续失败 N 次 → 暂停 |
| `plugin` | 由插件给出的结论（插件不可用时按 `PROTECTOR_UNAVAILABLE` 处理） |

**第 0 层断电器**：数据目录（`GITRADER_HOME`）下出现名为 `HALT` 的文件，内核立刻锁存停机并尝试撤单。这是「手边没有界面也要能一键停」的出口。

- 锁存：删掉文件**不会**恢复。
- 恢复只认你本人在场的 `resume`（PIN）；文件还在时会拒绝并提示先删。
- 触发后 Agent 的可用动作只剩减仓 / 撤单 / 布防；它没有任何恢复类工具。

## 7. 异常处置

| 现象 | 先做什么 | 命令 / 位置 |
|---|---|---|
| 单被拒，不知道为什么 | 看被拦统计，再回放那一单的判定 | `gitrader risk stats`、`gitrader risk replay <precheckId>` |
| 怀疑策略文件被换过 / 策略签名不对 | 验签并回放 | `gitrader risk verify`、`gitrader risk verify <precheckId>` |
| 想确认限额到底是多少 | 导出签名策略与本地批准参数 | `gitrader risk policy export` |
| 要临时放宽（比如止损被限额挡住） | 人面 PIN；**默认放宽 4 小时**（界面可选 1 / 4 / 12 / 24 小时），最长 24 小时，到期自动收回 | 工作台「临时放宽限额」输 PIN；或 `gitrader risk relax @patch.json [--hours N]`（要 PIN） |
| 限额要永久改 | 单独入口，不会自动收回；界面要在二次确认里选「永久修改」，要 PIN | 工作台二次确认；或 `gitrader risk relax @patch.json --permanent`（要 PIN） |
| 要让某个 Agent 立刻失去权限 | 撤销它的 Agent 钥匙：立刻不能下单、待批作废；已有持仓和挂单不会自动处理，要另行处理 | 工作台：设置 → 钥匙 → Agent 钥匙 → 撤销（要 PIN）；或在自己的终端 `gitrader keys revoke agent <名字>`（要 PIN） |
| 账本对不上 | 重算哈希链，看断在第几号条目 | `gitrader ledger verify` |
| 想整体停掉 | 接管三连，或放 `HALT` 文件 | 工作台 / 主目录 |
| 纸面账户被跑乱 | 明确重置（要 PIN，要服务在跑） | `gitrader paper reset --account paper` |
| 引擎跑飞了 | 先停止策略实例，再绑回纸面 | `gitrader engines list` / `engines bind` |

`risk relax` 的补丁是 JSON：临时放宽只能改 `{"limits": {...}}` 里的限额；改其他项（例如 `{"maxDriftBps": 30}`）要加 `--permanent`。`--hours N` 要大于 0 且不超过 24。放宽动作整个过程中都要 PIN 在场，且会入账；临时放宽到期收回时也会记一条。

## 8. 我们不做的

- 不提现、不转账、不代管资金：需要用户签名类的动作（转账、提现、`approveAgent`）内核一律拒签，人面 PIN 流程除外。
- 不承诺收益，不给交易建议，不提供策略或数据。
- 不保证同一系统用户下的恶意代码拦得住——见 [09-安全](09-安全.md) 的 T-C 档。
- 不把「外部引擎自己连场所」的单算进受保护流量。
