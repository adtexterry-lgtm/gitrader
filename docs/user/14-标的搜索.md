# 标的搜索

交易所的代码写法五花八门：`BTCUSDT`、`BTC/USDT`、`btc-usdt` 指的是同一件事；`600519` 是 A 股、六位数字却可能是期货；`.HK` 结尾的才是港股。标的搜索（`@gitrader/symbol-search`）把这些收成一套：**按代码、名称、别名搜，按市场类型 / 场所 / 资产类别 / 报价货币过滤，并把「这条记录能不能加自选 / 能不能下单」判一遍**。

它是纯函数库：不读文件、不联网、不读环境变量、不 `start()` 连接器、没有全局状态。索引从你已经注册的数据连接器的 `listInstruments()` 来。

## 0. 在装好的产品里怎么用

标的搜索（`@gitrader/symbol-search`）接在 `research` 工具的 `search` 动作上，目录是内核已经加载的场所目录（断网拿不到目录时是空的，不会报错）：

- Agent：`research` 工具，`{"action":"search","query":"BTC","limit":5}`，可选 `venue`、`kind`（`perp` / `spot`…）过滤；回 `{ items, total, next? }`，每条有 `instrumentId`、`venue`、`symbol`、`base`、`quote`、`kind`、`score`；有 `next` 就把它当 `cursor` 取下一页。
- 命令行：`gitrader research search BTC --limit 5 --json`。

下面的函数说明是库本身的用法，给自己写集成的人看。

## 1. 索引怎么建

```ts
import { indexFromConnectors, searchSymbols, suggestSymbols, findSymbol, validateSelection } from '@gitrader/symbol-search'

// 连接器自己负责 start()；本包不替任何人发请求
const index = indexFromConnectors([binanceData, polygonData], {
  aliases: { 'polygon:AAPL': ['AAPL.US'] },   // instrumentId → 别名（中文名也走这里）
  sortOrder: { 'binance:BTCUSDT': 10 },       // instrumentId → 权重，越大越靠前
})
```

| 函数 | 用途 |
|---|---|
| `buildIndex({ instruments, source?, aliases?, names?, sortOrder? })` | 单个连接器的一次清单 → 索引 |
| `mergeIndexes([...])` | 多份索引合并去重 |
| `indexFromConnectors([...], opts?)` | 上面两步一次做完 |

去重键是 `(venue, 大写 symbol, kind, instrumentId)`；缺 `symbol` 或 `venue` 的记录被丢弃。

## 2. 搜索与排序

```ts
searchSymbols(index, 'btc', { limit: 10, filter: { kinds: ['perp'], quote: 'USDT' } })
// → [{ record, rank: 1, matchKind: 'symbol-prefix', matchedOn: 'symbol' }, …]
```

排序档位（高的在前）：0 代码精确 → 1 代码前缀 → 2 代码包含 → 3 名称包含 → 4 别名精确 → 5 别名包含 → 6 模糊命中。同档内按 `sortOrder` 降序、代码长度升序、代码、场所、instrumentId。

- **归一化**：比较前去掉 `/ - _ . 空格 :`，于是 `btc/usdt` 命中 `BTCUSDT`，`brk-b` 命中 `BRK.B`。不做拼音、不做中文分词——中文名要靠 `aliases` 注入。
- **模糊档只是兜底**：只要前五档有命中，模糊结果就不混进列表；`{ fuzzy: false }` 可完全关掉。
- **空查询返回空数组**（纯空白同理），不是返回全部。
- `suggestSymbols(index, q, n)` 只回精确与前缀命中，适合自动补全。
- `findSymbol(index, q)` 回第一条命中，适合「你刚粘贴进来的那一串」。
- **下架标的缺省被过滤**（`status === 'delisted'`）；要看它们显式传 `filter: { includeDelisted: true }`。

`SymbolFilter` 的字段：`venues` / `kinds` / `assetClass` / `quote` / `sources` / `includeDelisted`，单值或数组都行，`quote` 大小写不敏感。

## 3. 挑选校验

`validateSelection(record)` 返回 `undefined` 表示可以挑；否则返回 `{ code, message }`：

| 码 | 触发条件 |
|---|---|
| `EMPTY_SYMBOL` | 代码为空 |
| `CN_CODE_NOT_STOCK` | 六位数字但不是股票（A 股代码形状被期货 / 其它品种占用） |
| `HK_CODE_NOT_STOCK` | `.HK` 结尾但不是港股 |
| `CRYPTO_NOT_A_PAIR` | 加密标的不是 `BASE-QUOTE` 对 |

这四条挡的是「看起来对、其实下不了单」的输入。**它不是下单前置检查的替代品**：真正的闸门在风控与连接器的能力声明里，这里只是界面层的早期拒绝。

## 4. 记录里有什么、没有什么

`SymbolRecord` 只带展示与过滤需要的字段：代码、名称、场所、市场类型、资产类别、报价货币、状态等，**不带价格**。所以索引可以长期缓存，行情另取。

## 5. 边界

- 连接器没 `start()` 时 `listInstruments()` 是空清单，索引也就是空的——本包不替你拉。
- 排序权重由调用方给（我们不落库）；要持久化自选的顺序，自己存。
- 不在本包做的是：行情、下单、权限、拼音检索。

## 6. 一处有意与参照不同的行为

参照实现的「名称包含」因为 SQL 占位符绑错，实际落到了兜底分支；本包按注释意图实现（名称包含一律第 3 档）。这是**有意偏离**，不是照抄：如果你拿参照实现对数字，这一档会不一样。
