# 安全

这一篇写清「它到底保证什么、不保证什么」。每条都对应内核里的代码；没做到的直接写没做到。

## 1. 三档威胁模型

| 档 | 威胁 | 承诺 |
|---|---|---|
| **T-A** | 经 MCP 接进来的 Agent，包括被提示注入、被记忆注入的 | **强制**。批准、限额、钥匙、恢复交易**根本不在工具面上**（没有入口，不是「有入口但拦住」）；所有下单都过授权书与风控闸；每条记录的来源由服务端按已认证身份盖章，Agent 不能自报身份；Agent 只能触发自保动作：停止新开仓 / 撤单 / 全平 / 自降级；停止策略只限自己启动的实例（停别人的要「需确认」以上） |
| **T-B** | 本机其他进程经本地接口发请求（含带 shell 的编码 Agent） | **强制**。所有本地接口都要令牌；人面会话令牌只在界面进程内存里、不落盘；放宽类动作要 PIN；风控策略是内核验签的文档，缺失或被改动即进入 `HALTED`。**如果它能执行任意代码去改文件、读内存，就落到 T-C** |
| **T-C** | 同一系统用户下的恶意代码（改文件、读内存、解开用户级加密、读已解锁的密钥） | **不保证**。缓解办法：API 钱包没有提现权限、用独立子账户、把限额压小。M1 没有「加固模式」 |

**「风控不可绕过」只覆盖经工作台执行的订单**：引擎模式 A（订单交给内核发）、你手动下的单、Agent 经 MCP 下的单。外部引擎自己连场所下的单（模式 B）风控只是建议性的，界面会标注。

## 2. 本地接口鉴权

- 服务只绑 `127.0.0.1`。
- **无令牌即无身份**。`Origin`、`Sec-Fetch-Site`、`Host` 这些请求头**只用来额外拒绝**（跨站浏览器请求、DNS 重绑定），永远不用来放行——非浏览器进程可以随便伪造。
- 四种令牌，各管各的：

  | 令牌 | 谁用 | 生命周期 | 能力 |
  |---|---|---|---|
  | 会话 `ses_…` | 工作台界面 | 只在内存，12 小时，重启失效 | 会话级动作 |
  | 引导 `boot_…` | `serve` 打印的链接 | **一次性、120 秒** | 换会话令牌，用过即废 |
  | 服务 `svc_…` | 命令行等本机工具 | 存 `service.json` | 只读 + PIN 在场的动作，**不能当会话** |
  | Agent 钥匙 `gtk_…` | 接进来的 Agent | 到授权书有效期 | 只在授权书范围内；明文只显示一次 |

- `service.json`、钥匙库、PIN 文件写入时收紧权限：POSIX 上 `chmod 600`，Windows 上用 `icacls` 去掉继承、只留当前用户。收紧失败不会崩，但会在状态里如实标注。

## 3. PIN

- 6–12 位数字，或 8–64 位任意字符的口令（界面仍叫 PIN）。连号或全相同的弱 PIN（如 `123456`、`000000`），网页与终端都会先问一次「仍要使用吗」，确认了才会设置。
- 用 scrypt（N=2^17, r=8, p=1，约 128 MB 内存）派生，**再与设备密钥经 HKDF-SHA256 合并**成 32 字节主密钥；磁盘上只存盐与校验值。
- 失败退避：前 3 次不锁，之后 1s、2s、4s… 指数增长，最长 15 分钟；退避状态落盘，重启不清零；终端（CLI）与工作台共用同一个计数。**锁定期间输什么都不会被评估，正确的 PIN 也要等倒计时结束。**
- PIN 不进日志、不进账本、不进错误信息；命令行**永远不从参数读 PIN 或私钥**（只从终端隐藏输入或 stdin 读）。

## 4. 密钥静态加密

- API 钱包私钥存在 `~/.gitrader/keys/keystore.json`，用 **AES-256-GCM** 加密；主密钥由 PIN 派生，**不落盘**，解锁后只在内存，可随时锁回。
- 私钥永远不出内核：生成钱包只返回地址；导入时私钥从终端隐藏输入读入。
- 安装签名钥（给账本检查点签名）在 `keys/install-key.json`。
- 设备密钥在 `keys/device.key.json`：32 字节随机数，首次设 PIN 时生成。**Windows 上用 DPAPI（CurrentUser）包裹**；macOS / Linux 只有文件权限 0600，**没有系统钥匙串包裹**。

**这层防什么**：只拷走 `pin.json` + `keystore.json`（备份、同步盘、整机镜像到别的账户 / 机器）而没有设备密钥，无法离线穷举 PIN。Windows 上设备密钥文件换到别的机器 / 用户下解不开。三个文件一起被拷时，退回到「PIN 强度 + scrypt N=2^17」——单核一次约零点几秒，6 位数字扛不住有算力的人，所以建议用口令。

**仍然不保证**（T-C）：同用户恶意代码能调 DPAPI、能读已解锁时的内存、能装键盘记录。

**操作要求**：别把 `~/.gitrader/keys/` 放进同步盘。设备密钥丢了（重装系统、换用户）= 钥匙库打不开，只能用你另存的 API 钱包私钥重新导入。API 钱包建议不超过 180 天并定期轮换（提醒天数由 `keys.walletExpiryWarnDays` 控制，默认 14 天）。

## 5. 人面专属动作

以下动作 Agent 钥匙一个也调不了。「PIN」= 必须当场输入；「会话」= 工作台会话即可。

| 动作 | 在场要求 |
|---|---|
| 解锁钥匙库、给运行中的实例要新启动链接、轮换服务令牌 | PIN |
| 从 `REDUCING` / `HALTED` 恢复交易 | PIN |
| 放宽风控（含临时放宽，最长 24 小时到期自动回收） | PIN |
| 关闭「大模型不得实盘开仓」 | PIN（开启它只需会话） |
| 切风控预设：变宽要 PIN，变严会话即可 | PIN / 会话 |
| 创建 / 轮换 Agent 钥匙、签发或升级授权书 | PIN |
| 绑定引擎到账户 | PIN |
| 批准提案 | 会话；纸面账户批准不用 PIN，实盘账户、或单笔名义超过这把钥匙的 PIN 门槛（`presenceAboveNotional`）时才要输 PIN；批准实盘单且钥匙库已锁时先输 PIN |
| 撤销 Agent 钥匙（界面：设置 → 钥匙 → Agent 钥匙 → 撤销；终端：`gitrader keys revoke agent <名字>`） | PIN |
| 收紧风控、拒绝提案、撤销授权书 / API 钱包 | 会话 |
| 授予插件权限、卸载插件、导出账本、切主网 / 测试网、开关「允许 Agent 调整布局」 | 会话 |
| 改 PIN | 当前 PIN |

**接管**（停止新开仓 / 撤销挂单 / 全部平仓）人和 Agent 都能触发，**不需要 PIN**——自保动作要快（停止策略不属于接管，见上）。

## 6. 风控与停机

- 风控闸是**唯一的**下单检查点：授权书（额度、账户 / 场所 / 标的白名单、有效期、心跳）与风控策略（限额、保护器）取最严的那个；行情陈旧或缺价格一律拒单。
- 交易状态三态 `ACTIVE` / `REDUCING` / `HALTED`。进入后两者包括：你按了接管、保护器触发、Agent 心跳超时、启动对账失败、风控策略验签失败。
- `HALTED` 的放行面：撤单与**仅减仓**平仓（停机不能让人平不掉仓）；一切增加敞口的动作、启动策略、签发授权书、启动插件都被拒。恢复只能由你输 PIN。
- 授权书要求心跳时，Agent 心跳超时会自动降到只读并停止新开仓。
- 大模型来源的动作在账本与界面里永远标注来源（人 / 引擎 / LLM Agent / 系统），可一键禁止。**Gitrader 自己不调用任何大模型。**

## 7. 账本

- 只追加的 SQLite 账本，每条带前一条的哈希（哈希链），定期写检查点，用安装签名钥签名。`gitrader ledger verify` 重算整条链。
- **只认内核时钟**：账本条目的时间一律是内核时钟。下单意图里调用方自带的时间字段（`ts` / `timestamp` / `createdAt` / `clientTs` / `sentAt`）比内核时钟早 60 秒以上或晚 5 秒以上，这一单会被拒（`INVALID_PARAMS`）；在容差内也只当备注，不进账本、不影响任何判断。意图里协议没有的字段一律丢弃，回执的 `warnings` 会点名「已忽略未知字段」。
- **启动验链**：内核每次启动都重算账本哈希链（条目很多时从最近检查点验起，运行中每 10 分钟全量一次），并把最近 200 条成交和成交表逐条对一遍。断链或对不上 → 全部交易停止（`HALTED`），恢复交易前会重验，仍不过就拒绝恢复；`gitrader doctor` 会亮红并给出下一步。
- **账本库不见了不会悄悄重来**：`data/gitrader.sqlite` 不在、但本机还留着签名钥 / 纸面状态 / Agent 令牌时，`gitrader serve` 拒绝启动。从备份还原；确定要从空账本重来才加 `--accept-new-ledger`（新账本第一条会记下这件事）。如果 `paper-state.json` 里还有持仓、未结订单、被动用过的现金或前移的序号（新账本里没有它们的来历），光有 `--accept-new-ledger` 也会被拒绝，并且什么都不动、不留空账本。二选一：加 `--reset-paper-state`（旧纸面状态连同 `.prev` 移进 `backups/paper-state-<时间>/`，纸面账户按配置的初始资金重来，日志里写出备份路径）；或者保留原状，先把账本还原回 `data/gitrader.sqlite` 再不带参数重启。`--reset-paper-state` 只在账本库不在、同时带 `--accept-new-ledger` 时有意义；账本在的时候单独用它是参数错误。`gitrader doctor` 在账本库不在或纸面状态没有账本摘要可核对时，纸面一项至少亮黄灯，不会再写“和账本记录的摘要一致”。
- **纸面状态和账本互相核对**：`paper-state.json` 的摘要记在账本库里；文件被删、被截断、被改过、拿旧备份顶替 → 纸面账户停止交易，原文件和 `paper-state.json.prev` 都不动、绝不覆盖。出路：把原文件或 `.prev` 改回来后重启，或停掉服务后运行 `gitrader paper rebuild-from-ledger`（以账本为准重建现金、持仓与在挂的止损）。写盘失败时内核自动重试，下单回执带 `state_not_persisted` 提醒。
- 回测 / 回放数据不得写入前向账本；载荷里出现密钥类或供应商私有字段会被拒绝入账。
- **诚实说明**：本机哈希链只能证明**导出后没被改**，防不了拥有整个账本文件的人整条重写。导出件（`gitrader-ledger-export/2`）另带导出时的链头和用安装签名钥打的签名，`ledger verify <导出目录>` 因此能发现被删掉尾部；但能读到本机安装私钥的人仍可以重新签一份。细节见 [04-回测与研究](04-回测与研究.md) 的导出一节。

## 8. 其他边界

- **iframe 嵌入**：默认禁止（`frame-ancestors 'none'`）。要嵌进宿主页，配 `embed.allowedOrigins`（只接受 `scheme://host[:port]`，不许通配符 / 路径）。放宽的只是「跨站页面 GET 导航进 iframe」；`/api` 与 WebSocket 仍然必须有令牌。
- **免 PIN 取链接**：`gitrader open --print --json --unattended --origin <源>` 用服务令牌，**只有**在 `embed.allowedOrigins` 已配置且 `--origin` 在名单里才放行。开了它，本机任何能读 `service.json` 的同用户进程都能换到工作台会话（能做会话级动作；要 PIN 的动作仍然要 PIN）。不用嵌入就别开。
- **刷新页面要新链接**：会话令牌只在页面内存里，启动令牌一次性——这是设计，不是故障。
- **下单幂等与「结果未知」**：所有下单类操作接受 `clientOrderId`（MCP 会自动生成并在预览结果里回显）。`retryable: true` 只表示「请求没发出 / 没被处理，可以原样重试」（例如内核没在运行）。请求发出后超时或连接中途断开，一律报 `VENUE_OUTCOME_UNKNOWN`（结果未知，`retryable: false`），并带上本次的 `clientOrderIds`：**不要直接重发**，先按 id 查（`order.lookup` / `ledger trace`），要重试就用同一个 id（内核返回原订单，场所只收到一次）。内核在单子发到纸面场所之前就停了的，重启后这张单会记为「从没下出去」（`INTERRUPTED_BEFORE_VENUE`），同一个 id 可以再下一次。
- **Agent 调用频率**：每把钥匙（以及会话、服务令牌、引擎）各有一个令牌桶：默认容量 200、每秒补 60；行情 / 报价 / 预览这类只读调用另走一个更小的桶（容量 100、每秒补 30）。浏览器工作台的会话（人）单独一个大桶（容量 1000、每秒补 300，只读与命令共用），同一会话开两个窗口也不会互相挤掉。下单、撤单、平仓、急停、批准不计数（自保动作不能被限流挡住）。超出返回 `RATE_BUDGET`（HTTP 429，带 `retryAfterMs`），被限次数进指标 `gitrader_op_rate_limited_total`，账本每把钥匙每分钟最多记一条 `rate.limited`。预览被拒也入账，但每把钥匙每分钟只逐条记前 20 条，其余记一条汇总（条数、规则分布、样本），每天再记一条日汇总。可在 `server` 段的 `operationRateLimit`（含 `readOnly`、`session`）里调。
- **重启后的止损**：开仓时带的止损如果因为内核崩溃没记下来，重启时内核会认领场所上的那张止损；场所上也没有的，纸面账户自动补挂一张（只补一次，人后来撤掉的不会被挂回去），实盘账户只告警并转只减仓、等你确认。
- **插件**：进程隔离**不是安全沙箱**，权限在内核 API 层强制；网络限制不由 Node 强制。
- **引擎**：本地子进程不继承你的环境变量；引擎拿不到 API 钱包私钥（模式 A）。
- **数据**：默认不出本机。
- **供应链**：依赖钉版本；构建产物随附 `THIRD-PARTY-NOTICES.md`。

## 9. 一句话总结

| 保证 | 不保证 |
|---|---|
| 经工作台的订单过授权书与风控闸 | 外部引擎自己连场所下的单 |
| 人面动作只能由你在场完成 | 同系统用户下的恶意代码 |
| 密钥加密存放，PIN 不落盘 | 三个密钥文件一起被拷走时的离线穷举 |
| 账本可验证、可导出 | 拥有整个账本文件的人整条重写 |
| 插件只能拿到你授予的权限 | 插件本身是不是恶意代码（靠签名与来源） |
