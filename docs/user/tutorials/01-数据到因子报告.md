# 教程 01 · 从 K 线到一个因子报告

这条教程把「数据进来 → 因子统计出去」走一遍：先看懂一份 K 线文件的形状，再用 `tools/research` 把全部
Alpha158 因子跑成一份 Markdown + HTML 报告。全程**不联网也能做**——仓库自带三份合成样例数据（`assets/samples/`）。

跟着敲之前：命令都在**仓库根目录**执行，产物写到 `./tutorial-lab/`（教程自己的练习目录，删掉这一个目录就干净了；
你想换成绝对路径也行，把命令里的 `./tutorial-lab` 替换掉即可）。

> 全局装过 Gitrader 的机器，命令里的 `gitrader` 直接用。在源码树里没装全局包时，先 `npm run build`，
> 然后把 `gitrader` 换成 `node packages/cli/dist/bin.js`。

## 1. 建练习目录

```bash
mkdir -p ./tutorial-lab
```

## 2. 认识数据文件

样例是 `t,o,h,l,c,v` 的 CSV，一行一根 K 线，`t` 是开盘时间的 Unix 毫秒：

```text
t,o,h,l,c,v
1735689600000,62000,62279.25,61903.03,62152.59,1419
```

| 字段 | 含义 |
|---|---|
| `t` | 开盘时间（毫秒） |
| `o` / `h` / `l` / `c` | 开 / 高 / 低 / 收 |
| `v` | 成交量（合成数据里是造出来的量级，不是任何交易所的真实成交量） |

三份样例（来源与许可见 `assets/samples/README.md`）：`btcusdt-1h.csv`（1500 根 1h）、
`ethusdt-1h.csv`（1200 根 1h）、`solusdt-4h.csv`（900 根 4h）。都是**合成数据**，价格走势是随机走的，
没有任何市场含义。

## 3. 转成规范 JSON 并体检

`tools/data/inspect.mjs` 是 `@gitrader/data-files` 的薄封装：`normalize` 把原始 CSV 转成规范 JSON，
`inspect` 做体检（行数 / 周期 / 缺口 / 重复 / OHLC 违规），`manifest` 给文件摘要。

```bash
node tools/data/inspect.mjs normalize assets/samples/btcusdt-1h.csv ./tutorial-lab/btcusdt-1h.json
```

```bash
node tools/data/inspect.mjs inspect ./tutorial-lab/btcusdt-1h.json
```

输出里有这么几行（数字来自这份样例）：

```text
rows: 1500
parsed: 1500
skipped: 0
duplicates: 0
interval: 1h (1h, confidence 1.000)
gaps: none
ohlc violations: 0
```

`manifest` 打印绝对路径 + `sha256` + 格式 + 类型，回测与研究报告都靠这个摘要指认「用的是哪份数据」：

```bash
node tools/data/inspect.mjs manifest ./tutorial-lab/btcusdt-1h.json
```

## 4. 出因子报告

`tools/research/factor-report.mjs` 吃 CSV 或 JSON，算 **157 条因子**（Alpha158 口径：KBAR 9 + 价格 3 + 滚动 29 族 × 5 窗口），
对「未来 n 根收益」做 IC / 滚动 IR / 分位组收益：

```bash
node tools/research/factor-report.mjs assets/samples/btcusdt-1h.csv \
  --horizon 11 --window 60 --quantiles 5 --top 30 \
  --title "样例 · BTC 1h" \
  --md ./tutorial-lab/factors.md --html ./tutorial-lab/factors.html
```

| 参数 | 缺省 | 含义 |
|---|---|---|
| `--horizon n` | 5 | 前向收益取未来第 n 根收盘 |
| `--window w` | 60 | 滚动 IC 的窗口（根） |
| `--quantiles q` | 5 | 分位组数 |
| `--top k` | 20 | 报告里列多少条因子 |
| `--md` / `--html` | 与输入同目录 | 输出路径 |

## 5. 报告看什么

打开 `./tutorial-lab/factors.md`，三件事值得先看：

1. **数据摘要**：文件、`sha256`、根数、时间范围——报告和数据的对应关系是钉死的。
2. **因子表**：按 |IC| 降序，含 IC、滚动 IR、t 值、IC>0 占比、Q1/Q5 组收益、单调性、有效点。
3. **口径与限制**：分母为 0 记 0、数据不足记 null、分位组收益是等权无成本的前向收益均值。

**这两个数字不要读成业绩**：样例是合成数据，IC 高低只反映「这份随机序列里因子和未来收益的秩相关」，
换一份数据就变。真实数据上同一个因子在不同时间段也会翻号——要先看滚动 IR 与 IC>0 占比是否稳定，
再看分位组是否单调。报告末尾那行免责声明不是装饰。

## 6. 换成你自己的数据

**方案 A：用仓库里的抓取脚本（会联网）**。`tools/data/fetch-candles.mjs` 从交易所公共行情接口拉 K 线，
落成同样的规范 JSON + 清单。它会访问对应交易所的行情主机，不带任何密钥、只发 GET：

```text
node tools/data/fetch-candles.mjs --venue binance --instrument BTCUSDT --interval 1h \
  --from 2025-01-01 --to 2025-03-01 --out ./tutorial-lab/binance-btcusdt-1h.json
```

这条**需要联网**，教程的冒烟脚本不跑它（其余命令都跑）。参数与退出码见 `tools/data/README.md`。

**方案 B：用你自己的文件**。把 CSV 或 JSON 放到任意路径，把上面命令里的 `assets/samples/btcusdt-1h.csv` 换掉即可。
格式要求只有一条：`t` 升序、`t,o,h,l,c[,v]`（JSON 是 `{"candles":[…]}`、`[{…}]` 或 `[[…]]`），坏行会被跳过。

## 7. 做完了你应该能回答

- 这份数据的 `sha256` 是多少？报告里在哪一行？
- 换 `--horizon 5` 和 `--horizon 11`，因子排序变了多少？为什么前向窗口一改，IC 就会变？
- 哪些因子的 Q5−Q1 是负的？负的价差和单调性为负是同一件事吗？
