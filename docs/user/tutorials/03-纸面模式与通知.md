# 教程 03 · 纸面模式起内核，配一条通知通道，触发一条通知

这条教程把「内核起来 → 装一个通知通道插件 → 配好通道 → 真的发出一条通知」走完。
全程**纸面模式**（`paper` 账户）、`--offline`，不连任何真实场所、不下任何单。

两个稳当的做法，教程里一直这么做：

- **用教程自己的主目录**（仓库根目录下的 `./tutorial-lab/kernel`），不碰你真实的 `~/.gitrader`；玩坏了删目录重来即可。
- **密钥只放环境变量**：配置里只写 `env:WEBHOOK_SECRET` 这样的句柄，值放启动内核的那个进程环境里。

## 1. 建主目录并初始化

```bash
gitrader init --home ./tutorial-lab/kernel
```

它会建主目录和六个子目录，写一份默认 `gitrader.json`（一个测试网场所、一个纸面账户、一个内置引擎）。
终端是交互的话它会请你设 PIN（6–12 位数字或 8–64 位口令），**PIN 不进日志、不进账本、不能当命令行参数传**。

## 2. 纸面模式起内核

```bash
gitrader serve --offline --home ./tutorial-lab/kernel --port 48950
```

预期输出：

```text
Gitrader 0.1.1 已在 127.0.0.1:48950 运行
打开工作台（链接 2 分钟内有效，只能用一次）：
  http://127.0.0.1:48950/?launch=boot_...
想再拿登录链接：在这个窗口按 Enter。停止：Ctrl+C，或在另一个窗口运行 gitrader stop。
```

服务只绑 `127.0.0.1`；`--offline` 表示不连行情（账户、账本、插件、策略文件照常可用）。
这条命令会占住这个终端，**先别关**。

## 3. 另开一个终端看状态

```bash
gitrader status --home ./tutorial-lab/kernel
```

会打印版本与 pid、交易状态（`ACTIVE` / `REDUCING` / `HALTED`）、风控策略版本、账本序号与条数、账户列表
（含 `mode: paper`）、场所连接状态、连接器 / 引擎 / 插件数量、PIN 是否已设。要机器可读加 `--json`。

## 4. 停掉服务（授权那一步要求服务不在跑）

回到第 2 步那个终端按 Ctrl+C —— 也就是这一步要做的：

```bash
# 在 serve 那个终端按 Ctrl+C
```

授权入口（下一步的 `plugins grant`）要本地 PIN 在场，并且要求服务不在跑，避免两边同时写权限。

## 5. 装通道插件

通知在 Gitrader 里不是内置通道，是**插件**：声明了 `notify_send` 工具的插件就是一条通道。
本仓自带的 Webhook 插件在 `packages/plugin-notify-webhook/`，拷进主目录的 `plugins/` 下：

```bash
cp -r packages/plugin-notify-webhook ./tutorial-lab/kernel/plugins/notify-webhook
```

```bash
rm -rf ./tutorial-lab/kernel/plugins/notify-webhook/node_modules
```

（`node_modules/` 只是本地开发依赖目录，插件运行时只要那几个 `.mjs` 与清单。）

改过文件就要重新钉版本（写 `source.sha256`），然后校验清单：

```bash
gitrader plugins pin ./tutorial-lab/kernel/plugins/notify-webhook
```

```bash
gitrader plugins check ./tutorial-lab/kernel/plugins/notify-webhook
```

校验通过会打印 `ok connector.gitrader.notify-webhook@0.1.0`，退出码 0；不通过退出码 2 并逐条列出问题。

## 6. 配一条通道（顺带打开开发者模式）

配置在 `./tutorial-lab/kernel/gitrader.json` 的 `notify` 段。`notify.channels[]` 每一项是
`{ id, plugin, minLevel, params }`，`params` 里只放**非密钥**的目标参数（`url` / `chatId` / `to`…），
密钥一律走 `plugins.secrets` 的 `env:` 句柄。

```bash
node docs/user/tutorials/add-notify-channel.mjs \
  --home ./tutorial-lab/kernel \
  --id main \
  --url http://127.0.0.1:8787/hook \
  --min-level warn
```

它只动三处，其余键原样保留：`plugins.developerMode`、`plugins.secrets["connector.gitrader.notify-webhook"].WEBHOOK_SECRET
= `"env:WEBHOOK_SECRET"`、`notify.channels` 里加一条 `main`。脚本只做参数形状自检；整份配置的正式校验由内核做——第 9 步的 `notify test` 会读这份配置，写错了那一步直接报 Problem。

**为什么先开开发者模式**：本仓的通道插件没有签名，只有 `plugins.developerMode: true` 才会被内核加载；
没开的话下一步授权会被拒（`UNSIGNED_NOT_ALLOWED`）。开发者模式是本地开发用的折中——它放宽了「必须签名」这一条，
但**不能**申请 `trade.live` 与 `venue.credentials` 这类权限。装第三方插件时请回到签名 + 信任根的路径。

改完的配置长这样（节选）：

```json
{
  "plugins": {
    "developerMode": true,
    "secrets": { "connector.gitrader.notify-webhook": { "WEBHOOK_SECRET": "env:WEBHOOK_SECRET" } }
  },
  "notify": {
    "channels": [
      { "id": "main", "plugin": "connector.gitrader.notify-webhook", "minLevel": "warn",
        "params": { "url": "http://127.0.0.1:8787/hook" } }
    ],
    "rules": [ { "match": "*", "level": "warn", "channels": ["main"] } ]
  }
}
```

`minLevel` 是这条通道的最低等级（`info` / `warn` / `critical`）：低于它的通知不走这条通道。
`rules` 按 `topic` 前缀路由（`risk.*`、`takeover.*`…），`match: "*"` 表示全都走 `main`。

## 7. 授权（要 PIN）

插件声明了 `net.fetch` 权限，得由你（人）授一次——这一项要 PIN，而且要服务不在跑：

```bash
gitrader plugins grant connector.gitrader.notify-webhook net.fetch --home ./tutorial-lab/kernel
```

成功打印 `granted connector.gitrader.notify-webhook: [net.fetch]`。看一眼列表：

```bash
gitrader plugins list --home ./tutorial-lab/kernel
```

那一行的形态是 `ok  <id>  <版本>  connector  granted:[net.fetch]  pending:[]  enabled:yes`。

## 8. 起一个本地接收器

没有飞书 / 钉钉 / Slack 也能验证链路：用这个只监听本机回环地址的小服务当 webhook 端点。

```bash
node docs/user/tutorials/notify-sink.mjs --port 8787
```

它会打印 `通知接收器已起：http://127.0.0.1:8787/hook（Ctrl+C 停止）`，每收到一条就打印方法、路径和正文。
这条也会占住终端，**另开一个终端**做下一步。

## 9. 发一条测试通知

密钥句柄要在**启动内核的那个进程环境**里能解析。真实通道这里填你平台给的签名密钥；
本地接收器不校验签名，随便给一个占位值就行：

```bash
export WEBHOOK_SECRET='local-lab-placeholder'
```

```bash
gitrader notify test main --home ./tutorial-lab/kernel
```

`notify test` 发一条固定内容的 info 诊断消息（标题「通知通道测试」，正文带通道 id），
走的是内核的通知出口 → 插件 → 你的端点这一整条真链路；成功退出码 0：

```text
{
  "results": [
    {
      "channelId": "main",
      "ok": true
    }
  ]
}
```

回到第 8 步那个终端，应当看到收到的正文：

```text
#1 2026-10-21T08:40:11.000Z POST /hook
  {"text":"通知通道测试\nchannelId: main"}
```

## 10. 收尾

在两个占住终端的窗口各按一次 Ctrl+C：

```bash
# 在 notify-sink 那个终端按 Ctrl+C
```

服务没在跑时 `gitrader status` 会写明状态和下一步命令，退出码仍是 0；脚本里要判断是否在跑，读 `--json` 的 `running` 字段：

```bash
gitrader status --home ./tutorial-lab/kernel
```

## 11. 换成真实通道

只要把第 6 步的 `--url` 换成你平台的 webhook 地址，别的都不变（`params.url` 决定方言）：

| 平台 | `url` 形态 | 签名密钥 |
|---|---|---|
| 飞书 | `https://open.feishu.cn/open-apis/bot/v2/hook/<token>` | 可选，`WEBHOOK_SECRET` |
| 钉钉 | `https://oapi.dingtalk.com/robot/send?access_token=<token>` | 可选，`WEBHOOK_SECRET` |
| 企业微信 | `https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=<key>` | 不需要（key 在 URL 里） |
| Slack | `https://hooks.slack.com/services/<...>` | 不需要 |
| Discord | `https://discord.com/api/webhooks/<...>` | 不需要 |
| 自建 | 你自己的 `http(s)://` 端点 | 由你的服务决定 |

Telegram 与 SMTP 是另外两个插件（`plugin-notify-telegram` / `plugin-notify-email`），配置项不同，
见 `docs/user/06-通知配置.md`。

## 12. 三条行为要知道

1. **正文只有结构化事实**。提案理由、接管理由、备注、策略说明这类自由文本不进通知正文——
   通知是给你看「发生了什么」，不是转发模型说的话。
2. **同一次接管只发一条**。接管以 `takeoverId` 关联，去重窗口内阶段更新不重复发；失败阶段另发一条 `critical`。
3. **短密钥值也不打印**。返回结果与日志里的密钥原文（含 base64）一律替换成 `<redacted>`；
   错误里出现 URL 时只留 `origin + 路径第一段`，query 去掉。

## 13. 排错

| 现象 / 返回 | 原因 | 怎么办 |
|---|---|---|
| `MANDATE_LIMIT ... not enabled` | 插件没授权过 | 回到第 7 步 `plugins grant` |
| `missing secret handle: WEBHOOK_SECRET` | 配置有句柄但进程环境没有这个变量 | `export WEBHOOK_SECRET=...` 后重跑 |
| `reason: "network_error:fetch failed"` | 端点没在听 / 地址写错 | 先确认接收器在跑、`url` 的端口与路径对得上 |
| `REJECTED 1 problem(s)  UNSIGNED_NOT_ALLOWED` | 没开开发者模式 | 第 6 步的脚本会开；手改配置时别漏 |
| `unknown channel` | `notify.channels` 里没有这个 id | `--id` 与 `notify test <id>` 要一致 |
