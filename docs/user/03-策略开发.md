# 策略开发

## 1. 策略是什么

一条策略就是**一个纯函数**：给它一段收盘 K 线和一组参数，它对每根 K 线回答一个问题——「这里我想持多少仓」。

```text
target = +1     满仓做多
target =  0     空仓
target = -1     满仓做空
target = 0.5    半仓做多
```

引擎负责把 `target` 的**变化**翻译成订单意图、算仓位、过风控闸、发到场所。策略本身**不下单、不计算下单数量、不接触场所和密钥**。这条分工是有意的：你能改的东西改不出「绕过限额」这种事。

## 2. 文件放在哪

```text
~/.gitrader/engines/<engine-id>/strategies/<你的id>.ts
```

随包的内置引擎 `<engine-id>` 是 `gitrader-core`。文件夹是被监视的：存盘后引擎约一秒内校验并热加载，**不需要重启服务**。校验失败会给出可读的错误，改完再存一次即可。要看当前加载报告，调引擎侧扩展方法 `x-gitrader.strategy.files`（需要引擎声明了 `x-gitrader.strategy-folder` 能力）。

起步方式二选一：

- 空白开始：`gitrader examples copy template`；
- 从能跑的例子改：复制 `packages/engine-core/examples/strategies/` 下的任意一份。

示例是**教学材料，无业绩含义**，不随产品发布，也不默认加载。

## 3. 文件形状

```ts
const strategy: StrategyDef = {
  id: 'my-breakout',          // 小写字母、数字、短横线；2–40 字符；文件夹内唯一
  name: 'Donchian breakout',
  nameZh: '唐奇安突破',        // 可选
  version: '0.1.0',           // 语义化版本；逻辑一改就要升，回测会记下它
  desc: '…',                  // 平实描述规则、什么时候会失效；不写业绩与承诺
  tags: ['trend'],

  params: [
    { key: 'period', label: '回看根数', type: 'integer', default: 20, min: 2, max: 400, step: 1 },
  ],

  // 可选钩子，见第 6 节
  // anchor(candles, params) { return params },

  evaluate(candles, params) {
    const n = candles.length
    const target = new Array(n).fill(0)
    const reasons = new Array(n).fill('')
    const overlays: Record<string, Array<number | null>> = {}
    const warmup = 0
    return { target, reasons, overlays, warmup }
  },
}
```

### `evaluate` 的输出契约

| 字段 | 类型 | 要求 |
|---|---|---|
| `target` | `number[n]` | 每根 K 线一个目标仓位，落在 `[-1, 1]`，必须是有限数；预热期填 0 |
| `reasons` | `string[n]` | 目标变化的那根必须给一句人话原因，没变化填 `''`。它会被存进信号与订单，出事时靠它复盘 |
| `overlays` | `{ [名字]: (number\|null)[n] }` | 画在价格图上的线；`{}` 也行；最多 12 条 |
| `warmup` | 整数 ≥0 | 第一根有有效信号的下标；还在预热时可以大于 `n` |

函数必须能扛住 `n = 0`、`n` 小于参数周期、以及每个数值参数取到最小值或最大值——都不许抛异常。

## 4. 参数：两种写法，各用在哪

`params` 是参数的唯一真相。引擎加载策略文件时只认**写法 A**；**写法 B** 是同一套参数的注释写法，由工具链（生成策略、抽参数、回写默认值）解析，只写注释不会被当成 `params`。两种写法最终过同一套校验：类型只认 `number` / `integer` / `boolean` / `select`。

**写法 A：`params` 数组**（引擎加载认这个；随包示例 `packages/engine-core/examples/strategies/grid.ts` 就是这种）

```ts
params: [
  { key: 'period', label: '回看根数', type: 'integer', default: 20, min: 2, max: 400, step: 1 },
  { key: 'mode', label: '档位', type: 'select', default: 'fast', options: ['fast', 'slow'], help: '…' },
  { key: 'allowShort', label: '允许做空', type: 'boolean', default: true },
]
```

`ParamDef` 字段：`key`（camelCase，字母开头）、`label`、`type`（`number` / `integer` / `boolean` / `select`）、`default`、`min`、`max`、`step`、`options`（`select` 用）、`help`、`hidden`（内部参数，表单里不显示）。

**写法 B：文件头 `@param` 注释**（工具链读；类型与写法 A 同一套）

```text
// @param <key> <type> default=<v> [min=<v>] [max=<v>] [step=<v>] [values=a|b|c] [label="…"] [help="…"] [hidden]
```

`<type>` 只能写 `number` / `integer` / `boolean` / `select`；`values` 只对 `select` 有效，选项用 `|` 分隔（不是逗号），`default` 必须是其中一个选项。例如：

```ts
// @param fast_len integer default=12 min=5 max=30 step=1 label="快线"
// @param band_pct number default=1.5 min=0.2 max=5 help="通道宽度百分比"
// @param source select default=close values=close|hl2|hlc3 label="价格来源"
```

写成 `int` / `float` / `str`，或者写成 `values=close,hl2,hlc3`（逗号分隔），都会被拒。注释解析器同时认 `//` 和 `#` 前缀；回写默认值时只改 `default=` 那一段，行内其余 token 原样保留。

**规则**（违反会被拒绝，不会被静默修正）：

- 没在 `params` 里声明的键，传进来就是 `unknown parameter`；超范围、类型不对同样报错，**不会**替你夹到边界。
- 参数名不许像密钥（`privateKey`、`secret`、`apiSecret`、`mnemonic`、`seed`、`passphrase` 一类）。
- `size` 是保留名：单笔大小的上限由引擎统一管，不由策略参数决定。

## 5. 禁止事项

这些不是风格建议，验证器会拦：

1. **运行时不许 `import`。** 任何被擦除的类型导入（`import type`）没问题；真正的运行时依赖不行——需要的帮助函数复制进同一个文件。
2. **不许有 I/O 与副作用。** 网络、文件、`process`、环境变量、`eval` 都不许。
3. **必须确定。** 同样的 `(candles, params)` 必须得到同样的输出：不许 `Math.random()`、不许 `Date.now()`、不许跨调用保留隐藏状态。
4. **不许改参数。** 校验时 `candles` 是冻结的。
5. **不许看未来。** `target[i]` 只能用 `candles[0..i]`；拿全序列的均值 / 极值做归一化也算违规。验证器会把历史截断后重跑，只要早先的某个信号变了就判失败。
6. **不许在运行时调模型。** 语言模型可以帮你写一次代码，但它不在实时决策路径上。
7. **`desc` 不写业绩承诺。** 说规则做什么、什么时候容易失效，就够。
8. **同一账户同一标的同一时刻只允许一个策略（或工作流）实例持有目标仓位。** 要换策略先停旧的。风控按账户 × 标的的净持仓计敞口，两个策略在同一账户同一标的上会为一个净仓位打架。

## 6. 钩子

| 钩子 | 何时被调 | 用途 |
|---|---|---|
| `evaluate(candles, params)` | 必需。每根收盘 K 线 | 产出 `target` / `reasons` / `overlays` / `warmup` |
| `anchor(candles, params)` | 可选。实例或回测**启动时**调一次 | 冻结依赖「从哪儿开始」的参数（比如网格中心价）。返回值只能包含 `params` 里声明过的键 |

## 7. 四个模板怎么改参数

示例里有四个成套的机器人模板（网格、定投、马丁、趋势），它们的参数都写在文件自己的 `params` 数组里——**打开文件看 `key` 就是能传的名字**，不要在文档里背参数名。改法只有三种：

1. **改文件里的 `default`**：改完顺手把 `version` 升一位（回测会记版本，方便对照）。
2. **不改文件，调用时传参**：`strategy.start` / `backtest.run` 里带 `params`，只传你想覆盖的键，其余取默认。
3. **对运行中的实例改**：`strategy.update`（带 `instanceId` 与 `params`），出界的值直接被拒。

四个模板各自的旋钮：

| 模板 | 主要旋钮 | 真正的风险点 |
|---|---|---|
| 网格（只做多） | 中心价与区间上下限、格数、每格仓位、等差还是等比 | 跌出区间就满仓；单边下跌时越买越多，回撤来自持仓本身而不是格子 |
| 定投 | 每隔多少根买一次、每份多大、最多买几份、止盈线 | 只做多、不择时；止盈线设得越近，交易越频繁 |
| 马丁（只做多） | 亏损后加仓倍数、最大层数、整体止盈 / 止损 | 连续亏损时仓位按层数放大，回撤也放大；这是**教学用的风险示例** |
| 趋势 + ATR | 快慢 EMA 周期、ATR 倍数、止损只朝有利方向移动 | 横盘里快慢线来回交叉，会被连续小亏磨掉；ATR 变大时单笔亏损随之变大 |

改完之后的工作流：先回测（[04](04-回测与研究.md)），再纸面，再谈实盘（[05](05-实盘与风控.md)）。

## 8. 一次改动的检查清单

- [ ] `id` 唯一、`version` 升了、`desc` 说清了失效场景；
- [ ] 新增的每个可调量都在 `params` 里声明了默认值与范围；
- [ ] `n = 0`、`n = 1`、参数取最小 / 最大都能跑；
- [ ] 每个 `target` 变化都有 `reasons`；
- [ ] 没有任何运行时 `import`、时钟、随机数、隐藏状态；
- [ ] 只用 `candles[0..i]`；
- [ ] 存盘后引擎加载报告里没有错误码。
