# 机器人模板：网格 / 定投 / 马丁 / 趋势

机器人模板（`@gitrader/bots`）是四个**可配置策略模板**：每个模板声明参数、带安全上限、能在历史 K 线上纸面回放。它不联网、不下单、不读外部状态，只算自己的纸面账。

**先读这一句：模板是给你改的骨架，不是收益承诺。每一种在什么行情下会亏，下面都写了。马丁格尔模板风险极高，连续下跌时敞口指数增长，只能用极小的资金试探，不可作为主要策略。**

## 产品里怎么用

装完 Gitrader，四个机器人模板（`bot-grid`、`bot-dca`、`bot-martingale`、`bot-trend`）已经在引擎的策略列表里。

### 1. 列出可用策略

通过 MCP 工具调用 `strategies_list`：

```json
{
  "method": "strategies_list",
  "params": {
    "engineId": "gitrader-core"
  }
}
```

会看到四个 `bot-*` id（bot-grid、bot-dca、bot-martingale、bot-trend），每个带参数声明、安全上限的 help 与 min/max/required 标记。

或在命令行查看引擎：

```bash
gitrader engines
```

### 2. 回测

提交回测作业，用自己的参数（通过 MCP 工具）：

```json
{
  "method": "backtest_run",
  "params": {
    "engineId": "gitrader-core",
    "strategyId": "bot-grid",
    "instrumentId": "BTCUSDT-PERP@hyperliquid",
    "interval": "1h",
    "params": {
      "lowerPrice": 90000,
      "upperPrice": 110000,
      "gridCount": 10,
      "maxExposureNotional": 5000
    },
    "balance": 10000
  }
}
```

回测走现有异步作业：`run` → `status` → `result`。结果带「假设 / hypothetical」标记。

### 3. 纸面账户起实例

在 paper 账户上启动一个策略实例（通过 MCP 工具 start_strategy）：

```json
{
  "method": "strategy_start",
  "params": {
    "engineId": "gitrader-core",
    "strategyId": "bot-dca",
    "accountId": "paper",
    "instrumentId": "BTCUSDT-PERP@hyperliquid",
    "interval": "1d",
    "params": {
      "frequency": "daily",
      "notionalPerOrder": 100,
      "maxOrders": 30,
      "maxExposureNotional": 3000
    },
    "mandateId": "<你的授权书>"
  }
}
```

实例状态是运行中时会按 K 线节奏出单；停机后不再出单，仓位保持原样（不自动平仓）。

### 4. 停止实例

通过 MCP 工具：

```json
{
  "method": "stop_strategy",
  "params": {
    "engineId": "gitrader-core",
    "instanceId": "<instanceId>"
  }
}
```

**缺必填安全上限会被拒**：回测和起实例都报错，错误文本点名缺的参数。例如网格缺 `maxExposureNotional`、马丁缺 `maxAdds`、定投 `notionalPerOrder × maxOrders > maxExposureNotional` 都会被拒，不会留半个实例。

## 1. 四个模板一览

| 模板 | `id` | 它做什么 | 主要会亏在哪 |
|---|---|---|---|
| 网格 | `grid` | 在 `[lowerPrice, upperPrice]` 之间铺 `gridCount` 格，价格触到开仓线就买、到平仓线就卖 | **单边趋势**：价格一路下行会持续接货，跌破下边界时按 `boundaryAction` 停或止损；一路向上会一路卖飞，手上只剩现金 |
| 定投 | `dca` | 按 `frequency`（`every_bar` / `hourly` / `4h` / `daily` / `weekly`）买 `notionalPerOrder`，可选「跌了多买」；**只做多，卖出只用于止盈 / 止损** | 长期下跌：越买越亏，靠 `maxOrders` 与 `maxExposureNotional` 兜底；横盘时来回吃手续费 |
| 马丁 | `martingale` | 反向加仓摊平：每跌 `addDropPct` 加一次，仓位乘 `multiplier` | **最危险的一种**：连续下跌时名义额指数上升，靠 `maxAdds` 与 `maxTotalNotional` 硬顶；顶到上限就停机，不会自己恢复 |
| 趋势 | `trend` | `maPeriod` 均线 + `confirmBars` 确认，顺势进出，可带移动止损 | **震荡市**：来回被打止损，手续费与滑点吃掉本金；均线参数换一段行情就失效 |

## 2. 安全上限写在参数校验里，不是写在文档里

| 模板 | 必须声明的安全参数 |
|---|---|
| `grid` | `maxExposureNotional` |
| `dca` | `maxExposureNotional`、`maxOrders` |
| `martingale` | `maxExposureNotional`、`maxAdds`、`maxTotalNotional` |
| `trend` | `maxExposureNotional` |

- 模板**构造时自检**这些键是否在 `params` 里声明过，少了直接抛。
- 超限的动作是**拒单 + 停机**，不是「把数量截小继续下」——静默截断会让风控账与实际仓位分家。
- 减少仓位的单子永远不因敞口被拒（它让敞口变小）。
- **越界一律拒，不静默夹范围**：engine-core 的参数解析会把 `maxAdds: 99` 夹成 20 继续跑，本包直接报错——夹过的配置不是你以为的那份配置。
- **跨字段也校验**：定投 `notionalPerOrder × maxOrders` 超过 `maxExposureNotional` 直接拒；趋势 `confirmBars > maPeriod` 直接拒；网格单格名义额已超上限在构造期就拒。

## 3. 编程方式使用

```ts
import { createBot, runBot, runTemplate, TEMPLATES, templateIds } from '@gitrader/bots'

templateIds()                       // ['grid', 'dca', 'martingale', 'trend']
TEMPLATES.grid.params               // 参数声明（key / label / type / default / min / max / options / help）

// 单步：建模板 → 在历史 K 线上纸面回放
const run = runTemplate('grid', {
  lowerPrice: 90_000,
  upperPrice: 110_000,
  gridCount: 12,
  maxExposureNotional: 5_000,
}, candles, {
  initialCash: 10_000,
  feeRate: 0.0005,
})

run.fills          // 每笔纸面成交
run.equity         // 每根 K 线一个权益点
run.realizedPnl    // 已实现盈亏
run.maxExposure    // 全过程最大持仓名义额
run.unfilled       // 没被触达的限价意图（正常挂单，不是错误）
run.halted         // 停机原因（触到上限 / 止损 / 越界）
```

也可以自己建实例再逐步喂：

```ts
const bot = createBot('martingale', {
  baseNotional: 100,
  multiplier: 1.5,
  maxAdds: 4,
  maxTotalNotional: 1_000,
  maxExposureNotional: 2_000,
})
const one = runBot(bot, candles, { initialCash: 10_000 })
```

参数不合规抛 `BotParamError`（带逐条原因），数据不可信抛 `BotStateError`（K 线乱序 / 缺字段 / 价格为非正等）。

## 4. 网格的几条口径（最容易踩）

- `gridCount` 是**格数**，边界线是 `gridCount + 1` 条。
- `gridMode` 取 `arithmetic`（等差）/ `geometric`（等比）；等比要求 `upperPrice > lowerPrice > 0`。
- `gridDirection` 取 `long` / `short` / `neutral`：`neutral` 在中线以下做多格、以上做空格。
- `boundaryAction` 取 `pause`（停止开新格）/ `stop_loss`（停机）/ `hold`（只记日志，继续跑已有格）。
- **同一格不在同一根 K 线内完成来回**：不用「这根 K 线的最低价买、最高价卖」这种乐观假设。

## 5. 马丁的硬顶

- `maxAdds`：最多加几次仓。到次数就停机。
- `maxTotalNotional`：累计名义额上限。到上限就停机。
- 这两个都写进参数校验（`SAFETY_KEYS.martingale`）；缺一个模板都构造不出来。

## 6. 参数与缺省

| 模板 | 参数（缺省） |
|---|---|
| `grid` | `lowerPrice` 90000、`upperPrice` 110000、`gridCount` 10、`gridMode` `arithmetic`、`gridDirection` `long`、`qtyPerGrid` 0.001、`boundaryAction` `pause`、`stopLossPct` 10、`maxExposureNotional` 10000 |
| `dca` | `frequency` `daily`、`notionalPerOrder` 100、`maxOrders` 30、`dipBuyEnabled` false、`dipThresholdPct` 3、`takeProfitPct` 20、`stopLossPct` 25、`maxExposureNotional` 3000 |
| `martingale` | `direction` `long`、`baseNotional` 100、`multiplier` 1.5、`addDropPct` 2、`maxAdds` 4、`maxTotalNotional` 1000、`takeProfitPct` 3、`stopLossPct` 15、`maxExposureNotional` 2000 |
| `trend` | `maPeriod` 50、`maType` `SMA`、`confirmBars` 2、`positionPct` 50、`direction` `both`、`trailingStopPct` 5、`stopLossPct` 8、`maxExposureNotional` 10000 |

每个参数都有 `min` / `max` / `options`，越界直接抛 `BotParamError` 并逐条列出原因。`maxAdds` 是**加仓次数**（不含首仓）。

## 7. 用之前要接受的三件事

1. **纸面回放不含滑点模型**：只按你给的 `feeRate` 与 K 线成交价算。要更真实，用 sim-book 的盘口级成交另跑一遍。
2. **参数是骨架，不是配方**：同一组参数换一段行情可能完全不同；要判断它是不是只在样本内好看，用参数寻优看 `pbo` / `dsr`。
3. **模板不会自己恢复**：触到上限或止损就停机，重启与是否继续由人决定。
