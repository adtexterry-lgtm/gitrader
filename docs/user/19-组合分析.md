# 组合分析：跨场所汇总、敞口、盈亏归因、集中度

组合分析包（`@gitrader/portfolio`）是一组**纯函数**：给它一组持仓、一份价格源、一张汇率表，它回答四个问题——**现在值多少、敞口压在哪、钱是谁赚的、集中度有多高**。

记账一律十进制字符串（内部 18 位定点，对外 8 位），全程不碰浮点。纯函数：同一输入永远同一输出，不读时钟、不读环境变量、不联网。

## 0. 在装好的产品里怎么用

组合分析（`@gitrader/portfolio`）接在 `research` 工具的 `portfolio` 动作上，只读：

- Agent：`{"action":"portfolio"}` 或 `{"action":"portfolio","accountId":"<账户 id>"}`。不给 `accountId` 取授权书里的第一个账户；不在授权书里的账户回错误，不回数据。
- 命令行：`gitrader research portfolio [--account <id>] [--json]`。
- 回 `{ accountId, ccy, valuation { total, positions[] }, exposure, concentration, missing }`：估值取账户快照的权益和每个持仓的标记价；拿不到标的元数据、标记价或汇率的持仓不参与汇总，原因列在 `missing` 里（绝不当 0）。

下面讲的是库本身的输入与输出。

## 1. 输入：协议类型 + 两样本包补的东西

```ts
import { analyzePortfolio, staticPriceSource } from '@gitrader/portfolio'

const analysis = analyzePortfolio({
  positions,                                   // 协议 Position[]
  instruments,                                 // 协议 Instrument[]（估值要乘数、结算币、资产类别）
  valuationCcy: 'USD',                         // 所有金额输出都用这个币
  prices: staticPriceSource({ 'binance:BTCUSDT': '64000.5' }),  // 价格源，由你注入
  fx: { 'USDT/USD': '1' },                     // 报价币 → 计价币；同币种不需要
  strategyTags: { 'acct_1|binance:BTCUSDT': 'grid-btc' },      // 策略归因标签
  onMissingPrice: 'throw',                     // 或 'skip'
})
```

- **价格源由调用方注入**：`{ price(instrumentId) => Decimal | undefined }`。返回 `0` 或负数按缺价处理。
- **缺价策略两档**：`throw`（缺省，报错里列全所有缺价标的）与 `skip`（跳过该笔并列入 `unpriced`，**绝不当 0**）。
- **策略不在协议持仓里**（策略是引擎侧概念），所以归因标签由你注入：键优先 `${accountId}|${instrumentId}`，其次 `${accountId}`，都没有记 `unassigned`。
- 汇率表键是 `FROM/TO`，反向对自动取倒数；**不做三角换算**。
- **数量单位看 `Instrument.venueSizeUnit`**：`'contract'` 时基础数量 = `size × contractSize`；`'base'` 时 `size` 就是基础数量，`contractSize` 只作展示（有的数据连接器把合约面值放在这里）。

## 2. 输出：四块

```ts
analysis.valuation      // 逐笔估值 + unpriced
analysis.exposure       // 敞口：总、按资产、按场所、按方向
analysis.attribution    // 盈亏：总、按策略、按场所、按标的
analysis.concentration  // 集中度：按资产 / 场所 / 标的 / 策略
```

**估值是唯一的错误出口**：`valuePositions()` 抛 `PortfolioError`，`code` 供分支，`details` 逐条列出所有问题（不吞第一条）。

| 错误码 | 什么时候 |
|---|---|
| `valuation_failed` | 逐笔问题一次列全后抛这一条；`details` 每条以子类前缀开头：`unknown_instrument:`（持仓引用了不在 `instruments` 里的标的）、`unsupported_settlement:`（非线性结算）、`invalid_position:`（`size` ≤ 0）、`duplicate_position:`（同一 (账户, 标的, 方向) 两条）、`missing_price:`、`missing_fx:` |
| `invalid_input` | `valuationCcy` 为空、汇率表里写了 0 或负值、`instruments` 里同一标的出现两次——直接抛，不聚合 |
| `missing_fx` | 单独调 `fxRate()` 缺汇率对时 |

## 3. 敞口：gross / net / long / short 四个口径

`totals`、`byAsset`、`byVenue`、`byInstrument` 的每个桶（`ExposureBucket`）都有 `key`、`gross`、`net`、`long`、`short`、`quantity`（带符号基础资产数量）、`positionCount`。

- `gross = long + short`（绝对值相加），`net = long − short`。
- `byAsset` / `byVenue` / `byInstrument` 是桶数组；`byDirection` 是单个对象 `{ long, short, net, gross }`，没有 `key` / `quantity` / `positionCount`。
- 看风险用 `gross` 与 `byDirection`；看方向性观点用 `net`。

## 4. 盈亏归因：已实现、未实现、资金费，还有一条对账线

每个桶（`PnlBucket`）给 `realized`、`unrealized`、`funding`、`total`，另有两个专门给对账用的字段：

| 字段 | 意思 |
|---|---|
| `venueUnrealized` | 场所上报的未实现盈亏（已折计价币），**不参与 `total`** |
| `drift` | `unrealized − venueUnrealized`：我们算的与场所说的差多少 |

`drift` 不是装饰：它持续不为零，说明你的估值口径（乘数、标记价、汇率）与场所有分歧，别急着归因给策略。

## 5. 集中度：HHI 与等效持仓数

四个维度各出一份报告：`byAsset` / `byVenue` / `byInstrument` / `byStrategy`。

| 字段 | 意思 |
|---|---|
| `hhi` | Σ wᵢ²，0..1；只有一笔时 = 1，越分散越趋近 0 |
| `effectiveN` | `1 / HHI`，即「等效持仓数」；空组合为 0 |
| `top1` / `top3` / `top5` | 前 1 / 3 / 5 名占比 |
| `largest` | 最大的那一桶（含 key 与各项金额） |
| `buckets` | 全部桶，按大小降序 |

## 6. 用在界面上

返回值就是一个账户总览视图需要的东西（工作台目前还没有接这个库，要用就自己接）：`analysis.valuation.positions` 直接进持仓表，`exposure.byVenue` 进场所分布，`attribution.byStrategy` 进策略盈亏排行，`concentration.byInstrument` 进集中度卡片。**金额都是计价币的十进制字符串**，前端不要自己再乘一遍。

## 7. 它不做什么

- 不算保证金、可用余额、强平价：那是账户与风控的事。
- 不做跨币种三角换算：缺一条直接汇率就报 `missing_fx`，不猜。
- 不读库、不缓存行情、不判断价格新鲜度：价格源注入什么就用什么。**喂旧价格会得到旧结论**，这一点由调用方负责。
