# 可观测性

Gitrader 自己不内置监控面板。它做两件事：**把状态变成 Prometheus 指标**，以及**把每个动作写进账本**。采集与展示由你的 Prometheus / Alertmanager / Grafana 负责。

## 1. 两个 HTTP 端点

| 端点 | 鉴权 | 返回 |
|---|---|---|
| `GET /api/metrics` | `Authorization: Bearer <令牌>` | Prometheus 文本格式（`text/plain; version=0.0.4`） |
| `GET /api/ready` | 同上 | `{"ready":true|false,"components":{kernel,ledger,tradingState,halted}}`；就绪 200，否则 503 |

要点：

- 服务只绑 `127.0.0.1`，所以采集器要么跑在本机，要么用 `host.docker.internal` 穿透。
- 令牌用 `~/.gitrader/service.json` 里的服务令牌（`svc_…`）。它是本机工具用的令牌，只能做只读与「PIN 在场」的动作，**不能当工作台会话用**。
- `/api/ready` 的语义：内核与账本都正常才算就绪；`HALTED` **不算**「不就绪」——停机是一种正常但危险的运行状态，靠告警发现，不要靠探针把容器重启掉（重启不解决锁存）。

## 2. 指标

| 指标 | 类型 | 标签 | 说明 |
|---|---|---|---|
| `gitrader_up` | gauge | — | 进程活着就是 1 |
| `gitrader_uptime_seconds` | gauge | — | 启动至今秒数 |
| `gitrader_process_rss_bytes` | gauge | — | 常驻内存 |
| `gitrader_process_heap_used_bytes` | gauge | — | V8 堆占用 |
| `gitrader_ledger_entries` | gauge | — | 账本条数 |
| `gitrader_trading_state` | gauge | `state` = `ACTIVE` / `REDUCING` / `HALTED` | 当前状态那一条为 1 |
| `gitrader_events_total` | counter | `topic` | 事件总线按主题累计（主题集合见 `packages/kernel/src/events.ts`） |

只读这几个，就够回答「活着吗、在交易吗、在被拦吗、账本在长吗」。

## 3. 抓取

仓库里 `ops/prometheus/prometheus.yml` 是一份可直接改的示例：

- `job_name: gitrader-kernel`，`metrics_path: /api/metrics`，`scrape_interval: 15s`，`scrape_timeout: 10s`；
- 令牌走 `authorization.credentials_file`：**文件里只写路径，不写令牌值**；
- 目标默认 `127.0.0.1:47900`（容器里抓宿主机改成 `host.docker.internal:47900`）；
- `rule_files` 指向 `alerts.yml`；`alerting` 指向 Alertmanager。

```text
# 手动确认端点（本机）
curl -s -H "Authorization: Bearer <令牌>" http://127.0.0.1:47900/api/metrics | head
```

令牌从 `~/.gitrader/service.json` 里取，别贴进任何进了版本库的文件。

## 4. 告警规则

`ops/prometheus/alerts.yml` 有 7 条规则，本批次未改动：

| 告警 | 条件 | 意思 |
|---|---|---|
| `GitraderDown` | `gitrader_up == 0` | 内核没了 |
| `GitraderHalted` | `gitrader_trading_state{state="HALTED"} == 1` | 停机锁存，需要人处理 |
| `GitraderRiskDenialsSpike` | 5 分钟内 `risk.denials` 增量 > 20 | 单被大量拦下：要么参数设错，要么行情异常 |
| `GitraderNoMarketData` | 10 分钟内 `market.candles` 增量为 0 且进程活着 | 行情断了 |
| `GitraderHighMemory` | `gitrader_process_rss_bytes > 1.5e9` | 内存超过 1.5 GB |
| `GitraderLedgerStalled` | 30 分钟账本增量为 0 但 30 分钟内有成交事件 | 账本没记上，属于严重问题 |
| `GitraderRestarted` | `gitrader_uptime_seconds < 120` | 刚重启过（可能反复崩） |

`ops/alertmanager/alertmanager.yml` 按 `severity` 分流，给出 telegram / email / webhook 三个**占位**接收器：里面的机器人令牌、SMTP 密码、Bearer 令牌一律只走 `*_file` 文件引用（`bot_token_file` / `auth_password_file` / `credentials_file`），**不要把真值写进去**。Alertmanager 不展开 `${ENV}`：想用环境变量，得在启动前用 `envsubst` 之类渲染成临时文件再挂进去。

## 5. 展示

- `ops/grafana/dashboards/gitrader-overview.json`：运行状态、运行时长、事件速率（按 topic，`rate(...[5m])`）、账本增长、交易状态（当前值 + 时间线）、内存（RSS 与 V8 heap）、被限流的调用（按身份）。
- `ops/grafana/provisioning/` 下有数据源（uid `prometheus`）与仪表盘自动装载的配置。
- 起栈的 compose 片段在 `ops/README.md`，是**示例**，不放进仓库根；端口只绑 `127.0.0.1`。

## 6. 自检

```text
node ops/verify-ops.mjs
```

离线跑：把 Grafana 仪表盘 `expr` 里的 `gitrader_*` 指标名、标签与 `packages/kernel/src/metrics.ts`、`packages/kernel/src/events.ts`、`packages/protocol/src/model/risk.ts` 双向对账，再检查 Prometheus / Alertmanager / provisioning 的 YAML 结构与有没有密钥字面量。告警规则文件 `alerts.yml` 只查存在性，规则里的表达式不参与对账——那部分由 `packages/kernel/test/alerts-config.test.ts` 守。不一致会列出并以 1 结束。这条适合放进 CI：改指标名忘了改面板，立刻红。

## 7. 日志与账本

- 内核日志走 stderr，行首带 `[gitrader]`；警告是 `[gitrader] warning: …`。`gitrader serve` 的终端别一直最小化。
- 真正的审计面是账本，不是日志：`gitrader ledger verify` 重算哈希链；`gitrader ledger export --out <目录>` 导出 JSONL + 清单 + 给人看的 `账单.csv` 与 Markdown 交易日志（可 `--redact` 去载荷）。
- 指标是「现在怎么样」，账本是「发生过什么」。排障时两个都要看。

## 8. 排错

| 现象 | 原因 | 处理 |
|---|---|---|
| 抓取 401 | 令牌不对 / 文件没挂进去 / 用了会话令牌 | 用 `service.json` 里的服务令牌；检查 `credentials_file` 权限 |
| 抓取连不上 | 内核只绑 127.0.0.1 | 采集器跑本机，或容器里用 `host.docker.internal` |
| 指标在但交易状态缺 `HALTED` 序列 | 该状态没出现过（只暴露当前状态） | 正常；状态时间线靠抓取历史 |
| `GitraderNoMarketData` 一直红 | 用 `--offline` 起的服务，或行情连接断了 | 看 `gitrader status` 的 `Venues` 一行 |
| `GitraderLedgerStalled` | 账本写入卡住（磁盘满、权限、数据库被占） | 立刻查 `ledger verify` 与磁盘 |
| 面板空 | 数据源 uid 不是 `prometheus`，或时间范围不含抓取点 | 对照 `ops/grafana/provisioning/` |
