# 测试网账户准备

这一篇只讲**测试网 / 模拟盘**：先把账户、钥匙、导入与旅程脚本跑通，再谈真钱（真钱的门槛见 [05-实盘与风控](05-实盘与风控.md)）。

仓库里能核实的内容（命令行分支在 `packages/cli/src/index.ts`、配置字段在 `packages/kernel/src/config.ts`、连接器行为在各包源码）写实。真正要上交易所网站做的事——页面名、注册步骤、测试资金领取、能否绑 IP、测试网账户是否由主账户派生——由交易所自己规定，以官方文档为准：Hyperliquid 看 <https://hyperliquid.gitbook.io/hyperliquid-docs>，Binance 看 <https://developers.binance.com/>。本篇不照搬交易所的页面步骤，也不编 URL。

## 共同前提

- 密钥只走两条路：终端隐藏输入（`gitrader keys import`）或启动 `gitrader serve` 时的**环境变量**。配置文件里只写 `env:变量名` 句柄，不写值；脚本也不读任何密钥文件。
- 测试网与主网用两套名字：测试网的变量名都带 `TESTNET` / `DEMO`，主网惯用名（如 `*_API_KEY`）不会被测试网脚本读取。
- 旅程脚本在仓库的 `tools/testnet/` 下，主机白名单、退出码、失败怎么读见 [tools/testnet/README.md](../../tools/testnet/README.md)。

## Hyperliquid

### 1. 测试网入口

- 连接器里的测试网基址是 `https://api.hyperliquid-testnet.xyz`（`packages/connector-hyperliquid/src/rest.ts` 的 `HL_ENDPOINTS.testnet.http`）；主网是另一个主机 `api.hyperliquid.xyz`。
- `tools/testnet/venues-testnet.json` 只登记测试网这个主机，`journey-hyperliquid.mjs` 也只接受它；`--base-url` 指到别的主机会在发请求之前被拒。
- 测试网的网页入口、注册与建账户在 Hyperliquid 自己的网站上，以官方文档为准：<https://hyperliquid.gitbook.io/hyperliquid-docs>。

### 2. 建账户要什么

- 一个主账户（记下**主账户公开地址**，`0x` 开头 20 字节），加一只 **API 钱包**（一把 secp256k1 私钥）。
- 主账户只用来授权。下单由 API 钱包签：连接器永远拿不到私钥，签名走内核注入的 `signTypedData` 句柄（`packages/connector-hyperliquid/README.md` 的「交易」节）。
- 余额 / 持仓 / 成交按**主账户地址**查，所以配置里要写主账户公开地址（见第 5 步的 `accounts[].owner.address`）。
- 测试网账户怎么建、是否必须由主账户派生，由 Hyperliquid 规定，以官方文档为准：<https://hyperliquid.gitbook.io/hyperliquid-docs>。

### 3. 测试资金怎么领

测试资金在 Hyperliquid 的测试网网站上领取。Gitrader 没有领取测试资金的实现，步骤以官方文档为准：<https://hyperliquid.gitbook.io/hyperliquid-docs>。

### 4. API 钱包怎么建（权限只开读取 + 交易，不开提现）

两种做法，都在本机、都不让私钥进命令行参数：

| 做法 | 命令 | 说明 |
|---|---|---|
| 本机生成 | `gitrader keys new wallet hl-testnet --network testnet --days 180` | 私钥不出钥匙库，只打印地址；之后在主钱包里对这个地址做一次 `approveAgent` 授权 |
| 导入已有 | `gitrader keys import hl-testnet --network testnet` | 私钥在终端隐藏输入，不进 argv、不进 shell 历史 |

- 建完用 `gitrader keys list` 看地址、状态与到期日。
- API 钱包的授权窗口最长 180 天（`packages/connector-hyperliquid/src/approvals.ts` 的 `AGENT_MAX_VALID_MS`，钥匙库同一上限 `WALLET_MAX_VALIDITY_DAYS`），到期前轮换。
- 授权只给「读取 + 交易」，**不给提现**：API 钱包本身无提现权限，授权时也不要另行授予。主钱包里 `approveAgent` 的具体操作由 Hyperliquid 文档说明：<https://hyperliquid.gitbook.io/hyperliquid-docs>。
- 「支持开发者」的 builder 费默认关闭（`supportDeveloper` 默认 false），测试网这一步可以跳过。

### 5. 导入 Gitrader（配置里怎么写）

`gitrader.json` 里两处要改：场所切到测试网，账户写成实盘模式的**测试网**账户（`mode: "live"` 表示「连场所」，不是「碰真钱」；网络由 `environment` 决定）。

```json
{
  "venues": [{ "id": "hyperliquid", "environment": "testnet", "enabled": true }],
  "accounts": [
    { "alias": "hl-testnet", "venue": "hyperliquid", "environment": "testnet", "mode": "live",
      "signerRef": "hl-testnet",
      "owner": { "address": "0x0000000000000000000000000000000000000000" } }
  ]
}
```

- `accounts[].signerRef` 填钥匙库里那只 API 钱包的**名字**（不是私钥）。
- `accounts[].owner.address` 填主账户公开地址（公开信息，不是密钥）。
- 改完启动 `gitrader serve`，用 `gitrader status` 看场所连接与账户是否就绪。

### 6. 跑旅程脚本

```text
export HL_TESTNET_MAIN_ADDRESS=0x主账户公开地址
export HL_TESTNET_API_WALLET_KEY=0xAPI钱包私钥
node tools/testnet/journey-hyperliquid.mjs --json
```

- 只有这两个变量进得去；其余参数 `--instrument`（缺省 `hyperliquid:BTC`）、`--account`、`--size`（缺省 `0.001`）、`--json`、`--help`。
- `--size` 的缺省值是相对 Hyperliquid 的最小名义额 `10` USDC 取的（连接器把该下限写进 `instrument.minNotional`，数量按标的步长截断）；旅程在名义额不足时会按 2 倍递增抬到够。
- 退出码：`0` 全部步骤通过、`1` 任一步失败（打印脱敏后的 Problem）、`2` 用法 / 基址不合规、`3` 缺环境变量（不发任何请求）。
- 旅程只走 REST（不开 WebSocket）；账户快照由后台 REST 刷新，脚本只读不写。
- 限价 / 触发价按 Hyperliquid 的价格规则（≤5 位有效数字、小数位 ≤ 6 − `szDecimals`）由参考价贴出来；连接器的 instrument 没有 tick 字段，脚本自己按这条规则算步长。
- 真跑前先确认账户在该标的上**没有持仓、没有挂单**：旅程的前置检查会拒掉带持仓的账户。

## Binance

### 1. 测试网入口

- 本仓 Binance 连接器的测试网基址是 `https://demo-fapi.binance.com`（USDⓈ-M 永续测试网），主网是 `fapi.binance.com`；`tools/testnet/venues-testnet.json` 只登记测试网主机。
- 官方测试网站点与文档由 Binance 提供，以官方文档为准：<https://developers.binance.com/>；测试网站点：<https://testnet.binancefuture.com>。

### 2. 建账户要什么

- 一个**测试网**账户，加一对 API key / secret（测试网的 key 与主网不通用）。
- 测试网注册步骤由 Binance 规定，以官方文档为准：<https://developers.binance.com/>。

### 3. 测试资金怎么领

测试资金在 Binance 的测试网站点上领取。Gitrader 没有领取实现，步骤以官方文档为准：<https://developers.binance.com/>。

### 4. API 钥匙怎么建（权限只开读取 + 交易，不开提现）

- 在测试网的 API 管理页新建 key；权限只勾「读取」与「合约交易」，**不要勾提现**；能绑 IP 就绑上。
- 能否绑定 IP、有没有其它限制，由 Binance 规定，以官方文档为准：<https://developers.binance.com/>。
- 生成的 secret 只显示一次，复制进环境变量（下一步），不要写进配置文件。

### 5. 导入 Gitrader（`keys import` 存不了 key/secret）

`gitrader keys import` **目前不能**存 Binance 的 key/secret 对：它只收一把 32 字节十六进制私钥、按 secp256k1 派生地址后存进钥匙库（存的是 API 钱包，见 `packages/cli/src/index.ts` 的 `keys import` 分支与 `packages/kernel/src/keystore.ts`）。Binance 的凭据用配置里的 `env:` 句柄：

```json
{
  "accounts": [
    { "alias": "bn-testnet", "venue": "binance", "environment": "testnet", "mode": "live",
      "credentials": {
        "apiKey": "env:BINANCE_TESTNET_API_KEY",
        "apiSecret": "env:BINANCE_TESTNET_API_SECRET" } }
  ]
}
```

- 句柄里的值放在**启动 `gitrader serve` 的那个环境**里；内核只认 `env:` 形式，解析不到就把该场所退回只读行情（启动日志会打印一条 warning）。
- 配置里只有变量名，没有密钥本身；`accounts[].credentials` 的键名与连接器要的字段一致（`apiKey` / `apiSecret`）。

### 6. 跑旅程脚本

```text
export BINANCE_TESTNET_API_KEY=测试网APIkey
export BINANCE_TESTNET_API_SECRET=测试网secret
node tools/testnet/journey-binance.mjs --json
```

- 只有这两个变量进得去；参数与退出码口径同 Hyperliquid 一节（缺省标的 `binance:BTCUSDT`，缺省 `--size 0.002`）。
- 只打 `demo-fapi.binance.com`；`--base-url` 指到 `fapi.binance.com` 会在发请求之前退出 `2`。
