# 指标库：ta-plus 清单与 engine-core 差异

engine-core 自带一套指标（`packages/engine-core/src/strategy/ta/`），ta-plus（`@gitrader/ta-plus`）补上它没有的那些：基本面比率、风险与波动、动量偏离、窗口极值、TA-Lib 的若干经典函数。两个包**并存**，ta-plus 不并入 engine-core。

这一页回答三件事：有哪些、和 engine-core 重名的那些差在哪、什么情况下会算错。

## 0. 在装好的产品里怎么用

ta-plus 是函数库（`@gitrader/ta-plus`），**没有单独的命令或工具动作**；装好的 `gitrader` 里能直接碰到指标的地方是研究工具：

- Agent：MCP 工具 `research` 的 `factor_report` 动作；命令行：`gitrader research factors --instrument hyperliquid:BTC --interval 1h --from <毫秒|ISO> --to <毫秒|ISO> --json`（或 `--data <csv>` 用本地 K 线文件）。它评估 157 个滚动因子的 IC / IR / 分位组收益，t 值用 Newey-West（HAC）口径，口径写在摘要的 `tMethod` / `tLags` 里。因子库是随包的那一份，不是 ta-plus。
- 要在自己的策略里用本页的指标：策略文件必须自包含（不许 `import`），把需要的函数体从 ta-plus 源码拷进策略文件。npm 安装包不带 ta-plus 源码，去仓库的 `packages/ta-plus/src/` 取。

## 1. 约定（两包一致）

- 输出**与输入等长**；还不能算的位置是 `null`，不是 `0` 也不是 `NaN`。
- **因果**：第 i 项只用 ≤ i 的数据。截断尾部不改变历史值。
- 周期参数必须是 ≥ 1 的整数；`period ≤ ddof`、基本面比率分母为 0、上期营收 ≤ 0 这类无定义情形抛 `RangeError`，不返回 `Infinity`；滚动窗口内方差为 0（如 `correl` / `beta`）时该位置为 `null`。
- **非法周期一律抛错**（0 / 负数 / 小数 / `NaN` / `Infinity` 五类都算），包括下面那 5 个转发 engine-core 的指标：engine-core 遇非法周期静默返回全 `null`，本包的包装函数先校验、抛错。回归类另要求 `period ≥ 2`：`linRegSlope` / `linRegIntercept` / `linRegAngle` / `tsf` 与 `correl` / `beta` 一样，传 `period = 1`（或 0）抛 `RangeError`，`period = 2` 起正常计算（见第 6 节第 1 条）。
- **非有限值输入没有统一处理**：`NaN` / `±Infinity` 只是部分函数会抛错，其余会把 `NaN` 带进结果，还有几个会把 `NaN` 当「无变动」静默吃掉。喂数据前自己清洗，别指望库挡（逐函数结果见第 6 节）。
- 不修改输入数组 / K 线对象。
- 双精度浮点（不引入十进制）；**比率类返回分数，不返回百分数**——例外是 `atrPercent`（比率）、`pricePosition`（0..100）、`natr`（百分数）。

## 3. 与 engine-core 的差异表

**语义重复的 9 处**，分两类：

| ta-plus | engine-core 对应 | 关系 |
|---|---|---|
| `plusDI`、`minusDI` | `adx()` 内部的 +DI / −DI（未单独导出） | 同口径同值：**直接转发** engine-core 的实现（Wilder(1978)，种子 = 第 1..period 根 DM / TR 之和，首值在下标 period），本包不再维护第二套 |
| `aroonOsc` | `aroon()` 的 `osc` 字段 | 同口径同值：**直接转发** |
| `linRegSlope`、`linRegIntercept` | `linearRegression()` | 同口径同值：**直接转发**（横轴为窗口内序号） |
| `adOsc` | `chaikinOscillator()` | **口径不同**：见下 |
| `stochF` | `stochastic()` | **口径不同**：见下 |
| `correl` | `rollingCorr()` | **口径不同**：见下 |
| `variance` | `rollingStd()` | **口径不同**：见下 |

转发的做法是**相对路径只读引用** engine-core 的源码（engine-core 的 `package.json` 只导出 `.`，根入口没有 re-export `ta/`），同值性由 `test/engine-core-parity.test.ts` 逐项断言；`dx` / `linRegAngle` / `tsf` 由转发结果合成。

四条口径不同，逐条说清：

1. **`adOsc` 与 `chaikinOscillator`**：公式同为 `EMA(A/D, fast) − EMA(A/D, slow)`，差别在 EMA 的种子与预热期。`adOsc` 按 TA-Lib `ta_ADOSC.c`：两条 EMA 都以第一个 A/D 值为种子，首个非 null 位置是 `max(fast, slow) − 1`。`chaikinOscillator` 用 engine-core 自己的 `emaSeries` 种子与预热期。参数形状也不同（前者是位置参数，`fastPeriod` 缺省 3、`slowPeriod` 缺省 10；后者收 `{ fast, slow }` 选项对象）。两条序列在预热段数值不同，稳态收敛。
2. **`stochF` 与 `stochastic`**：`stochF` 是快速随机指标，`K` 不做事后平滑（`dPeriod` 只平滑 `D`），缺省 `kPeriod = 5`；`stochastic` 缺省 `kPeriod = 14`。**区间为 0 时两者取值不同**：`stochF` 给 `K = 0`，`stochastic` 给 `K = 50`。横盘行情下这条差异会直接改变信号。
3. **`correl` 与 `rollingCorr`**：窗口 Pearson 的数值口径相同（分母为 0 → `null`），差别在输入形状与空洞处理：`correl` 只收 `number[]`、`period` 缺省 20；`rollingCorr` 收 `(number | null)[]`，**窗口里出现 null 就整段给 null**，`period` 必填。
4. **`variance` 与 `rollingStd`**：同一个窗口平方和，`variance` 给方差（TA-Lib `TA_VAR`，`ddof` 缺省 0），`rollingStd` 给标准差。两者都允许 `ddof` 调整（`ddof = 1` 即 pandas `.var()` / `.std()` 的样本口径）。

## 4. 与 TA-Lib 的已知差异（用 TA-Lib 对数时会踩）

| 指标 | 差异 |
|---|---|
| `cmo` | 用 TA-Lib 口径（Wilder 平滑），与 QD 原始 Chande 定义不同。输入 `[10,11,10,12,12,13]`、period 3：QD 口径给 50 / 33.33 / 100，本包给 50 / 50 / 68 |
| `plusDM` / `minusDM` / `plusDI` / `minusDI` | Wilder 种子取第 1..period 根之和，首值在下标 period；TA-Lib 的种子是前 period−1 根之和再平滑一步（首值在下标 period−1），预热段数值不同 |
| `natr` | ATR 用第 0 根 TR = h−l、首值在下标 period−1；TA-Lib 的 TR 从第 1 根算、首值在下标 period |
| `beta` | 不做收益率转换。TA-Lib 的 `BETA` 内部先把两条价格转成单根收益率；要常规意义的 beta，先用 `simpleReturns` 转收益率再传入 |
| `correl` | 分母为 0 时 TA-Lib 输出 0.0，本包输出 `null`（宁可缺值，不给假的 0） |
| `skewness` / `kurtosis` | 缺省样本口径（pandas `.skew()` / `.kurt()`、Excel SKEW / KURT 的校正公式，需 n ≥ 3 / n ≥ 4）；`{ sample: false }` 切总体矩 |
| `volumeRatio` | 基线**不含当根**：`volume[i] / mean(volume[i−period .. i−1])`。含当根的口径会系统性压低比值 |

## 5. 数字从哪来（别自己循环自证）

参照值**不来自本包实现**，也不来自任何移植代码的输出：

- **TA-Lib**（BSD，只读下载、未入库）的 C 源码，用来核对公式定义（CMO 的平滑、BOP、AVGDEV 的除数、VAR 的总体方差、ADXR 的延迟项）。
- **QuantDinger**（Apache-2.0）的因子注册表与行情技术指标模块，只借鉴口径与字段语义。
- **手算小例**：每个指标至少一条用可整除的小整数构造、把分数推导写在注释里的用例（如 CMO `[10,11,10,12,12,13]` → 68）。

自己验数时照这个来做：**参照值要在你的代码之外**。拿自己算的数核对自己，只会得到「一致」。

## 6. 输入约定：非有限值、溢出与周期表

这一节只回答「喂进去的东西不对时会发生什么」。数字不是抄来的：拿固定序列逐个函数跑一遍，看返回值里出现了什么（`NaN`、`Infinity`、`null`、还是抛错）。**现状是三种做法并存**，调用前自己清洗输入。

### 6.1 输入含 `NaN` / `Infinity`（非有限值）

1. **抛 `RangeError`**：`packages/ta-plus/src/risk.ts` 里的 5 个函数先逐项校验，报错原文形如 `realizedVolatility: 第 5 项不是有限数`——`realizedVolatility`、`downsideVolatility`、`skewness`、`kurtosis`、`maxDrawdown`。这是最省心的一类：错就是错。
2. **把 `NaN` 透传进输出**：其余 30 个吃周期的导出（见 6.3 表格最后一列「透传 `NaN`」）。输出里出现的是 `NaN`，**不是** `null`——`null` 的含义是「还不能算」，`NaN` 的含义是「算出来是脏的」，两者别混。
3. **静默吞掉**（最危险的一类：既不报错，输出里也看不到 `NaN`）：`cmo`、`maxIndex`、`minIndex`、`plusDM`、`minusDM`、`aroonOsc`。这些实现里用的是「比较为假」的分支（`if (x > 0)` 之类），`NaN` 的比较恒为假，于是脏数据被当成「这一根没有变动」。用法上要自己先筛。

不带周期参数的那些不做校验：`avgPrice` / `medPrice` / `typPrice` / `wclPrice` / `bop` / `simpleReturns` 遇到 K 线里的 `NaN` 原样带进结果（`avgPrice([{ c: NaN … }])[0]` 就是 `NaN`）；基本面比率是标量入口，分母为 0 或非有限数抛 `RangeError`。

数据源给的空洞（停牌、缺 bar、除权断层）请先用 `dropna` 或补值消掉，别让 `NaN` 进到 `cmo` / `maxIndex` 这类会吞掉它的函数里。

### 6.2 溢出（1e300 量级）

窗口方差类实现用平方和：输入量级到 1e299 时 `d²` 已经在 1e598，超出双精度上界，直接变 `Infinity`。

- engine-core 的 `rollingStd` 给 `Infinity`；`bollinger` 建在它上面，`upper` / `lower` / `bandwidth` 全是 `Infinity`，`percentB` 是 `NaN`（`upper - lower` 成了 `Infinity - Infinity`）。**这不是给 `null`，是给 `Infinity`**，画图 / 比较时会直接串到下游。
- ta-plus 里同口径的三个自己也溢出成 `Infinity`：`variance`、`realizedVolatility`、`downsideVolatility`。
- `kurtosis`：先按整列最大绝对值缩放再算（峰度与尺度、平移无关），1e299 / 1e300 量级下与小量级给出同一个值，不会溢出，也不再给常数。
- `amihudIlliquidity`：成交额（收盘价 × 成交量）或比值超出双精度范围时，该窗口给 `null`（不可表示），不再给 `0`。
- 其余函数在这个量级下仍是有限数（线性运算、比值、取极值）。

现实里撞上这个量级，通常是「指数化点位 / 极小单位的币价」被当成原始价直接喂进来。先缩放再算（除以一批数据的均值，或先用 `simpleReturns` 转成收益率）；别指望这些函数自己保住精度。

读表三条要点：

1. **`correl` / `beta` 与 `linRegSlope` 口径一致**：`period = 1`（窗口只有一个点，离差平方和为 0）都抛 `RangeError`，回归至少要两个点；改动前 `correl` / `beta` 在这里静默返回全 `null`，现在不会了。`period = 2` 起正常计算，前 `period − 1` 项为 `null`。
2. **最小周期 2 来自 `ddof`**：`zScore`（`ddof` 缺省 1）与 `realizedVolatility`（`ddof` 缺省 1）要求 `period > ddof`，所以最小 2；显式传 `ddof: 0` 时 `period = 1` 可用。`skewness` 要 n ≥ 3、`kurtosis` 要 n ≥ 4，所以 `period < 3` / `< 4` 给全 `null` 而不是抛错。
3. **`period = 1` 的「有效数值」多是退化值**：`variance` / `avgDev` 恒为 0，`cmo` 恒为 100 或 0。能跑通不等于有意义。
