# 常见问题

按「你现在卡在哪」分组。每条都给出能跑的下一步，而不是一句「请检查配置」。

## 安装与启动

**Q：`gitrader` 命令不存在。**
A：需要 Node >= 22.13（`node --version`）。包还没发到 npm 时，`npx gitrader …` 用不了，按根 `README.md` 的办法从 `npm pack -w packages/cli` 出来的 tarball 装，或在仓库里用打包后的 `dist/bin.js`。

**Q：启动报端口被占用。**
A：默认从 47900 起自动找空闲端口，并避开一批常见端口。要定死就 `gitrader serve --port 48080`；也可以改 `server.port`（`null` = 自动）。`--port` 优先级更高。

**Q：`a Gitrader service is already running for <home>`。**
A：同一个主目录只允许一个实例。先停掉在跑的那个（在它的终端按 Ctrl+C），或者用 `--home` 指到另一个主目录做隔离实验。

**Q：`status` 说服务没在运行。**
A：服务没起，或 `service.json` 里的 pid 已经不在了。按它给出的下一步 `gitrader serve --detach` 起来再试。这种情况退出码是 0（状态查到了）；脚本里要判断是否在跑，读 `--json` 的 `running` 字段。

**Q：行情一直连不上，但我想先调策略。**
A：`gitrader serve --offline`（等价 `GITRADER_OFFLINE=1`）。此时不连任何行情，账户、账本、插件、策略文件照常可用，纸面撮合没有价格输入，不会成交。

**Q：配置文件改错，服务起不来了。**
A：报错会逐个列出问题字段与原因（不做静默修正）。按提示改回；实在不行把 `~/.gitrader/gitrader.json` 里那一项删掉，重新 `gitrader init` 只会补缺失项、不会覆盖已有内容。

**Q：怎么升级（比如从 0.1.0 到 0.1.1）？**
A：数据不用动，新版直接沿用 `~/.gitrader`（或 `GITRADER_HOME` 指向的目录）。步骤：
1. 先 `gitrader stop` 停掉在跑的服务（旧服务不停，它还是旧版本在跑）；
2. 用你当初的方式装新版：npm 安装就 `npm install -g <新版 tgz>` 覆盖；便携包就把新压缩包解压到**另一个**目录，用新目录里的 `start.cmd`（macOS / Linux 是 `./start.sh`）启动，确认没问题再删旧目录；
3. 重新 `gitrader serve`，然后 `gitrader --version` 和 `gitrader status` 里的版本应当一致；
4. 想确认账本没出问题：`gitrader ledger verify`。
浏览器里已登录的会话在服务重启后会失效，用 `gitrader open` 取新链接（便携包里用 `bin\gitrader.cmd open`）。

**Q：怎么卸载？**
A：先 `gitrader stop`。然后按安装方式删程序：npm 安装用 `npm uninstall -g gitrader`；便携包直接删掉解压出来的那个目录。这一步不会碰你的数据。
数据在 `~/.gitrader`（或 `GITRADER_HOME` 指向的目录）：钥匙库、配置、账本都在里面。想一起清掉，就删这个目录；删了找不回来，要留底的话先整体复制一份。Agent 接入时写过的 `.mcp.json`、`~/.codex/config.toml` 等宿主配置里的 `gitrader` 条目，以及你放令牌文件的位置，需要你自己到宿主那边删。

## 工作台

**Q：链接打开说失效。**
A：启动链接里的 `launch` 令牌**一次性、120 秒有效**，刷新页面也会失效。在 `serve` 的终端按回车拿新链接，或 `gitrader open --print`（要 PIN）。

**Q：`gitrader open` 提示没设 PIN。**
A：先在终端里跑一次 `gitrader init` 设 PIN（非交互环境不会问）。没 PIN 就签不出链接，`serve` 打印的那条照旧可用。

**Q：能把工作台嵌进我自己的系统吗？**
A：可以，但默认禁止。`gitrader config set embed.allowedOrigins https://app.example`，然后**重启服务**。只接受 `scheme://host[:port]`，不许通配符与路径；`none` 清空。放宽的只是页面嵌入，`/api` 与 WebSocket 仍然要令牌。

## PIN 与钥匙

**Q：PIN 忘了。**
A：没有找回通道——主密钥由 PIN 派生，推导不回去。在本机终端里运行 `gitrader pin reset`（非交互 / 管道喂 PIN 一律拒绝，先停掉正在跑的 `gitrader serve`）：它把 `keys/pin.json` 与 `keys/keystore.json` 移到 `keys.bak-<本地时间>` 备份目录，然后让你设新 PIN。代价是**已加密的 API 钱包私钥随之停用，得用你自己另存的私钥重新 `gitrader keys import`**；全部 AI 钥匙会被吊销（之后用 `gitrader keys new agent …` 重建）。**账本、历史记录与签名身份保留**，不删除任何文件。

**Q：怎么让一个 Agent 马上失去权限？**
A：撤销它的 Agent 钥匙，要输 PIN：工作台「设置 → 钥匙 → Agent 钥匙」里点那一行的「撤销」（Agent 卡的档位菜单里也有「撤销此 Agent…」），或在自己的终端运行 `gitrader keys revoke agent <名字>`。撤销后它立刻不能下单、待批作废；**已有持仓和挂单不会自动处理**，要你另行处理。不要让 Agent 替你写脚本去撤权。

**Q：`keys list` 里某只钱包标了 `ROTATE SOON`。**
A：到期前 `keys.walletExpiryWarnDays`（默认 14 天）开始提醒。`gitrader keys new wallet <新名字> --days 180` 生成新的，去主钱包 `approveAgent` 授权新地址，再把 `accounts[].signerRef` 指过去，最后 `gitrader keys revoke wallet <旧名字>`。

**Q：导入私钥失败。**
A：`gitrader keys import <名字> --network mainnet` 读的是终端隐藏输入，粘贴进去的应当是十六进制私钥本体（不要带 `0x` 以外的修饰、不要带引号）。命令行参数里传私钥永远不会被接受——这是设计。

## 策略

**Q：策略文件放进去了，`engines list` 里看不到新策略。**
A：三件事：① 目录对不对（`~/.gitrader/engines/<engine-id>/strategies/`，内置引擎是 `gitrader-core`）；② `id` 是否合法且文件夹内唯一（小写字母、数字、短横线，2–40 字符）；③ 有没有校验错误——存盘后约一秒会出加载报告，错误里有行号与原因。

**Q：启动策略报 `unknown parameter`。**
A：参数必须在文件 `params` 里声明过（或用 `@param` 注释声明）。没声明就传，会被拒；类型不对、超范围同样被拒——**不会**替你夹到边界。

**Q：`engines list` 里 `bound:no`。**
A：引擎还没绑到账户。`gitrader engines bind gitrader-core`（要 PIN，默认绑纸面账户），且服务要在跑。

**Q：策略跑起来但没动静。**
A：先看 `warmup`——预热期 `target` 一直是 0 是正常的。再看 `reasons` 有没有变化；如果 `target` 一直在变却被闸门拦了，去 `gitrader risk stats` 看拦截计数。

**Q：重启后策略没了？**
A：纸面账户的实例会在引擎重新连上、且它用到的标的都已就绪后自动恢复（带原来的参数）；标的目录还在加载时会自己等并重试（最多约 10 分钟，超时会列进 `needsRestart`，原因写 `restore timed out`），这段等待不算「恢复失败」。实盘账户的、或交易状态受限（`REDUCING` / `HALTED`）时的实例**不会**自动恢复——它们会列在 `gitrader status` 的提醒（warnings）和 `engines` 的 `needsRestart` 里，写明原因。你确认后重新启动它，或者停掉它即可；重新启动时给 `start_strategy` 带上原来的 `instanceId`，就沿用同一个 id 并清掉这条提醒（正在跑的、不存在的 id 会被拒绝，什么也不启动）。系统不会替你自动接管实盘，也不会因此下单、撤单。

**Q：重启后实盘账户为什么一时开不了仓？**
A：实盘开仓要等该场所的「启动对账」完成：内核重启后先把本地未结订单、成交和场所对一遍，对完才放行开仓（`gitrader status` 的场所就绪度里 `startupReconciled` 为真）。对账没完成、失败或结果不明时，开仓会被拒绝（`TRADING_STATE`，原因 `startup reconcile pending`），减仓、平仓、撤单不受影响；失败的对账会自动隔一阵重试。纸面账户不受这条影响。

**Q：引擎卡住了怎么办？**
A：引擎进程在、但心跳停了：`engines status` 里它会改报 `degraded`（`heartbeat lost`），绑定账户先被收紧到 `REDUCING`；连续两个超时周期仍没有心跳，内核会结束这个本地引擎进程并按退避重启。重启后账户仍是 `REDUCING`，要你确认后用 `reconcile resume` 恢复交易，纸面实例也会因此列进 `needsRestart` 等你重新启动。

## 回测与研究

**Q：回测结果一笔成交都没有。**
A：常见三种：数据区间太短（不够预热）、`target` 恒为 0（逻辑没生效）、价格序列是常数。另外看 `biasChecks` 与新加的参数是否让信号永远触发不了。

**Q：walk-forward 一折都没有。**
A：窗口放不下：需要 `trainBars + embargoBars + testBars <= n - blindHoldoutBars`。数据根数不够时先把 `testBars` 或 `blindHoldoutBars` 调小，或换更长的数据。

**Q：`data.files[].sha256` 对不上。**
A：内核会拒跑。重新算文件的 sha256 再填；不要为了让回测跑起来把哈希改成别的——那等于放弃「这份结果对应哪份数据」的可核对性。

**Q：`trialCount` 很大说明什么？**
A：说明这条策略在这次研究里被试了很多组参数。只报最好那一组、不报试了多少次，是研究里最常见的自欺方式。把 `trialCount` 与实验记录一起交出去。

**Q：`lab verify` 返回不一致。**
A：说明这份包从导出后被动过，或者不是同一份实验。别发出去，重新 `lab export` 一次。

## 插件与通知

**Q：`plugins check` 报 `REJECTED`。**
A：看每行 `码 路径 说明`。最常见的三个：权限名不在枚举里、申请了永远不可授予的权限（如 `withdraw`）、`HASH_MISMATCH`（改了文件没重钉，跑 `gitrader plugins pin <目录>`）。

**Q：`plugins grant` 说服务在跑。**
A：这是故意的：授权入口要本地 PIN，且不希望两个写入者同时改权限。在 `serve` 的终端按 Ctrl+C，再跑 `gitrader plugins grant <id> [权限…]`，完了重新 `serve`。

**Q：通知测试返回 `missing secret handle: <NAME>`。**
A：自动转发与声明密钥注入已接线。按 [通知出口](../notifications.md) 为 `<NAME>` 配置 `plugins.secrets` 的环境句柄，并在启动内核的进程环境中设置对应值，再启动插件、运行 `gitrader notify test <channelId>`。结果与出口日志只报告名字；`notify_send` 仅由通知出口和人面测试调用，通用 `plugins call` 与 Agent 调用被拒。

**Q：通知里为什么没有提案理由、接管理由或备注？**
A：这是设计，不是 bug。通知正文由内核模板按字段白名单拼出来，只带结构化事实（账户、标的、规则、数值、状态），自由文本一律不转发，不符合事实词形的字符串写成 `[text omitted]`。要留档去账本查（`gitrader ledger export`），也别指望通道插件把正文「补」回来。

**Q：同一笔接管收到好几条通知，或者一条都没收到？**
A：收到了多条：通知 key 按 takeoverId 归并，阶段更新共用一条 key，同一通道在去重窗口内只发一次；把 `notify.rateLimit.dedupeWindowSec` 设成 0 就等于关掉去重（失败与告警另算一条 critical，属正常）。一条都没收到：先看 `notify.channels` 是否为空、通道 `minLevel` 是否高于事件级别、规则是否把该主题指到了别的通道；先用 `gitrader notify test <通道ID>` 确认通道本身通。

**Q：通道密钥可以很短吗？比如 6 位的口令。**
A：不行。短于 8 个字符的密钥值不参与插件返回帧的回显比对，启动时只有一条 `short secret excluded from frame scan` 告警——等于内核看不见它被泄露。密钥用 ≥8 字符的随机串，每个通道各用各的。

**Q：在 `notify.channels[].params` 里写 `secret` 或 `password`，配置直接被拒？**
A：`params` 只放非密钥参数。键名命中 `privateKey` / `secret` / `apiSecret` / `mnemonic` / `seed` / `passphrase` / `pin` / `password`（不分大小写、忽略 `_` 与 `-`）就校验失败，提示你改用 `plugins.secrets`：配置里只写 `env:<变量名>` 句柄，值放启动内核的进程环境。

**Q：Windows 上 `plugins call` 传 JSON 总失败。**
A：`.cmd` 垫片会吃掉内层双引号。把入参写进 `args.json`，用 `@args.json`。

**Q：装了插件但 Agent 看不到工具。**
A：四个条件缺一不可：校验通过、已启用（`plugins grant`）、工具写在清单 `tools[]` 里、工具声明的权限都已授予。缺哪条会返回对应的码（`PLUGIN_TOOL_UNKNOWN` / `MANDATE_LIMIT` / `INVALID_PARAMS`）。

## 交易状态

**Q：怎么从 `HALTED` 恢复？**
A：只有你本人输 PIN 才能恢复。如果是因为主目录里存在 `HALT` 文件触发的，先删文件再恢复（文件还在会被拒）。别指望重启服务解决——锁存是设计。

**Q：状态是 `REDUCING`。**
A：只能减仓、撤单。原因通常是保护器触发、Agent 心跳超时、或你按了接管。`gitrader status` 的括号里会写原因。

**Q：单被拦了，但不知道是哪条规则。**
A：`gitrader risk stats` 看被拦统计；拿到 `precheckId` 后 `gitrader risk replay <precheckId>` 逐字段回放判定，差异会列出规则码。

**Q：`ledger verify` 报 `LEDGER BROKEN at seq N`。**
A：链在那个位置断了。不要继续写入：先导出留证（`gitrader ledger export --out <目录>`），再查该条目前后的系统状态（磁盘、时钟、是否有第二个进程在写同一个数据库）。

**Q：纸面账户被我跑乱了，怎么重置？**
A：`gitrader paper reset --account paper`（要 PIN，服务要在跑）。它会明确重置那个纸面账户，实盘账户不受影响。

## 其它

**Q：`gitrader bench` 为什么只打印一行？**
A：它是 M1 的占位。性能数字由发布流程写进 `docs/perf-baseline.md`，不是本地测出来的。

**Q：日志在哪？**
A：内核日志走 stderr，行首 `[gitrader]`。审计数据在账本（`~/.gitrader/data/gitrader.sqlite`），用 `gitrader ledger verify` 与 `ledger export` 访问，不建议直接开库改。

**Q：这些文档和代码不一致怎么办？**
A：以代码为准（`packages/cli/src/index.ts` 与 `packages/kernel/src/config.ts`），并跑一次 `node docs/user/verify-docs.mjs` 看是哪一类漂移：命令名、配置键、还是禁词。
