# 参数寻优：先看证据等级

参数寻优最容易做的事，是从一段历史上挑出最好看的一组参数，然后把它当成未来的证据。寻优包（`@gitrader/optimizer`）不给这条路：**过拟合指标不是可选项，样本外验证是必填参数**。

它跑在 engine-core 的回测之上，只用公开入口 `runBacktest` 与 `@gitrader/stats` 的统计函数；不改内核、不联网、零第三方依赖。

## 0. 在装好的产品里怎么用

寻优包本身是库（`@gitrader/optimizer`），装好的 `gitrader` 把它接成了**异步作业**，和回测一个形态：起作业 → 看进度 → 取结果。研究是只读的，不下单、不写交易类账本。

命令行（照 Freqtrade 的 hyperopt 子命令）：

```
gitrader research optimize --strategy ema-cross --data btcusdt-1h.csv \
  --space '{"fast":{"type":"integer","min":5,"max":15,"step":5},"slow":{"type":"integer","min":20,"max":60,"step":20}}' \
  --validation holdout:300 --json
gitrader research walk-forward --strategy ema-cross --data btcusdt-1h.csv --space @space.json --validation wf:600:200
```

- `--data` 是 `t,o,h,l,c[,v]` 的 K 线 CSV（毫秒时间戳）；不给就用 `--instrument` / `--from` / `--to` 走场所行情。`--search grid|random:<n>|evolution`，`--seed` 缺省 42，`--fee` 缺省 0.0005（吃单），`--slippage` 缺省 3 bp。
- 默认等作业跑完；`--json` 只打印一个 JSON（含 `jobId`）。`--no-wait` 只起作业，之后用 `gitrader research status|result|cancel <作业 id>`；`result <作业 id> --part trials|folds` 分页取明细。

Agent 用 MCP 工具 `research`：`optimize` / `walk_forward` 起作业（回 `{ jobId, kind, state }`），`status` 看进度，`result` 取摘要（不超过 8 KB，带 `counts`），`result` 加 `part: "trials" | "folds"` 与 `limit` / `cursor` 分页，`cancel` 取消。

产品里的规则（起作业之前同步校验，不对就回 `INVALID_PARAMS` 且不建作业）：

- `validation` 必填（`holdout` 或 `walk-forward`）；`walk_forward` 动作只收 walk-forward 计划。
- 网格组合数或随机试验数不超过 500；`space` 里的参数名必须是策略声明过的；不参与寻优的参数放在 `subject.strategy.params`。
- 结果和库里直接调用 `optimize()` 逐点一致；摘要带 `overfit`（PBO / DSR / 试验次数）、`validation`（样本外得分）与首行标注。所有数字都是**假设性回测**，不是前向证据。

下面讲的是库本身（`optimize()` 的参数与结果）。

## 1. 三种搜索与一次强制验证

| 方式 | 行为 | 复现 |
|---|---|---|
| `grid` | 参数空间笛卡尔积穷举，第一维最慢；组合数超过 `maxTrials` 抛 `RangeError`，**不偷偷抽样** | 完全确定，不用随机数（`seed` 记 0） |
| `random` | 每维按取值域均匀抽，数值型贴 step 网格；抽满 `trials` 个互不重复的组合 | 同一 `seed` 逐点相同 |
| `evolution` | 精英保留 + 锦标赛选择 + 均匀交叉 + 逐基因变异，`population × generations` 次评估 | 同一 `seed` 逐点相同 |

同一个参数组合只回测一次（搜索内部按参数键缓存），所以**「试验次数」就是真正跑过的回测数**。

## 2. 用法

```ts
import { optimize, renderReport } from '@gitrader/optimizer'

const result = optimize({
  strategy,
  candles,
  space: {
    fast: { type: 'integer', min: 3, max: 20, step: 1 },
    slow: { type: 'integer', min: 10, max: 60, step: 5 },
    mode: { type: 'select', options: ['long', 'both'] },
  },
  search: { kind: 'evolution', population: 12, generations: 4 },
  validation: { kind: 'walk-forward', trainBars: 120, testBars: 40, embargoBars: 1 },
  seed: 7,
  sim: { feeRate: 0.0005, slippageBps: 2 },
})

console.log(renderReport(result))   // 首屏第一行就是证据等级
```

- 没有 `validation` 直接抛 `TypeError`：**没有样本外证据的寻优，本包不接受**。
- `metric` 缺省是夏普；要换口径（卡玛、换手惩罚等）传一个 `returns => number`。
- `sim` 是费用与滑点；不传时用 engine-core 缺省（手续费率 0.00045、滑点 2 bp），未必是你场所的真实费率——**先把费用填对**。

## 3. 结果里必须看的四样

| 字段 | 意思 | 怎么读 |
|---|---|---|
| `overfit.trials` | 寻优区间内真正回测过的组合数（不含留出期与盲段） | 试验越多，最好那条越可能是运气。永远有值 |
| `overfit.pbo` | CSCV 的过拟合概率（Bailey–Borwein–López de Prado–Zhu 2014） | 越接近 0.5 越像噪声；缺省 8 块（C(8,4)=70 组），周期不够自动降到能整除的偶数块，低于 2 期记 `null` |
| `overfit.dsr` | 最优试验的去膨胀 Sharpe（Bailey & López de Prado 2014），基准是「N 次试验下的期望最大 Sharpe」 | DSR 是概率（0..1）：越接近 1，越说明最优 Sharpe 超过了 N 次试验下的期望最大值；明显低于 0.95 时，不能排除「挑出来的最好结果只是运气」 |
| `validation` | walk-forward 各折或留出期的样本外得分 | 只有样本外得分算证据；`efficiency`（样本外 / 样本内）掉得厉害就是过拟合 |

算不出来的指标**字段是 `null`，`missing` 里写原因**，不会用 0 糊过去。

**`inSampleOnly` 为真时**（walk-forward 凑不出窗口或没有有效折、留出期的样本段没有可用试验），报告首屏第一行是那行固定标注：**样本内，不可作为前向证据**。这句话不是免责声明，是结论。

## 4. 验证方式

- `walk-forward`：窗口规则与 engine-core 的 walk-forward 一致——测试窗紧接训练窗，中间可留 `embargoBars`，末尾 `blindHoldoutBars` 谁都不碰。每折只在训练窗寻优，样本内最优参数原样拿到测试窗回测。
- `holdout`：在样本内寻优，样本内最优参数只在末尾留出期回测一次。
- 每折的搜索种子 = `seed + 折号`：各折不会抽到同一批组合，整体仍可复现。
- **寻优区间**：`best`、`trials`、PBO、DSR 只在样本内区间上算——holdout 时是前 `n − holdoutBars` 根，walk-forward 时是前 `n − blindHoldoutBars` 根；留出期与盲段不参与任何寻优或打分，结果里 `searchRange` 写明区间。walk-forward 各折的样本外得分评估的是「这套寻优流程」，最终 `best` 在整个寻优区间上重选，本身没有单独的样本外证据。
- **预热 `warmupBars`**：可以显式给，也可以按参数名（`period` / `lookback` / `window` / `length` / `bars` 这类回看期）推断；测试窗和留出段会向前借 `warmupBars` 根历史让指标先暖起来，借来的这部分不计分。既没给、也推断不出来时会有警告（指标未齐的头几根也计分）。`testBars` 仍应取最长回看期的数倍，否则窗内可能没有信号，样本外得分偏向 0。

## 5. 它不做什么

- **不做成交仿真**：那是 engine-core 与 sim-book 的事；这里按 K 线级回测的成交假设算。
- **不做多目标优化**：目标函数是单个 `returns => number`，要综合评分自己写 `metric`。
- **不判断参数有没有经济含义**，也不替你决定该不该上实盘。
- 不做参数敏感度热图：`trials` 里有每条试验的参数与收益序列，要画自己画。

## 6. 一张诚实的结果单长什么样

报告里至少写清：搜索方式与种子、试验次数、`pbo`、`dsr`、验证方式与各折样本外得分、费用与滑点假设、`warnings` 全文。缺任何一项，这份寻优结果就只能当「样本内最优」，不能当前向证据。
