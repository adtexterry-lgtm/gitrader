# Portfolio analysis: cross-venue aggregation, exposure, PnL attribution, concentration

The portfolio package (`@gitrader/portfolio`) is a set of **pure functions**: give it positions, a price source and an FX table and it answers four questions — **what is it worth now, where does the exposure sit, which part made or lost the money, and how concentrated is it**.

All accounting uses decimal strings (18-digit fixed point internally, 8 digits at the boundary) and never touches floats. Pure functions: the same input always gives the same output, with no clock, no environment variables and no network.

## 0. Using it in the installed product

Portfolio analysis (`@gitrader/portfolio`) is wired to the `portfolio` action of the `research` tool, read-only:

- Agent: `{"action":"portfolio"}` or `{"action":"portfolio","accountId":"<account id>"}`. Without `accountId` it takes the first account in the mandate; an account outside the mandate returns an error, not data.
- Command line: `gitrader research portfolio [--account <id>] [--json]`.
- It returns `{ accountId, ccy, valuation { total, positions[] }, exposure, concentration, missing }`: valuation uses the account snapshot's equity and each position's mark price; a position whose instrument metadata, mark price or FX rate is unavailable is left out of the totals and listed in `missing` (never counted as 0).

What follows describes the library's inputs and outputs.

## 1. Input: protocol types plus two things the package adds

```ts
import { analyzePortfolio, staticPriceSource } from '@gitrader/portfolio'

const analysis = analyzePortfolio({
  positions,                                   // protocol Position[]
  instruments,                                 // protocol Instrument[] (multiplier, settlement ccy, asset class)
  valuationCcy: 'USD',                         // every amount output is in this currency
  prices: staticPriceSource({ 'binance:BTCUSDT': '64000.5' }),  // injected price source
  fx: { 'USDT/USD': '1' },                     // quote ccy to valuation ccy; same ccy needs none
  strategyTags: { 'acct_1|binance:BTCUSDT': 'grid-btc' },      // strategy tags for attribution
  onMissingPrice: 'throw',                     // or 'skip'
})
```

- **The price source is injected**: `{ price(instrumentId) => Decimal | undefined }`. A `0` or a negative value is treated as missing.
- **Two missing-price modes**: `throw` (the default, listing every unpriced instrument in the error) and `skip` (skip that position and list it in `unpriced`, **never treat it as zero**).
- **Strategies are not part of a protocol position** (a strategy is an engine-side concept), so tags are injected: keys prefer `${accountId}|${instrumentId}`, then `${accountId}`, otherwise the bucket is `unassigned`.
- FX keys are `FROM/TO`; the inverse pair is derived automatically and **no triangular conversion is done**.
- **Size units follow `Instrument.venueSizeUnit`**: with `'contract'`, base quantity = `size × contractSize`; with `'base'`, `size` already is the base quantity and `contractSize` is display-only (some data connectors put the contract face value there).

## 2. Output: four blocks

```ts
analysis.valuation      // per-position valuation plus unpriced
analysis.exposure       // exposure: total, by asset, by venue, by direction
analysis.attribution    // PnL: total, by strategy, by venue, by instrument
analysis.concentration  // concentration: by asset, venue, instrument, strategy
```

**Valuation is the single error exit**: `valuePositions()` throws `PortfolioError`, whose `code` you branch on and whose `details` list every problem (it does not swallow all but the first).

| Code | When |
|---|---|
| `valuation_failed` | Raised once after every per-position problem is collected; each entry in `details` starts with its subclass prefix: `unknown_instrument:` (a position references an instrument missing from `instruments`), `unsupported_settlement:` (non-linear settlement), `invalid_position:` (`size` <= 0), `duplicate_position:` (the same (account, instrument, side) twice), `missing_price:`, `missing_fx:` |
| `invalid_input` | Empty `valuationCcy`, a 0 or negative rate in the FX table, or the same instrument twice in `instruments` — thrown directly, not aggregated |
| `missing_fx` | Calling `fxRate()` on its own when the pair is missing |

## 3. Exposure: gross, net, long, short

Every bucket (`ExposureBucket`) in `totals`, `byAsset`, `byVenue` and `byInstrument` carries `key`, `gross`, `net`, `long`, `short`, `quantity` (signed base-asset quantity) and `positionCount`.

- `gross = long + short` (absolute values added), `net = long - short`.
- `byAsset`, `byVenue` and `byInstrument` are arrays of buckets; `byDirection` is a single object `{ long, short, net, gross }` with no `key`, `quantity` or `positionCount`.
- Read risk from `gross` and `byDirection`; read directional view from `net`.

## 4. PnL attribution: realised, unrealised, funding, plus one reconciliation line

Every bucket (`PnlBucket`) gives `realized`, `unrealized`, `funding` and `total`, plus two fields meant for reconciliation:

| Field | Meaning |
|---|---|
| `venueUnrealized` | Unrealised PnL as reported by the venue, already converted into the valuation currency; **not part of `total`** |
| `drift` | `unrealized - venueUnrealized`, i.e. how far our number is from the venue's |

`drift` is not decoration: if it stays non-zero, your valuation inputs (multiplier, mark price, FX) disagree with the venue, so do not rush to blame the strategy.

## 5. Concentration: HHI and effective N

Four dimensions, one report each: `byAsset`, `byVenue`, `byInstrument`, `byStrategy`.

| Field | Meaning |
|---|---|
| `hhi` | Sum of squared weights, 0..1; a single position gives 1, and it approaches 0 as the book spreads out |
| `effectiveN` | `1 / HHI`, the "effective number of positions"; 0 for an empty book |
| `top1` / `top3` / `top5` | Share of the top 1 / 3 / 5 buckets |
| `largest` | The biggest bucket with its key and amounts |
| `buckets` | Every bucket, largest first |

## 6. Using it in the interface

The return value is exactly what an account-overview view needs (the workbench does not use this library yet; wire it in yourself): `analysis.valuation.positions` feeds the position table, `exposure.byVenue` the venue breakdown, `attribution.byStrategy` the per-strategy PnL ranking, `concentration.byInstrument` the concentration card. **Amounts are decimal strings in the valuation currency**; do not multiply them again in the frontend.

## 7. What it does not do

- No margin, buying power or liquidation price: those belong to accounts and risk.
- No triangular FX: a missing direct rate raises `missing_fx` rather than guessing.
- No database access, no quote cache, no freshness check: whatever price source you inject is what gets used. **Stale prices give stale conclusions**, and that is the caller's responsibility.
