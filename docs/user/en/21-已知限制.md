# Known limitations (0.1.1)

Gitrader 0.1.1 is a **developer preview**. This page lists what does not work yet, what is not yet validated, and what you should not assume. Every item applies to the release as shipped; the rest of the user documentation describes what does work.

## 1. Mainnet live trading is not supported in 0.1.1

Live trading on **mainnet** is not available in this release. If an account is configured for it, any order is rejected by the kernel, and `gitrader doctor` reports the problem and tells you what to change. This is a deliberate limit, not a configuration mistake.

Two related paths are unaffected:

- **Read-only watch accounts work on mainnet.** A watch account needs only a public address, holds no key and can never place an order.
- **Paper trading works on mainnet market data.** A paper account can use mainnet quotes and candles while every fill stays local.

## 2. Testnet live ordering is experimental

Placing **live orders on testnet** is an experimental feature in 0.1.1. It has not yet been fully validated on the real network, so treat it as a test path: use small sizes, watch the ledger and reconciliation output, and do not rely on it for anything that matters.

The Hyperliquid testnet requires that an address has previously deposited on mainnet before it can authorise an agent wallet and place orders. This release uses only testnet tokens and has not been tested with real funds, so the primary evidence for the trading path is paper accounts and offline fixture tests.

## 3. No installer, and no code signing

Gitrader does not ship an EXE, MSI or pkg installer. The supported packages are the npm package and the portable zip bundles.

The portable bundles and the release assets are **not code-signed**. Windows SmartScreen and macOS Gatekeeper may therefore show a warning when you run them. Check the checksum published with the release before you start a bundle.

**Docker images are not published to an image registry.** 0.1.1 provides only the build files in `docker/`; users build locally with `docker compose build`.

## 4. Parameter optimization is single-process

The optimizer runs in a single process. It does not parallelise across CPU cores, so a large grid or evolution search takes as long as one core needs. Plan runs accordingly.

## 5. No mainland China market data sources

Gitrader ships no market data source for mainland China markets. The bundled venue connectors and the market data paths documented in the user guide cover the venues described there only.

## 6. Some CLI help and messages are Chinese-only

Parts of the CLI help text and some runtime messages are currently Chinese-only. The English user documentation describes the same commands and fields; when the two disagree, the command output and the source code are authoritative.

## 7. No strategies, data, factors or advice

Gitrader ships **no strategies, no market datasets and no factors**. It does not give trading advice and does not custody funds. The bot templates are skeletons with configurable parameters, not recommendations, and the engine ships with no historical data: bring your own files or record candles locally.

The engine, the protocol packages and the interfaces are the product. What you trade, with which data and with which rules, is yours.
