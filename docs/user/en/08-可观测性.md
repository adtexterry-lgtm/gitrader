# Observability

Gitrader does not ship a monitoring dashboard. It does two things: **turns state into Prometheus metrics** and **writes every action into the ledger**. Collection and display are up to your Prometheus / Alertmanager / Grafana.

## 1. Two HTTP endpoints

| Endpoint | Auth | Returns |
|---|---|---|
| `GET /api/metrics` | `Authorization: Bearer ***` | Prometheus text format (`text/plain; version=0.0.4`) |
| `GET /api/ready` | same | `{"ready":true|false,"components":{kernel,ledger,tradingState,halted}}`; 200 when ready, otherwise 503 |

Key points:

- The service binds `127.0.0.1` only, so the scraper either runs on the same machine or reaches it through `host.docker.internal`.
- Use the service token from `~/.gitrader/service.json` (`svc_…`). It is the token for local tools: read-only plus PIN-present actions, and it **cannot be used as a workbench session**.
- `/api/ready` semantics: ready only when both kernel and ledger are healthy; `HALTED` **does not** count as "not ready" — a halt is a normal-but-dangerous running state, to be caught by alerting, not by a probe restarting the container (a restart does not clear a latch).

## 2. Metrics

| Metric | Type | Labels | Notes |
|---|---|---|---|
| `gitrader_up` | gauge | — | 1 while the process is alive |
| `gitrader_uptime_seconds` | gauge | — | Seconds since start-up |
| `gitrader_process_rss_bytes` | gauge | — | Resident memory |
| `gitrader_process_heap_used_bytes` | gauge | — | V8 heap in use |
| `gitrader_ledger_entries` | gauge | — | Ledger entry count |
| `gitrader_trading_state` | gauge | `state` = `ACTIVE` / `REDUCING` / `HALTED` | 1 for the current state only |
| `gitrader_events_total` | counter | `topic` | Event bus totals per topic (topics are listed in `packages/kernel/src/events.ts`) |

These few are enough to answer "is it alive, is it trading, is it being denied, is the ledger growing".

## 3. Scraping

`ops/prometheus/prometheus.yml` in the repository is a ready-to-edit example:

- `job_name: gitrader-kernel`, `metrics_path: /api/metrics`, `scrape_interval: 15s`, `scrape_timeout: 10s`;
- the token goes through `authorization.credentials_file`: **the file holds the path only, never the token value**;
- the target defaults to `127.0.0.1:47900` (in a container scraping the host, change it to `host.docker.internal:47900`);
- `rule_files` points at `alerts.yml`; `alerting` points at Alertmanager.

```text
# Manual endpoint check (same machine)
curl -s -H "Authorization: Bearer ***" http://127.0.0.1:47900/api/metrics | head
```

Take the token from `~/.gitrader/service.json`; never paste it into any file that goes into version control.

## 4. Alert rules

`ops/prometheus/alerts.yml` contains 7 rules, unchanged in this batch:

| Alert | Condition | Meaning |
|---|---|---|
| `GitraderDown` | `gitrader_up == 0` | The kernel is gone |
| `GitraderHalted` | `gitrader_trading_state{state="HALTED"} == 1` | Halt latched, a human has to act |
| `GitraderRiskDenialsSpike` | `risk.denials` increment > 20 within 5 minutes | Orders are being denied en masse: either the parameters are wrong or the market is abnormal |
| `GitraderNoMarketData` | `market.candles` increment is 0 for 10 minutes while the process is alive | Market data has stopped |
| `GitraderHighMemory` | `gitrader_process_rss_bytes > 1.5e9` | Memory above 1.5 GB |
| `GitraderLedgerStalled` | ledger increment 0 for 30 minutes but fill events within those 30 minutes | The ledger is not recording — serious |
| `GitraderRestarted` | `gitrader_uptime_seconds < 120` | Just restarted (possibly crash-looping) |

`ops/alertmanager/alertmanager.yml` routes by `severity` and ships three **placeholder** receivers: telegram / email / webhook. The bot token, SMTP password and bearer token inside them must go through `*_file` references only (`bot_token_file` / `auth_password_file` / `credentials_file`) — **never write real values in**. Alertmanager does not expand `${ENV}`: to use environment variables, render a temporary file with something like `envsubst` before starting and mount that.

## 5. Display

- `ops/grafana/dashboards/gitrader-overview.json`: runtime state, uptime, event rate (by topic, `rate(...[5m])`), ledger growth, trading state (current value plus timeline), memory (RSS and V8 heap), rate-limited calls (by identity).
- `ops/grafana/provisioning/` holds the datasource (uid `prometheus`) and the dashboard auto-load configuration.
- The compose snippet for bringing up the stack is in `ops/README.md`; it is an **example**, not placed at the repository root, and its ports bind `127.0.0.1` only.

## 6. Self-check

```text
node ops/verify-ops.mjs
```

Runs offline: it reconciles the `gitrader_*` metric names and labels in the Grafana dashboard `expr` fields against `packages/kernel/src/metrics.ts`, `packages/kernel/src/events.ts` and `packages/protocol/src/model/risk.ts` in both directions, then checks the structure of the Prometheus / Alertmanager / provisioning YAML and looks for secret literals. For the alert rules file `alerts.yml` it checks existence only — the expressions inside are not reconciled; `packages/kernel/test/alerts-config.test.ts` guards those. On mismatch it lists everything and exits 1. This belongs in CI: rename a metric and forget the panel, and it goes red immediately.

## 7. Logs and the ledger

- Kernel logs go to stderr, prefixed with `[gitrader]`; warnings look like `[gitrader] warning: …`. Do not leave the `gitrader serve` terminal minimised forever.
- The real audit surface is the ledger, not the logs: `gitrader ledger verify` recomputes the hash chain; `gitrader ledger export --out <dir>` exports JSONL, a manifest, a human-readable `账单.csv` and a Markdown trade log (`--redact` strips payloads).
- Metrics say "how it is now"; the ledger says "what happened". Troubleshooting needs both.

## 8. Troubleshooting

| Symptom | Cause | Action |
|---|---|---|
| Scrape returns 401 | Wrong token / file not mounted / a session token was used | Use the service token from `service.json`; check the permissions of `credentials_file` |
| Scrape cannot connect | The kernel binds 127.0.0.1 only | Run the scraper on the same machine, or use `host.docker.internal` from a container |
| Metric present but no `HALTED` series for trading state | That state has never occurred (only the current state is exposed) | Normal; build the state timeline from scrape history |
| `GitraderNoMarketData` stays red | The service was started with `--offline`, or the market-data connection is down | Look at the `Venues` line of `gitrader status` |
| `GitraderLedgerStalled` | Ledger writes are stuck (disk full, permissions, database locked) | Check `ledger verify` and the disk immediately |
| Panels are empty | The datasource uid is not `prometheus`, or the time range contains no scrapes | Compare against `ops/grafana/provisioning/` |
