# The four data sources that need an API key

Gitrader's market-data connectors come in two kinds: **key-free** ones (the crypto venues, which read public market data directly and are registered in the `gitrader serve` venue table) and **keyed** ones (the four below, third-party vendors for US and global equities). This page covers the keyed ones only: which environment variable holds the key, what the free plan gives you, what it does not, and which error code each failure maps to.

## 1. The four at a glance

| Vendor | Package | Environment variable | Free-plan limit (as declared in `describe().rateLimits`) | Read-only |
|---|---|---|---|---|
| Alpha Vantage | `@gitrader/connector-alphavantage-data` | `ALPHAVANTAGE_API_KEY` (then `ALPHA_VANTAGE_API_KEY`) | 25 calls per day, per IP | Yes |
| Finnhub | `@gitrader/connector-finnhub-data` | `FINNHUB_API_KEY` | 60 calls per minute, per IP, counted per call rather than per weight | Yes |
| Polygon | `@gitrader/connector-polygon-data` | `POLYGON_API_KEY` | 5 calls per minute, per account | Yes |
| Twelve Data | `@gitrader/connector-twelvedata-data` | `TWELVEDATA_API_KEY` | 8 credits per minute and 800 credits per day | Yes |

All four declare `x-data-only: true`: market data only, no funds, no trading credentials.

**The key comes from the environment only.** You can also pass `apiKey` to the constructor (it wins over the environment), but **never put it in a config file**: config files are hashed, signed and written to the ledger. A missing key fails at construction (`VENUE_AUTH` for Alpha Vantage and Polygon, `INVALID_PARAMS` for Finnhub and Twelve Data), the message names the variable and never the value, and a key echoed back by the upstream in an error body is replaced with `<redacted>` before it leaves the client.

## 2. What the free plan gives, and what it does not

| Vendor | Available on the free plan | Not available on the free plan |
|---|---|---|
| Alpha Vantage | Daily `compact` (last 100 bars), weekly and monthly (full history), `GLOBAL_QUOTE`, `LISTING_STATUS` | Any intraday interval (`1m` / `5m` / `15m` / `30m` / `1h`; `TIME_SERIES_INTRADAY` is premium), daily `n > 100`, daily with `from` (it uses `outputsize=full`); no bid/ask at all (`book` raises `CAPABILITY_UNSUPPORTED` rather than inventing levels) |
| Finnhub | Instrument list, `quote`, `marketStatus`, `marketHolidays` | `candles` (`/stock/candle`) and `book` / `bidAsk` (`/stock/bidask`) are marked premium and return 403 with a free key |
| Polygon | About two years of history and minute aggregates (updated after the close) | Snapshot endpoints (refreshing `quote`, one-level NBBO `book`, `context`, `subscribe({channel:'quote'})`) return 403 on the free plan |
| Twelve Data | Stock list, `time_series`, `quote`, `market_state` (subject to your plan) | Endpoints and symbols outside your plan (401 / 403); no bid/ask (`x-book: 'none'`) |

**"Not available" never silently becomes empty data**: a paywall maps to `VENUE_AUTH` with no retry, and a bad parameter or symbol maps to `INVALID_PARAMS`.

## 3. What you see when it fails

| Upstream behaviour | Mapping |
|---|---|
| Alpha Vantage over limit or not entitled: HTTP 200 with an `Information` or `Note` body | Text containing `premium` becomes `VENUE_AUTH` (no retry, no budget penalty); anything else becomes `VENUE_UNAVAILABLE` (`retryable: true`, retry in about 60 seconds) and backs the budget off |
| Alpha Vantage `Error Message` | `INVALID_PARAMS` (no retry) |
| Finnhub 403 on a premium endpoint | `VENUE_AUTH` (no retry) |
| Polygon 429 / 403 | 429 becomes `VENUE_UNAVAILABLE` carrying `Retry-After`; 403 becomes `VENUE_AUTH` |
| Twelve Data 429 (or HTTP 200 with `{status:"error", code:429}`), 401 / 403, 400 / 404 | 429 becomes `VENUE_UNAVAILABLE` (`retryable: true`); 401 / 403 become `VENUE_AUTH`; 400 / 404 become `INVALID_PARAMS` |

## 4. Handling the limits

None of the four sleeps by itself. Before each request they ask an injected `budget` for allowance (preferring `acquire(weight)`, falling back to `take(weight)`) and call `reportOk()` on success; the default budget is unlimited. To actually respect a free plan, build the budget from the numbers declared in `describe().rateLimits`:

```ts
import { AlphaVantageDataConnector } from '@gitrader/connector-alphavantage-data'

const conn = new AlphaVantageDataConnector({ budget })   // the key comes from ALPHAVANTAGE_API_KEY
conn.describe().rateLimits   // [{ scope: 'ip', model: 'count', limit: 25, windowMs: 86_400_000, note: … }]
```

Large pulls need paging: `describe().history` declares the per-call bar limit and the page limit. Polygon walks the instrument list on first start using `instrumentPages` (default 100 pages of 1000 symbols), which is slow at 5 calls per minute — **lower `instrumentPages`, or call `getInstrument()` for symbols you already know**.

## 5. What works today, and what does not

- **Works**: constructing an instance in code, then `start()`, `listInstruments()`, `candles()`, `refreshQuote()` — feeding backtests and feeding `@gitrader/symbol-search` to build an index.
- **Does not work yet**: these four are **not registered in the `gitrader serve` venue table**. Using them from the UI needs a registration, which is scheduled elsewhere.
- All four packages run their tests **offline**: each ships a fake server returning official response shapes and error codes.

## 6. Three things to keep in mind

1. **Do not retry against a paywall.** A paywall is not a rate limit; retrying only burns quota and returns the same 403.
2. **The limit numbers come from official pages** (each package README cites the source). They change, and your account console is authoritative; `describe().rateLimits` is what the software declares, not what your plan allows.
3. **Vendor data does not follow exchange conventions.** Adjustments, time zones, trading calendars and delay all differ. Record which vendor you used and when you pulled the data in every backtest report.
