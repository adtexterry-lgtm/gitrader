# Bot Templates: Grid / DCA / Martingale / Trend

Bot templates (`@gitrader/bots`) are four **configurable strategy templates**: each declares parameters with safety caps and can replay on historical candles. They don't connect to the internet, place orders, or read external state—only calculate their own paper ledger.

**Read this first: templates are skeletons for you to adapt, not profit promises. The risk of each in certain market conditions is documented below. The Martingale template is extremely high-risk with exponentially growing exposure during consecutive drops—only experiment with very small capital, never as a main strategy.**

## Using in the Product

After installing Gitrader, four bot templates (`bot-grid`, `bot-dca`, `bot-martingale`, `bot-trend`) are already in the engine's strategy list.

### 1. List available strategies

Via MCP tool `strategies_list`:

```json
{
  "method": "strategies_list",
  "params": {
    "engineId": "gitrader-core"
  }
}
```

You'll see four `bot-*` ids (bot-grid, bot-dca, bot-martingale, bot-trend), each with parameter declarations, safety cap help, and min/max/required markers.

Or check engines from command line:

```bash
gitrader engines
```

### 2. Backtest

Submit a backtest job with your own parameters (via MCP tool):

```json
{
  "method": "backtest_run",
  "params": {
    "engineId": "gitrader-core",
    "strategyId": "bot-grid",
    "instrumentId": "BTCUSDT-PERP@hyperliquid",
    "interval": "1h",
    "params": {
      "lowerPrice": 90000,
      "upperPrice": 110000,
      "gridCount": 10,
      "maxExposureNotional": 5000
    },
    "balance": 10000
  }
}
```

Backtests run as async jobs: `run` → `status` → `result`. Results carry a "hypothetical" marker.

### 3. Start instance on paper account

Start a strategy instance on the paper account (via MCP tool start_strategy):

```json
{
  "method": "strategy_start",
  "params": {
    "engineId": "gitrader-core",
    "strategyId": "bot-dca",
    "accountId": "paper",
    "instrumentId": "BTCUSDT-PERP@hyperliquid",
    "interval": "1d",
    "params": {
      "frequency": "daily",
      "notionalPerOrder": 100,
      "maxOrders": 30,
      "maxExposureNotional": 3000
    },
    "mandateId": "<your-mandate>"
  }
}
```

When running, the instance places orders on each bar close; when stopped, positions remain as-is (no auto-flatten).

### 4. Stop instance

Via MCP tool:

```json
{
  "method": "stop_strategy",
  "params": {
    "engineId": "gitrader-core",
    "instanceId": "<instanceId>"
  }
}
```

**Missing required safety caps are rejected**: both backtest and start will error, naming the missing parameter. E.g., grid missing `maxExposureNotional`, martingale missing `maxAdds`, or DCA with `notionalPerOrder × maxOrders > maxExposureNotional` are all rejected—no half-created instances.

## 1. The Four Templates at a Glance

| Template | `id` | What it does | Main loss scenario |
|---|---|---|---|
| Grid | `bot-grid` | Place `gridCount` grids in `[lowerPrice, upperPrice]`, buy at entry, sell at exit | **Trending markets**: keeps buying on the way down, hits `boundaryAction` below lower bound; sells everything on the way up, left with only cash |
| DCA | `bot-dca` | Buy `notionalPerOrder` every `frequency` (`every_bar` / `hourly` / `4h` / `daily` / `weekly`), optional "buy the dip"; **long only, sells only for TP/SL** | Long-term downtrend: more you buy, more you lose, capped by `maxOrders` and `maxExposureNotional`; sideways bleeds fees |
| Martingale | `bot-martingale` | Add to losing position: every `addDropPct` drop, add with `multiplier` | **The riskiest**: notional grows exponentially on consecutive drops, hard-capped by `maxAdds` and `maxTotalNotional`; hits cap and halts, doesn't self-recover |
| Trend | `bot-trend` | `maPeriod` MA + `confirmBars` confirmation, ride trends with optional trailing stop | **Choppy markets**: whipsawed into stop-losses, fees and slippage erode capital; MA params fail on regime change |

## 2. Safety Caps in Parameter Validation, Not Just Docs

| Template | Required safety parameters |
|---|---|
| `bot-grid` | `maxExposureNotional` |
| `bot-dca` | `maxExposureNotional`, `maxOrders` |
| `bot-martingale` | `maxExposureNotional`, `maxAdds`, `maxTotalNotional` |
| `bot-trend` | `maxExposureNotional` |

- Templates **self-check on construction** that these keys are declared in `params`, throws immediately if missing.
- Over-limit action is **reject + halt**, not "clip size and continue"—silent clipping would make risk ledger diverge from actual positions.
- Position-reducing orders never rejected for exposure (they reduce exposure).
- **Out-of-range is rejected, not clamped**: engine-core's param resolver would clamp `maxAdds: 99` to 20 and continue; this package throws immediately—clamped configs aren't what you think they are.
- **Cross-field validation**: DCA with `notionalPerOrder × maxOrders > maxExposureNotional` is rejected; trend with `confirmBars > maPeriod` is rejected; grid with single-cell notional exceeding cap is rejected at construction.

## 3. Programmatic Usage

```ts
import { createBot, runBot, runTemplate, TEMPLATES, templateIds } from '@gitrader/bots'

templateIds()                       // ['grid', 'dca', 'martingale', 'trend']
TEMPLATES.grid.params               // parameter declarations (key / label / type / default / min / max / options / help)

// One-step: create template → replay on historical candles
const run = runTemplate('grid', {
  lowerPrice: 90_000,
  upperPrice: 110_000,
  gridCount: 12,
  maxExposureNotional: 5_000,
}, candles, {
  initialCash: 10_000,
  feeRate: 0.0005,
})

run.fills          // each paper fill
run.equity         // one equity point per bar
run.realizedPnl    // realized PnL
run.maxExposure    // max position notional throughout
run.unfilled       // limit intents not reached (normal pending, not errors)
run.halted         // halt reason (hit cap / stop-loss / boundary)
```

Or build instance and feed step-by-step:

```ts
const bot = createBot('martingale', {
  baseNotional: 100,
  multiplier: 1.5,
  maxAdds: 4,
  maxTotalNotional: 1_000,
  maxExposureNotional: 2_000,
})
const one = runBot(bot, candles, { initialCash: 10_000 })
```

Invalid params throw `BotParamError` (with itemized reasons), untrusted data throws `BotStateError` (out-of-order candles / missing fields / non-positive price, etc.).

## 4. Grid Gotchas (Easiest to Step On)

- `gridCount` is **number of cells**, boundary lines are `gridCount + 1`.
- `gridMode` is `arithmetic` (equal steps) / `geometric` (equal ratios); geometric requires `upperPrice > lowerPrice > 0`.
- `gridDirection` is `long` / `short` / `neutral`: `neutral` does long grids below mid, short grids above.
- `boundaryAction` is `pause` (stop opening new grids) / `stop_loss` (halt) / `hold` (log only, keep running existing grids).
- **Same grid doesn't round-trip in one bar**: doesn't assume "buy at low, sell at high of the same bar."

## 5. Martingale Hard Stops

- `maxAdds`: max number of add-ons. Halts when reached.
- `maxTotalNotional`: cumulative notional cap. Halts when reached.
- Both are in parameter validation (`SAFETY_KEYS.martingale`); template won't construct if either is missing.

## 6. Parameters and Defaults

| Template | Parameters (defaults) |
|---|---|
| `bot-grid` | `lowerPrice` 90000, `upperPrice` 110000, `gridCount` 10, `gridMode` `arithmetic`, `gridDirection` `long`, `qtyPerGrid` 0.001, `boundaryAction` `pause`, `stopLossPct` 10, `maxExposureNotional` 10000 |
| `bot-dca` | `frequency` `daily`, `notionalPerOrder` 100, `maxOrders` 30, `dipBuyEnabled` false, `dipThresholdPct` 3, `takeProfitPct` 20, `stopLossPct` 25, `maxExposureNotional` 3000 |
| `bot-martingale` | `direction` `long`, `baseNotional` 100, `multiplier` 1.5, `addDropPct` 2, `maxAdds` 4, `maxTotalNotional` 1000, `takeProfitPct` 3, `stopLossPct` 15, `maxExposureNotional` 2000 |
| `bot-trend` | `maPeriod` 50, `maType` `SMA`, `confirmBars` 2, `positionPct` 50, `direction` `both`, `trailingStopPct` 5, `stopLossPct` 8, `maxExposureNotional` 10000 |

Each parameter has `min` / `max` / `options`; out-of-range throws `BotParamError` with itemized reasons. `maxAdds` is **number of add-ons** (excludes initial position).

## 7. Three Things to Accept Before Using

1. **Paper replay has no slippage model**: only uses your `feeRate` and bar settlement prices. For more realism, use sim-book's order-book-level fills separately.
2. **Parameters are skeleton, not recipe**: same params on different regimes may behave completely differently; to check if they only look good in-sample, use parameter sweep and check `pbo` / `dsr`.
3. **Templates don't self-recover**: once hitting a cap or stop-loss, they halt; restart and whether to continue are human decisions.
