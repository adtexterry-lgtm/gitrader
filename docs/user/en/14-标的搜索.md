# Symbol search

Exchanges spell the same instrument several ways: `BTCUSDT`, `BTC/USDT` and `btc-usdt` are one thing; a six-digit number may be an A-share or a futures contract; only names ending in `.HK` are Hong Kong stocks. Symbol search (`@gitrader/symbol-search`) folds all of that into one place: **search by code, name or alias, filter by market type / venue / asset class / quote currency, and check whether a record can be added to a watchlist or traded at all**.

It is a pure-function library: no file reads, no network, no environment variables, never calls `start()` on a connector, no global state. The index comes from the `listInstruments()` of data connectors you already registered.

## 0. Using it in the installed product

Symbol search (`@gitrader/symbol-search`) is wired to the `search` action of the `research` tool. The catalog is the venue catalog the kernel has already loaded (an empty list, not an error, when the catalog could not be fetched offline):

- Agent: the `research` tool with `{"action":"search","query":"BTC","limit":5}`, optional `venue` and `kind` (`perp` / `spot`...) filters; it returns `{ items, total, next? }` and each item has `instrumentId`, `venue`, `symbol`, `base`, `quote`, `kind`, `score`. When `next` is present, pass it as `cursor` for the next page.
- Command line: `gitrader research search BTC --limit 5 --json`.

The rest of this page describes the library itself, for people writing their own integration.

## 1. Building the index

```ts
import { indexFromConnectors, searchSymbols, suggestSymbols, findSymbol, validateSelection } from '@gitrader/symbol-search'

// the connector owns start(); this package never issues requests on its behalf
const index = indexFromConnectors([binanceData, polygonData], {
  aliases: { 'polygon:AAPL': ['AAPL.US'] },   // instrumentId -> aliases (localised names go here too)
  sortOrder: { 'binance:BTCUSDT': 10 },       // instrumentId -> weight, higher comes first
})
```

| Function | Purpose |
|---|---|
| `buildIndex({ instruments, source?, aliases?, names?, sortOrder? })` | One instrument list from one connector -> index |
| `mergeIndexes([...])` | Merge several indexes, de-duplicated |
| `indexFromConnectors([...], opts?)` | Both of the above in one call |

The dedupe key is `(venue, upper-cased symbol, kind, instrumentId)`; records without `symbol` or `venue` are dropped.

## 2. Searching and ranking

```ts
searchSymbols(index, 'btc', { limit: 10, filter: { kinds: ['perp'], quote: 'USDT' } })
// -> [{ record, rank: 1, matchKind: 'symbol-prefix', matchedOn: 'symbol' }, ...]
```

Rank tiers (higher first): 0 exact symbol, 1 symbol prefix, 2 symbol contains, 3 name contains, 4 exact alias, 5 alias contains, 6 fuzzy. Within a tier: `sortOrder` descending, symbol length ascending, symbol, venue, instrumentId.

- **Normalisation**: `/ - _ . space :` are stripped before comparing, so `btc/usdt` matches `BTCUSDT` and `brk-b` matches `BRK.B`. No transliteration or word segmentation: inject localised names through `aliases`.
- **Fuzzy is a last resort**: if any of the first five tiers matched, fuzzy hits are not mixed in. `{ fuzzy: false }` turns it off entirely.
- **An empty query returns an empty array** (blank queries too), not everything.
- `suggestSymbols(index, q, n)` returns exact and prefix matches only, which suits autocomplete.
- `findSymbol(index, q)` returns the first hit, which suits "the string I just pasted".
- **Delisted instruments are filtered out by default** (`status === 'delisted'`); pass `filter: { includeDelisted: true }` to see them.

`SymbolFilter` fields: `venues` / `kinds` / `assetClass` / `quote` / `sources` / `includeDelisted`. Each accepts a single value or an array; `quote` is case-insensitive.

## 3. Selection checks

`validateSelection(record)` returns `undefined` when the record is usable, otherwise `{ code, message }`:

| Code | Trigger |
|---|---|
| `EMPTY_SYMBOL` | The code is empty |
| `CN_CODE_NOT_STOCK` | Six digits but not a stock (the A-share code shape taken by something else) |
| `HK_CODE_NOT_STOCK` | Ends in `.HK` but is not a Hong Kong stock |
| `CRYPTO_NOT_A_PAIR` | A crypto symbol that is not a `BASE-QUOTE` pair |

These four catch input that looks right and cannot be traded. **They do not replace pre-trade checks**: the real gates are the risk layer and the connector's declared capabilities; this is an early rejection at the interface layer.

## 4. What a record has, and has not

`SymbolRecord` carries only what display and filtering need: symbol, name, venue, market type, asset class, quote currency, status and a few more. **It carries no price**, which is why an index can be cached for a long time while quotes are fetched separately.

## 5. Boundaries

- With a connector that has not been `start()`ed, `listInstruments()` is empty and so is the index. This package does not fetch on its behalf.
- Ranking weights come from the caller (nothing is persisted here). Persist watchlist order yourself.
- Out of scope: quotes, orders, permissions, transliterated search.

## 6. One deliberate divergence from the reference

In the reference implementation the "name contains" case silently fell into the fallback branch because of a bound SQL placeholder. This package implements the stated intent (name contains is always tier 3). The divergence is deliberate, not an oversight: if you diff numbers against that reference, this tier will not match.
