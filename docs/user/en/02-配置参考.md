# Configuration reference

One file rules everything: `~/.gitrader/gitrader.json`. `gitrader init` writes the default contents; change them as you like afterwards. Fields, defaults and validation rules all come from `packages/kernel/src/config.ts`. A file that fails validation makes the kernel **refuse to start and list every problem** — there is no silent correction.

## General rules

- **The kernel reads it once at startup**; M1 has no hot reload, so restart `gitrader serve` after editing.
- **No secrets in the file**: only names from the keystore (`signerRef`) and public addresses; tokens are always written as handles (`env:VARIABLE_NAME`).
- Decimal values (notional amounts, ratios) are written as **strings**, e.g. `"2000"`, `"0.03"`; counts, seconds and multiples are numbers.
- One exception: the `risk` section can only **tighten**. Anything wider than the signed risk policy is ignored and reported in the startup warnings; loosening requires entering your PIN in the workbench (or `gitrader risk relax`).
- Switching network (mainnet / testnet) in the workbench rewrites `venues[].environment` and `accounts[].environment` and tells you to restart.

## Top-level fields

| Field | Type | Default | Notes |
|---|---|---|---|
| `schema` | string | `"gitrader-config/1"` | Must be exactly this value; anything else will not start |
| `supportDeveloper` | boolean | `false` | "Support the developer" switch: when on, Hyperliquid orders carry a 1 bp builder fee (you must also authorise it from your main wallet); trading works normally when off. `init` does not ask about it |
| `venues` | array | see below | Venues |
| `accounts` | array | see below | Accounts |
| `engines` | array | see below | Engines |
| `risk` | object | see below | Risk seed |
| `keys` | object | see below | Key defaults |
| `layout` | object | `{"workspace":"ws_default"}` | Default workspace name; M1 validates it only and never reads it |
| `server` | object | `{"port":null}` | Local service port |
| `plugins` | object | `{"developerMode":false,"trustRoots":[]}` | Plugins |
| `embed` | object | `{"allowedOrigins":[]}` | Origins allowed to embed the workbench in an iframe |

## `venues`: venues

Default: `[{"id":"hyperliquid","environment":"testnet","enabled":true}]`

| Field | Type | Notes |
|---|---|---|
| `id` | string | Lowercase letters, digits, hyphens. The venues you can use are in the capability table below |
| `environment` | `"mainnet"` \| `"testnet"` | Network |
| `enabled` | boolean | Whether it is enabled |

Mainnet is off by default: before switching to mainnet in the workbench you must import or generate a **mainnet** API wallet (see 05).

**Which venues you can use, and how far each goes** (put the first column in `id`; "read-only" = market data, "testnet / mainnet" = whether orders can be placed):

| Venue `id` | Read-only | Testnet orders | Mainnet orders | Notes |
|---|---|---|---|---|
| `hyperliquid` | yes | yes | yes | Bundled and enabled by default; mainnet needs a mainnet API wallet first |
| `ibkr` | yes | yes | no | Needs a local IB gateway; list the tickers you use in `symbols`; mainnet live is not open |
| `binance` | yes | yes | no | Testnet orders need credential handles on a live account; mainnet is market data only |
| `okx` | yes | yes | no | As above, plus a passphrase |
| `bybit` | yes | yes | no | Same as binance |
| `bitget` | yes | yes | no | Same as okx |
| `gateio` | yes | yes | no | Same as binance |
| `alpaca` | yes | yes | no | Stocks; the paper environment can trade, a mainnet live account gets market data only |
| `kraken` | yes | no | no | Market data only |
| `coinbase` | yes | no | no | Market data only |
| `kucoin` | yes | no | no | Market data only |
| `deribit` | yes | no | no | Market data only |
| `dydx` | yes | no | no | Market data only (the trading connector is not wired in yet) |

To enable another venue, add an entry under `venues` (keep the default `hyperliquid`) and restart the service:

```json
{
  "venues": [
    { "id": "hyperliquid", "environment": "testnet", "enabled": true },
    { "id": "okx", "environment": "mainnet", "enabled": true }
  ]
}
```

For a venue that is not configured, the `market` tool answers `INSTRUMENT_UNKNOWN` naming the venue instead of pretending to have market data.

## `accounts`: accounts

Default is one paper account; aliases must be unique. `accountId` is filled in by `init` — do not edit it by hand.

| Field | Type | Required | Notes |
|---|---|---|---|
| `alias` | string | yes | How the command line and agents refer to the account |
| `venue` | string | yes | Matches a `venues[].id` |
| `environment` | `"mainnet"` \| `"testnet"` | yes | Network |
| `mode` | `"paper"` \| `"live"` \| `"shadow"` \| `"watch"` | yes | Paper (simulated matching on real market data) / live / shadow (currently the same simulated matching path as paper) / watch (read-only: positions and balances of a public address, no key, cannot trade) |
| `paper` | `{initialBalance, ccy}` | required when `mode=paper` | `initialBalance` is a decimal string |
| `watch` | `{address}` | required when `mode=watch` | The public address to watch (`0x` plus 40 hex characters). A watch account must not also set `signerRef`, `credentials` or `paper`; only the `hyperliquid` venue is supported, and its `environment` is read on its own network, which need not match the network the venue is connected to. Add it with `gitrader accounts watch <address>` instead of writing it by hand |
| `signerRef` | string | required when `mode=live` | Name of the API wallet in the keystore (visible via `gitrader keys list`); **not the private key** |
| `accounts[].owner.address` | string | recommended for live | Public address of your main account. On Hyperliquid the API wallet places orders on behalf of the main account; balances / positions / fills are looked up by main-account address. If unset, startup warns and that data cannot be tracked |

```json
{
  "accounts": [
    { "alias": "paper", "venue": "hyperliquid", "environment": "testnet", "mode": "paper",
      "paper": { "initialBalance": "10000", "ccy": "USDC" } },
    { "alias": "main-live", "venue": "hyperliquid", "environment": "mainnet", "mode": "live",
      "signerRef": "my-api-wallet",
      "owner": { "address": "0x0000000000000000000000000000000000000000" } }
  ]
}
```

## `engines`: engines

Default: `[{"id":"gitrader-core","enabled":true,"builtin":true}]`

Each entry needs an `id` (lowercase letters, digits, `.`, `_`, `-`, unique), `enabled`, plus one of three shapes:

| Shape | How to write it | Behaviour |
|---|---|---|
| Bundled reference engine | `{"builtin": true}` | The kernel launches the packaged `engine-core` as a stdio child process; if the bundle is missing it is registered but not started (point at it with the environment variable `GITRADER_ENGINE_CORE_BUNDLE`) |
| Local child process, any language | `{"launch": {"command": "...", "args": [...], "env": {...}, "cwd": "..."}}` | The kernel launches it, health-checks it, and restarts it with backoff after a crash (1 s to 60 s; 5 crashes within 10 minutes marks it failed). The child **does not inherit** your environment: it gets only what is written in `env`, `GITRADER_GEP_TOKEN` and a minimal set of system variables |
| Already-running ws / remote wss | `{"launch": {"url": "wss://...", "auth": {"method": "token", "tokenRef": "env:VARIABLE_NAME"}}}` | `url` must be `ws://` or `wss://`; non-local endpoints must be `wss://`; **tokens must never be in the URL**; `auth` holds a handle, not the token or certificate itself |

```json
{
  "engines": [
    { "id": "gitrader-core", "enabled": true, "builtin": true },
    { "id": "my-rust-engine", "enabled": true,
      "launch": { "command": "C:/engines/my-engine.exe", "args": ["--gep", "stdio"],
                  "env": { "MY_MODE": "paper" }, "cwd": "C:/engines" } },
    { "id": "partner-engine", "enabled": false,
      "launch": { "url": "wss://engine.example.com/gep",
                  "auth": { "method": "token", "tokenRef": "env:PARTNER_ENGINE_TOKEN" } } }
  ]
}
```

- The strategy folder is always `~/.gitrader/engines/<id>/strategies/` (`<id>` is `gitrader-core` for the built-in engine).
- For remote engines the `env:` handle is read from **the environment that started `gitrader serve`**; the configuration file only holds the variable name. Other handle kinds (keystore entries) are not implemented in M1 and show as failed; mTLS is not verified.
- The engine protocol is documented in `docs/engine-protocol.md`; binding an engine to an account requires you to enter your PIN in person: `gitrader engines bind <id>`.

## `risk`: risk seed

Default:

```json
{
  "risk": {
    "preset": "p-lev3-o2000-d3",
    "limits": { "maxSlippageBps": 50, "maxOrdersPerMinute": 30, "maxCancelsPerMinute": 60, "duplicateIntentWindowSec": 10 },
    "protectors": [],
    "failClosed": { "stalePriceMs": 5000, "onMissingPrice": "deny" },
    "dailyResetAt": "00:00Z",
    "valuationCcy": "USDC"
  }
}
```

**This section is only a seed**: on first start the kernel derives a **signed risk policy** from it and stores that in the database; from then on the signed policy is authoritative. A `risk` block in the file is merged only where it is stricter than the current policy.

| Field | Type | Default | Notes |
|---|---|---|---|
| `preset` | string | `p-lev3-o2000-d3` | Numeric preset, one of three; the numbers are in the id |
| `limits` | object | see above | Overrides the preset's fields of the same name |
| `protectors` | array | `[]` | Protectors; leave empty to use the preset's own |
| `failClosed` | `{stalePriceMs, onMissingPrice}` | `{5000,"deny"}` | Deny every order when market data is older than `stalePriceMs` milliseconds or no price is available |
| `denyLlmLiveEntries` | boolean | `true` | Agents of model origin may not open live positions; they can only propose and wait for your approval. Writing `false` is a loosening and **is ignored in the file** — turn it off in the workbench with your PIN |
| `dailyResetAt` | string | `"00:00Z"` | Baseline time for the daily PnL window |
| `valuationCcy` | string | `"USDC"` | Valuation currency |
| `maxDriftBps` | integer >= 0 | 30 | Bound on price drift for local approval (bp). Configuration can tighten only; loosening needs a human PIN |

**Presets**:

| id | Leverage | Single order notional | Per-instrument share of equity | Total exposure share of equity | Open positions | Daily loss | Cooldown |
|---|---|---|---|---|---|---|---|
| `p-lev3-o2000-d3` (default) | <= 3x | <= 2,000 | 0.3 | 0.6 | 3 | 3% | 5 s |
| `p-lev5-o5000-d5` | <= 5x | <= 5,000 | 0.5 | 1 | 5 | 5% | 2 s |
| `p-lev10-o20000-d10` | <= 10x | <= 20,000 | 1 | 2 | 10 | 10% | 0 |

**Available `limits` fields** (all optional; `maxSlippageBps` defaults to 50):

| Field | Type | Meaning |
|---|---|---|
| `maxLeverage` | number >= 0 | Leverage cap |
| `maxOrderNotional` | decimal string | Notional cap per order |
| `maxPositionNotionalRatio` | decimal string | Position notional / equity, per instrument |
| `maxTotalNotionalRatio` | decimal string | All positions notional / equity |
| `maxOpenPositions` | number >= 0 | Number of open positions |
| `maxDailyLossRatio` | decimal string | Daily equity drawdown ratio |
| `maxDailyNotional` | decimal string | Total notional per day |
| `maxSlippageBps` | number >= 0 | Slippage cap for market-style orders (bp) |
| `maxOrdersPerMinute` | number >= 0 | Orders per minute (guards against hammering and venue rate limits) |
| `maxDailyOrders` | number >= 0 | Orders per day |
| `maxCancelsPerMinute` | number >= 0 | Cancels per minute (risk-reducing actions are not limited) |
| `duplicateIntentWindowSec` | number >= 0 | A duplicate intent with the same account, instrument, side, price and size inside the window is rejected outright; `0` disables it (a loosening) |

**Protector kinds** (stackable; they can only deny or tighten): `cooldown`, `stoploss_guard`, `drawdown_pause`, `low_profit_lock`, `max_consecutive_failures`, `plugin`. Fields and semantics: `docs/risk-gate-protocol.md` and `packages/kernel/src/protectors.ts`.

## `keys`: key defaults

Default: `{"agentKeyExpiryDays":90,"defaultTier":"paper","walletExpiryWarnDays":14}`

| Field | Type | Notes |
|---|---|---|
| `agentKeyExpiryDays` | number > 0 | Validity in days for newly created agent keys |
| `defaultTier` | `"read_only"` \| `"paper"` \| `"confirm"` | Default tier for new keys. **`auto_limited` is not allowed here**: automatic-with-limits cannot be the default |
| `walletExpiryWarnDays` | number | How many days before API-wallet expiry rotation reminders start |

## `layout` / `server` / `plugins` / `embed`

| Field | Type | Default | Notes |
|---|---|---|---|
| `layout.workspace` | string | `"ws_default"` | Default workspace name |
| `server.port` | integer (1–65535) or `null` | `null` | `null` = find a free port from 47900 upward, skipping a list of common ports; the command-line `--port` wins. The service always binds `127.0.0.1` only |
| `plugins.developerMode` | boolean | `false` | Only when on are **unsigned** plugins loaded (local development). Unsigned plugins cannot request `trade.live` / `venue.credentials` |
| `plugins.trustRoots` | `[{keyId, publicKey}]` | `[]` | Plugin signing public keys you trust manually; the built-in trust root set is empty in M1 |
| `embed.allowedOrigins` | string array | `[]` | Origins allowed to embed the workbench, of the form `https://host[:port]`; no wildcards or paths. Empty = embedding forbidden (`frame-ancestors 'none'`). Restart after changing |

`embed.allowedOrigins` can be changed from the command line, no hand-editing needed:

```text
gitrader config get embed.allowedOrigins
gitrader config set embed.allowedOrigins https://app.example
gitrader config set embed.allowedOrigins none
```

## Home directory layout (change with the environment variable `GITRADER_HOME`)

```text
~/.gitrader/
  gitrader.json    every knob you can turn (the subject of this document)
  plugins/         <dir-name>/gitrader-plugin.json — dropping it in installs it
  engines/         <engine-id>/strategies/  strategy files
  workspaces/      workbench layouts
  lab/             local experiment artefacts
  data/            gitrader.sqlite (ledger + state)
  keys/            pin.json / keystore.json / install-key.json / device.key.json
  service.json     port and token of the running instance (permissions tightened)
```

Do not put `keys/` on a sync drive; it holds the PIN verifier, encrypted private keys and the device key. Rationale in [09-security](09-安全.md).
