# 第一次运行

目标：一条命令之内把 Gitrader 起起来，并在**纸面账户**上跑起一条示例策略。全程不碰真钱，默认连测试网。

前置：Node >= 22.13（`node --version` 看一眼）。不需要 Git、Python、Java，也不需要数据库。

## 1. 建主目录

```text
gitrader init
```

它做的事（可以重复跑，已存在的文件和目录不动）：

- 建 `~/.gitrader/`，以及 `plugins/` `engines/` `workspaces/` `lab/` `data/` `keys/` 六个子目录；
- 写 `~/.gitrader/gitrader.json`，内容是一份默认配置：一个测试网场所 `hyperliquid`、一个纸面账户 `paper`（初始 10000 USDC）、一个随包的内置引擎 `gitrader-core`；
- 顺手补上每个账户缺的 `accountId`（这一项不要手改）。

如果你的终端是交互的，它随后会请你设 PIN：

```text
设置 PIN（6–12 位数字，或 8–64 位口令；越长越安全）：
再输一遍：
```

第一遍输入不合规会当场说明原因并重问；两遍不一致只重问第二遍。像 `000000`、`123456` 这类容易被猜到的 PIN 会再确认一次——终端里问一句「仍要使用吗？(y/N)」，网页设置 PIN 时同样会提示「这个 PIN 容易被猜到」并要你点「仍然使用」，两边口径一致。

PIN 是这台机器上所有「人面动作」的钥匙：解锁钥匙库、绑定引擎、恢复交易、放宽风控、签发 Agent 钥匙、给运行中的实例要新链接。它不进日志、不进账本、不能通过命令行参数传。忘掉的后果见 [10-常见问题](10-常见问题.md)。

非交互环境（CI、脚本、便携包的 `start.cmd`）里 `init` 不问 PIN；加 `--no-pin` 是显式跳过（`gitrader init --help` 会列出这个选项）。之后 `gitrader serve`，在浏览器里打开终端打印的链接设 PIN；也可以在交互终端再跑一次 `gitrader init`。

### 可选：先加一个观察账户

想先看一个真实地址的持仓？加一个**只读观察账户**：只要一个公开地址，不要钥匙，也永远不能下单。

```text
gitrader accounts watch <地址> --network testnet
```

之后 `gitrader serve` 起来，接进来的 AI（第 9 节）就能用 `account` 工具看这个地址的持仓和余额。`--network` 缺省是 `mainnet`：观察账户按自己的网络读公开数据，和 `venues` 里 hyperliquid 场所连的网络无关，交易场所留在测试网也能看主网地址（这种跨网读取只读主 dex，builder dex 上的仓位看不到；`gitrader serve --offline` 时没有行情连接，读不了）；细节见 [02-配置参考](02-配置参考.md)。

## 2. 起内核 + 工作台

```text
gitrader serve
```

终端会打印类似：

```text
Gitrader <版本> 已在 127.0.0.1:47900 运行
打开工作台（链接 2 分钟内有效，只能用一次）：
  http://127.0.0.1:47900/?launch=...
想再拿登录链接：在这个窗口按 Enter。停止：Ctrl+C，或在另一个窗口运行 gitrader stop。
```

要点：

- **服务只绑 `127.0.0.1`**，局域网里别的机器连不上，这是设计。
- 端口默认从 47900 起找一个空闲的，并避开一批常见端口；要定死用 `gitrader serve --port 48080`。
- 链接里的 `launch` 令牌**一次性、120 秒有效**。刷新页面或再次打开旧链接会失效，这不是故障——在终端按回车拿新链接，或另开一个终端跑 `gitrader open --print`（要 PIN）。
- 不想连行情（纯离线检查）用 `gitrader serve --offline`，等价于环境变量 `GITRADER_OFFLINE=1`。此时行情面板是空的，账户、账本、插件、策略文件都照常可用。
- 同一个主目录只能有一个实例在跑；重复启动会直接报错并给出已在跑的端口和 pid。
- 会话失效（页面提示登录过期、刷新后进不去）：在终端运行 `gitrader open`（要 PIN）拿一条新链接。
- 停掉服务用 `gitrader stop`：它先让服务正常收尾，等不到才强制结束，不用你去找进程号。停服务不会撤单、不会平仓：场所上已有的持仓和挂单仍在原处，只是服务停着时本机不再盯盘、不再过风控。

## 3. 打开工作台

浏览器点上面那条链接即可。工作台默认三块加状态条：持仓与盈亏、Agent 活动与待批、风险状态。默认是纸面账户，不会把任何东西发到场所。

## 4. 看一眼运行状态

另开一个终端：

```text
gitrader status
```

会打印：版本与 pid、交易状态（`ACTIVE` / `REDUCING` / `HALTED`）、风控策略版本与完整性、账本序号与条数、账户列表（含 `mode` 与网络）、场所连接状态、连接器 / 引擎 / 插件数量、PIN 是否已设、钥匙库是否解锁。要机器可读加 `--json`。

服务没在跑或还没初始化时，它会写明当前状态和下一步命令（`gitrader serve --detach` / `gitrader init`），退出码仍是 0；`--json` 里看 `running` / `state` / `next`。只有查不出状态（比如数据目录读不了）才返回非 0。

## 5. 放一条策略进去

策略就是文件夹里的一个文件。内置引擎的文件夹固定是：

```text
~/.gitrader/engines/gitrader-core/strategies/
```

装好的包里自带示例（**不默认加载**）：`gitrader examples list` 看清单，`gitrader examples copy grid` 把它拷进上面那个文件夹；便携包里也在 `app/cli/examples/`（不想用命令就直接从那里拷）。

- 想从空白开始：`gitrader examples copy template`（只有接口，没有任何交易逻辑）；
- 想看能跑的完整例子：`gitrader examples list` 里那十来份，网格、定投、马丁、趋势、双均线、突破、动量、RSI、超级趋势都有；
- 从源码树跑（开发者）：`packages/engine-core/strategy-template/strategy.ts` 与 `packages/engine-core/examples/strategies/` 是同一批文件。

复制进去后改文件里的 `id`（小写字母、数字、短横线，2–40 字符，文件夹内不许重名）和 `name`，不要保留示例的 `id`。引擎会在约一秒内校验并热加载这个文件，不需要重启服务；写错了会给出可读的错误，改完存盘再看。

## 6. 把引擎绑到纸面账户

绑定是写操作，要先有一个本机会话。先登录一次：

```text
gitrader session login
```

它会问「启动令牌」：在跑着 `gitrader serve` 的终端里按回车拿一个新的，粘进来。如果服务是用 `serve --detach` 起在后台的，没有那个终端：运行 `gitrader open --print`（要 PIN），它打印出一条形如 `http://127.0.0.1:<端口>/?launch=<令牌>` 的链接，粘贴时只要 `launch=` 后面那一段。一个服务会话登录一次就够；服务重启后要重新登录。然后绑定：

```text
gitrader engines bind gitrader-core
```

要输 PIN。不写 `--account` 时默认绑**纸面账户**，内核会给这次绑定签一份纸面级的授权书；实盘账户不走这条路（见 [05-实盘与风控](05-实盘与风控.md)）。先确认服务在跑，`engines` 两个子命令都需要活着的实例：

```text
gitrader engines list
```

输出一行的形态是 `id  state  transport  gep:<状态>  bound:<账户>`。

## 7. 在纸面跑起来

在工作台里对这条策略点启动；或者让接进来的 Agent 调 `engines` 工具集的 `start_strategy`（纸面账户上这是 L1 级动作，不需要你逐笔批准）。启动参数里的 `params` 用策略自己声明的键，超出范围或写了没声明的键会被拒绝，不会被静默截断。

跑起来之后，检查这三处：

1. 工作台的「Agent 活动与待批」——谁在什么时候改了什么、为什么；
2. 「持仓与盈亏」——纸面成交与浮动盈亏；
3. 账本：

```text
gitrader ledger verify
```

应当输出 `Ledger OK: <n> entries, seq 0..<m>, ... checkpoints, head <hash>`。任何一条对不上会指出断在第几号条目，退出码 2。

## 8. 完成标准

本节做完，你应当能回答「是」：

- `gitrader status` 说服务在跑、交易状态是 `ACTIVE`、PIN 已设、钥匙库状态正常；
- 工作台里能看到三个块，没有红色告警；
- `~/.gitrader/engines/gitrader-core/strategies/` 里有你自己的策略文件，引擎列表里 `bound:` 后面是纸面账户；
- 纸面账户上出现过至少一笔成交，账本条目数在涨；
- `gitrader ledger verify` 通过。

## 9. 接上 Agent

让 AI（Cursor、Claude Code、Codex、Hermes 等）通过 MCP 用这台机器上的 Gitrader。四步，顺序别乱。

**第一步：给它建一把钥匙。** 钥匙决定它能做什么，从最小的档开始。令牌写进文件，不显示在屏幕上：

```text
gitrader keys new agent <名字> --host <宿主> --preset starter --token-file <令牌文件>
```

要输 PIN。`<宿主>` 只是个标签（claude-code / codex / hermes / unigit；用 Cursor 或别的宿主选 claude-code 即可）；`--preset starter` 是需确认档（confirm）：每笔开仓都要你批准，只许 hyperliquid 的 BTC / ETH 小额。纸面直通档（`--tier paper`）与它不同：Agent 在纸面账户上的单子直接成交，不等你批准；想让每笔都过你的手，就用 `--preset starter`。只想让它看、不让它下单，把 `--preset starter` 换成 `--tier read_only`，还可以加 `--accounts <观察账户别名>` 把它限制在观察账户上。

**第二步：生成宿主配置片段。**

```text
gitrader mcp snippet cursor --token-file <令牌文件>
```

打印出来的是一段 `mcpServers` 配置，令牌只以文件路径出现，不含明文。Cursor 把它存成项目里的 `.cursor/mcp.json`（所有项目共用就放 `~/.cursor/mcp.json`）；其它认 `mcpServers` 的宿主（Cline、Windsurf、Claude Desktop 等）用 `generic`，把输出并进它们的 `mcpServers`。Claude Code、Codex、Hermes、UNIGIT 各有自己的格式：把 `cursor` 换成宿主名就行。片段末尾会写出这把钥匙能看到几个工具，数字以输出为准。

**第三步：验证。** 重启宿主后看宿主侧：Cursor 的 Settings → MCP 里 gitrader 亮绿灯；Claude Code 用 `claude mcp list`，Codex 用 `codex mcp list`。也可以直接跑片段末尾那条 `--check` 命令：它连上内核，打印钥匙、档位和工具数，能列出工具才算通。

**第四步：装上手技能。** 让 AI 知道这些工具怎么用：

```text
gitrader skill install claude-code
```

Claude Code 装到当前项目的 `.claude/skills/`（加 `--global` 装到你的用户目录）；`gitrader skill install codex` 装到用户级的 `$CODEX_HOME/skills`（没设就是 `~/.codex/skills`），不往当前目录写任何东西。
