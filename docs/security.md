# 安全模型

写给想知道"它到底保证什么、不保证什么"的人。每一条都对应内核里的代码（`packages/kernel/src/`），M1 没做的地方直接写"未做"。

## 一、三档威胁模型

| 档 | 威胁 | 承诺 |
|---|---|---|
| **T-A** | 经 MCP 接入的 Agent，包括被提示注入、被记忆注入的 Agent | **强制**。批准、限额、钥匙、恢复交易**根本不在工具面上**（没有入口，不是"有入口但拦住"）；所有下单都过钥匙对应的授权书和风控闸；每条记录的来源由服务端按已认证身份盖章，Agent 不能自报身份；Agent 只能触发自保动作：停止新开仓 / 撤单 / 全平 / 自降级；停止策略只限自己启动的实例（停别人的要「需确认」以上） |
| **T-B** | 本机其他进程，经本地接口发请求（含带 shell 的编码 Agent） | **强制**。所有本地接口都要令牌，没有令牌就没有身份；人面会话令牌只在界面进程内存里、不落盘；放宽类动作要 PIN；风控策略是内核验签的文档，缺失或被改动即进入 HALTED。**如果它能执行任意代码去改文件、读内存，就属于 T-C** |
| **T-C** | 同一系统用户下的恶意代码（改文件、读内存、解开用户级加密、读已解锁的密钥） | **不保证**。README 与设置页如实写明"同用户恶意代码不在保证范围"。缓解办法：API 钱包没有提现权限、用独立子账户、限额。后续版本可选"加固模式"（内核跑在独立系统账户）——M1 未做 |

**"风控不可绕过"只覆盖经工作台执行的订单**：引擎模式 A（订单交给内核发出）、你手动下的单、Agent 经 MCP 下的单。外部引擎自己连场所下的单（引擎模式 B）风控只是建议性的，界面会标注。

## 二、本地接口鉴权

- 服务只绑 `127.0.0.1`。
- **无令牌即无身份**。`Origin`、`Sec-Fetch-Site`、`Host` 这些请求头**只用来额外拒绝**（跨站浏览器请求、DNS 重绑定），永远不用来放行——非浏览器进程可以随便伪造这些头。
- 三种令牌，各管各的：
  - **会话令牌**（`ses_…`）：工作台界面用，只在内存里，重启即失效，12 小时有效。
  - **引导令牌**（`boot_…`）：`gitrader serve` 打印的链接里带着，**一次性、120 秒内有效**；页面拿它换会话令牌，用过即作废。再要一条：`gitrader open`（要 PIN）。
  - **服务令牌**（`svc_…`）：本机工具使用，存在 `service.json`；可读只读接口，也可调用已认证的紧急 `kill` 降风险路径。它不是人类会话，不能用来铸造工作台会话；附带 PIN 也不会取得仅会话身份才有的权限。
  - **Agent 钥匙令牌**（`gtk_…`）：只代表授权书范围内的能力，永远拿不到人面专属动作。令牌明文只在创建时显示一次。
- `service.json`、钥匙库、PIN 文件写入时权限收紧：POSIX 上 `chmod 600`；Windows 上用 `icacls` 去掉继承、只留当前用户。收紧失败不会让程序崩溃，但会在状态里如实标注。

## 三、PIN

- 6–12 位数字，**或 8–64 位任意字符的口令**（界面仍叫 PIN；界面对纯数字短 PIN 会提示“更长更安全”，建议 10 位以上或口令）。用 scrypt（N=2^17=131072, r=8, p=1，约 128 MB 内存）派生，**再与“设备密钥”经 HKDF-SHA256 合并**成 32 字节主密钥；磁盘上只存盐和校验值（校验值针对合并后的主密钥）。
- 失败退避：前 3 次输错不锁，之后按 1 秒、2 秒、4 秒……指数增长，最长 15 分钟；退避状态落盘，重启不清零。
- PIN 不进日志、不进账本、不进错误信息；命令行永远不从参数读 PIN 或私钥（只从终端隐藏输入或 stdin 读）。

## 四、密钥静态加密

- API 钱包私钥存在 `keys/keystore.json`，用 **AES-256-GCM** 加密。主密钥由 PIN 经 scrypt 派生（见上），**不落盘**；解锁后只在内存里，可随时锁回。
- 私钥永远不出内核：生成钱包只返回地址；导入时私钥从终端隐藏输入读入。
- 安装签名钥（用来给账本检查点签名的 Ed25519 密钥）存在 `keys/install-key.json`，权限收紧。
- **设备密钥**（`keys/device.key.json`）：32 字节随机数，首次设置 PIN 时生成，参与主密钥派生。**Windows**：用 DPAPI（CurrentUser）包裹后存放，经系统自带的 Windows PowerShell 5.1 一次性子进程调用（不需要 pwsh 7）；只在首次设置和解锁时走一次，解出后缓存在内存，不进热路径。**macOS / Linux**：只有文件权限 0600，**无 OS 钥匙串包裹**——同一系统用户读得到这个文件。
- **这一层防什么**：只拷走 `keys/pin.json` + `keys/keystore.json`（备份、同步盘、整机镜像到别的账户 / 机器）而没有设备密钥，**无法离线穷举 PIN**——校验值对不上，合并前的 scrypt 输出本身也解不开任何东西。Windows 上设备密钥文件换到别的机器 / 别的用户下解不开。三个文件一起被拷（macOS / Linux 上同用户备份整个 `keys/`）时，退回到“PIN 强度 + scrypt N=2^17”：单核一次约零点几秒，6 位数字 PIN 仍扛不住有算力的人，所以才建议口令。拿到私钥也只是**只能交易、不能提现的 API 钱包**，损失上限是限额内的交易。
- **仍不在保证范围（T-C）**：同一系统用户下的恶意代码——能调 DPAPI、能读已解锁时内存里的密钥，也能装键盘记录。旧版（`pin.json` version 1，无设备密钥）仍可解锁但不享受这层保护，也不会自动升级；要升级需删掉 `keys/` 重新设置（M1 尚未发布，新安装一律是 version 2）。
- 别把 `~/.gitrader/keys/` 放进同步盘；尤其 macOS / Linux 上。设备密钥丢了（重装系统、换用户）= 钥匙库打不开，需用你保存的 API 钱包私钥重新导入。
- 钱包到期提醒：`keys.walletExpiryWarnDays`（默认 14 天）；建议 API 钱包有效期不超过 180 天并定期轮换。

## 五、人面专属动作

下表来自 `packages/kernel/src/ops.ts` 的 `presence` 声明。"PIN"= 必须当场输 PIN；"会话"= 工作台会话即可；Agent 钥匙对这些动作一个也调不了。

| 动作 | 在场要求 |
|---|---|
| 解锁钥匙库、给运行中的实例要新启动链接、轮换服务令牌 | PIN |
| 从 REDUCING / HALTED 恢复交易（`trading_state.resume`） | PIN |
| 放宽风控（`risk.relax`）、临时放宽（`risk.temporaryRelax`，最长 24 小时，到期自动回收） | PIN |
| 关闭"大模型不得实盘开仓"（`denyLlmLiveEntries`） | PIN（开启它只需会话） |
| 切预设：变宽要 PIN，变严会话即可 | PIN / 会话 |
| 创建 / 轮换 Agent 钥匙、签发或升级授权书（`agentkey.create` / `agentkey.rotate` / `mandate.update`） | PIN |
| 绑定引擎到账户（`engine.bind`） | PIN |
| 批准提案 | 会话；提案名义额超过授权书里的 `presenceAboveNotional` 时要 PIN；批准实盘单时钥匙库已锁则要先输 PIN 解锁 |
| 收紧风控、拒绝提案、撤销钥匙 / 授权书、撤销 API 钱包 | 会话 |
| 授予插件权限、卸载插件、导出账本、切主网 / 测试网、开关"允许 Agent 调整布局" | 会话 |
| 改 PIN | 当前 PIN |

接管（停止新开仓 / 撤销挂单 / 全部平仓）人和 Agent 都能触发，不需要 PIN——自保动作要快（停止策略不属于接管，见上）。

## 六、风控与 HALTED

- 风控闸在内核里执行，是**唯一的**下单检查点：钥匙的授权书（额度、账户 / 场所 / 标的白名单、有效期、心跳）和风控策略（限额、保护器）取最严的那个；行情陈旧或缺价格一律拒单。
- 交易状态三态：ACTIVE / REDUCING / HALTED。进入 REDUCING 或 HALTED 的原因包括：你按了接管、保护器触发、Agent 心跳超时（死人开关）、启动时对账失败、风控策略验签失败。
- **HALTED 的放行面**：撤单和**仅减仓**的平仓单（停机不能让人平不掉仓）；一切增加敞口的单、启动策略、签发授权书、启动插件都被拒。恢复只能由你输 PIN。
- 授权书若要求心跳，Agent 心跳超时会自动降到只读并停止新开仓。
- 大模型来源的动作在账本和界面里永远标注来源（人 / 引擎 / LLM Agent / 系统），可一键禁止。Gitrader 自己不调用任何大模型。

## 七、记录（账本）

- 只追加的 SQLite 账本，每条带前一条的哈希（哈希链）；定期写检查点，用安装签名钥签名。`gitrader ledger verify` 重算整条链；`ledger export` 导出 JSONL + 清单 + Markdown 交易日志（可 `--redact` 去掉载荷）。
- **只认内核时钟**：条目的时间戳以内核当前时间为准，调用方给的时间比内核时钟早超过 60 秒或晚超过 5 秒会被拒绝（防倒填）。
- 回测 / 回放数据不得写入前向账本；载荷里出现密钥类或供应商私有字段会被拒绝入账。
- 诚实说明：本机哈希链只能证明**导出后没被改**，防不了拥有整个账本文件的人整条重写。

## 八、其他

- **iframe 嵌入**：默认**禁止**被任何页面嵌入（`Content-Security-Policy: frame-ancestors 'none'`）。要把工作台嵌进 UNIGIT 等宿主页，在 `gitrader.json` 里写 `"embed": {"allowedOrigins": ["https://app.example"]}`（只接受 `scheme://host[:port]`，不许通配符 / 路径）；响应的 CSP 会变成 `frame-ancestors <列表>`，谁能嵌由浏览器强制。放宽的只是“跨站的页面 GET 导航进 iframe”（`Sec-Fetch-Dest: iframe`）；`/api`、WebSocket 仍然必须有令牌，跨站请求照旧拒绝。启动链接（`?launch=`）的换票在 iframe 内同样可用。
- **程序化取启动链接（宿主 / 配方）**：普通 `gitrader open --print --json` 只要 PIN（本机 service 令牌 + PIN 在场；拿到 `service.json` 不知道 PIN 换不到链接），不需要先 `gitrader session login`。`gitrader open --print --json --unattended --origin <host-origin>` 省去 PIN，因此要求当前有效的本机人类会话缓存（先 `gitrader session login`），且来源已配置在 `embed.allowedOrigins` 并与参数一致，每次签发入账；它不会把服务令牌换成人类会话，也不会赋予自动主机权限。一次性启动令牌只能消费一次。
- **刷新页面后取新链接**：页面会话令牌只存在内存中，一次性启动令牌换票后即作废。刷新或重新打开已用链接时，回到运行 `gitrader serve` 的窗口按 Enter，或运行 `gitrader open`（会要 PIN）。免 PIN 模式先确保人类会话有效，再用已配置的 `--origin` 重新签发。
- **下单幂等与超时**：所有下单类操作都接受 `clientOrderId`（幂等键）：超时后**不要重发**，用同一个 `clientOrderId` 重试（内核返回原订单、场所只收到一次），或调 `order.lookup {clientOrderId | orderId}` 查结果——返回订单状态、账本链类型；仍在“已提交、结果未知”或等待撤单确认的单会向场所查一次，先补录未入账成交，再按已知场所状态更新；若这单被转成了提案，返回票号。Agent 钥匙只查得到授权书覆盖账户里的单。

- **插件**：进程隔离**不是安全沙箱**。权限在内核 API 层强制；Node 子进程另加了 `--permission` 限制文件读取，但网络限制不由 Node 强制。第三方插件的信任主要来自签名与来源。详见 `docs/plugins.md`。
- **引擎**：本地子进程不继承你的环境变量；引擎拿不到 API 钱包私钥（模式 A）。
- **数据**：默认不出本机。
- **供应链**：依赖钉版本；构建产物随附 `THIRD-PARTY-NOTICES.md`。

## 九、报告安全问题

私密披露通道：见仓库根的 `SECURITY.md`（GitHub 私密漏洞报告 / Security Advisories）。请不要把可利用的细节发在公开 issue 里。

## 十、忘记 PIN 的重置（`gitrader pin reset`）

- **只能在本机终端里由本人做**：`!interactive` 或设置了 `GITRADER_PIN_STDIN` 时直接拒绝（退出码 2），并要先输入确认短语「我确认重置 PIN」，不一致就取消。服务在跑时也拒绝——函数会读 `service.json` 里的 pid，还活着就报「先停掉正在运行的 gitrader serve，再重置 PIN」。
- **做了什么**：把 `keys/pin.json`、`keys/keystore.json` 与 `keys/device.key.json` **移动**到 `keys.bak-<本地时间>`（同秒重复加 `-2`）；`keys/install-key.json` 原地不动，不删除任何文件。随后用新 PIN 重新创建 PIN、设备密钥与密钥库。设备密钥一起移走，是因为内核把「PIN 文件没了、钥匙库或设备密钥还在」判为安全状态损坏（防止删掉 `pin.json` 绕过 PIN）；三件在同一个备份目录里，记起旧 PIN 时可整体放回。
- **安全文件损坏时**：`gitrader doctor` 读内核的安全状态体检（服务在跑时经 `/api/health`；没在跑时看 PIN 文件是否缺失或损坏）；PIN、钥匙库或设备密钥损坏 → 下一步是停掉服务后 `gitrader pin reset`；安装签名钥损坏 → 只能从备份恢复 `keys/install-key.json`（它是账本身份，重置换不了）。
- **代价**：旧密钥库文件仍在备份里，但它由旧 PIN 派生的主密钥加密；旧 PIN 记不起来就打不开，等价于 API 钱包私钥停用——需要你自己另存的私钥重新 `gitrader keys import`。全部 AI 钥匙及其授权书被吊销，之后重建。账本、历史记录与安装签名身份保留。
- **账本**：重置写一条 `pin.reset`（`attestation: user-asserted`，载荷只有备份目录名与吊销数量；目录名不含绝对路径）。吊销走的是「会话」级证明，不需要 PIN——这是只会变严的自保动作，重置本身又已经把人面确认放在本机终端里做了。
